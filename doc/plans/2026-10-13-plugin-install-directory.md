# 插件安装目录调整

## 目标与边界

- 桌面插件的原生存储由 `{appLocalData}/plugin-private` 改为 `{可执行文件所在目录}/Plugin`，开发环境同样以实际可执行文件为准。
- 注册表、源码 revision、UI 产物、声明资源、插件偏好与后续运行时工作区统一使用新根目录；IndexedDB 安装记录保持既有职责。
- 旧原生数据首次使用时迁移；已有新目录不覆盖、不合并。迁移失败保留旧数据，并明确报错，不回退旧目录执行。
- 新、旧和迁移暂存目录均维持 fs scope、asset scope 与通用路径命令的私有目录保护；不新增命令或放宽 capability。

## 实施步骤

1. 修改 `src-tauri/src/plugins/registry.rs` 的目录定位与路径保护，固定使用可执行文件旁的 `Plugin`；拒绝符号链接、Windows 重解析点和非目录目标。
2. 复用既有注册表/快照布局迁移持久化数据，在安装目录内暂存后原子发布；只复制注册表及其备份、`revisions`、`ui-revisions` 与 `settings`，不迁移旧窗口 profile 或媒体任务。
3. 保留旧数据作为迁移备份；源码、UI、资源的摘要继续由现有执行/读取流程复核，损坏注册表沿用现有显式修复入口。
4. 在原生注册表测试中补充迁移内容、已有目录保护、失败重试与不安全路径回归；同步插件开发规范。

## 状态

- 已实现：新目录定位、持久化数据迁移、原有目录/暂存目录保护和原生回归用例。
- 本次未运行测试，待用户验收；跨盘迁移、Windows 目录联接拒绝、安装目录权限和真实独立 WebView 仍需桌面验收。

## 用户验收

前置：使用 Tauri 桌面端，应用安装目录可写；升级前保留一个已安装插件及其非敏感偏好。涉及删除或修改测试数据时使用独立测试安装和备份。

1. 升级并进入「设置 → 插件」：应生成可执行文件旁的 `Plugin`，旧插件仍可执行、打开内嵌/独立 UI，偏好保留；旧原生目录仍在。
2. 安装、更新、停用/启用并重启：新 revision 和偏好应仅写入 `Plugin`，插件列表与摘要一致；卸载后重启不重新出现。
3. 已有 `Plugin` 时修改旧目录中的测试数据：重启应仍使用新目录，不覆盖或合并旧数据。
4. 不可写安装目录、`Plugin` 被普通文件/符号链接/Windows 目录联接占用、迁移数据含链接：应报错，旧数据保留；修复目录权限或异常路径后重试。
5. 原生注册表损坏：应继续提供既有修复入口；普通文件 API、asset URL 与通用递归/归档命令应拒绝新旧私有目录及适用的祖先。

原生检查（用户执行，目录 `src-tauri`）：

```powershell
cargo test --lib plugin_registry::tests --no-default-features --features tauri-channel-tests
cargo check
```

## 回滚

停止应用后恢复原生目录定位代码。迁移保留的旧目录是迁移时备份，不能代表新版本安装/更新/卸载后的最新状态；需要保留后续数据时，先备份新目录并将其持久化子目录恢复到旧目录，再启动旧版。不要手动合并两份注册表或修改摘要。
