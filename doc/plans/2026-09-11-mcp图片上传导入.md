# MCP 图片上传导入

状态：代码、定向验证及三张真实图片的实机上传导入已完成。用户已授权实施、提交并继续宣传片。任务类型：平台能力。用户明确要求不加上传上限，因此不设文件总大小、单批总字节数或总暂存预算上限；不更改现有 MCP 单请求传输边界。

## 已确认事实

- 现有路径导入曾在第一项返回 IMPORT_COPY_FAILED，没有添加节点。复制服务折叠了底层异常，尚不能仅凭返回信息断定是源路径权限问题。
- 原生 stdio / HTTP MCP 单请求上限为 1 MiB，本次图片约 1.5 MiB，需要分块。
- 复用项目目录、Tauri 文件插件的追加/读取、图片尺寸解析和原子资源导入服务；无新依赖、原生命令或安全配置修改。

## 实现合同

1. `file_media_upload` 提供 begin、append、finish、status、cancel。begin 接收显示文件名、MIME、总字节数，返回随机 uploadId、块大小、初始摘要和空闲过期时间。
2. 每块固定 256 KiB 原始数据，末块为余量，使用 Base64 携带；参数封装后仍低于 1 MiB。严格检查顺序与摘要，重复发送最后一块时须内容摘要和长度相同，不重复追加。失败不自动重试。
3. 上传支持 PNG、JPEG、WebP。正文逐块写入当前项目随机命名的 `.part` 文件，只保留进度、摘要和最多 1 MiB 文件头；总字节数接受正安全整数，不设额外业务大小上限。
4. 上传绑定项目、MCP 对话、canvas revision 和存储配置。空闲十分钟过期，成功写入刷新期限；同一上传写入串行。上下文变化后拒绝继续写入和导入；同项目对话仍可查询旧 revision 状态或取消。
5. append 校验块 SHA-256；finish 校验总字节数与有序摘要链 `sha256-chain-v1`，按固定块读回磁盘内容复算。H0 为 SHA256(UTF8(`AI-Canvas-upload-v1:MIME:totalBytes`))；Hn 为 SHA256(UTF8(`previousDigest:offset:chunkSha256`))，十六进制小写。这不是普通整文件 SHA-256。
6. 文件头、MIME 与尺寸须匹配；文件头检查不等同完整图像解码。文件名只作显示名，保存扩展名来自已验证 MIME，不接受源路径或输出路径。
7. 现有 `file_import_media_to_canvas.files[]` 支持 path / uploadId 二选一，允许混合；保留原来的每批 1 至 20 项。所有资源准备成功后提交一次画布历史；上传消费后不能重复导入。导入失败释放领取状态，供客户端显式重试或取消。
8. 正常取消、空闲过期和热更新清理未交付的临时文件，已交付媒体保留。图片正文、Base64 和路径不进入消息、AgentTask、审批展示或日志。

## 风险与回滚

没有业务大小上限不代表无限磁盘或内存；磁盘写入失败返回安全错误，不自动重试。上传不恢复跨重启令牌。强制退出、磁盘故障或清理失败可能遗留未交付文件，不能承诺退出即自动删除。图片文件头解析复用现有最多 1 MiB 解析窗口；实际解码由媒体使用环节完成。

撤销上述新增上传服务与工具分支即可回滚，无数据库迁移。保留已有生成图片、路径导入和已交付项目媒体；已导入图片仍是标准 source-image 节点。
