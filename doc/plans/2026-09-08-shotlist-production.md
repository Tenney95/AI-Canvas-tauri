## 范围
从已保存的本集剧本创建正文来源节点与分镜表；统一分镜生成结果解析；给内部助手和 MCP 提供镜头行读取、追加与局部更新；支持批量补齐空镜画面并绑定真实图片节点。

首批范围不包含原著章节索引、跨版本改稿传播、音轨字幕装配、导演台或宫格自动拆图。后续按下列独立阶段接续，每阶段检查后提交。

## 约定
- 新建分镜采用当前分集的已保存剧本快照，保留独立的正文来源节点；不自动更新已有分镜。
- 镜头行使用稳定 ID，局部更新只修改指定字段并保留画面绑定。读工具只给可用的镜头正文和节点标识，不返回媒体路径或 URL。
- 所有入口复用共享服务与现有 Store Action；Agent/MCP 工具继续经过 Registry、Policy 和项目/revision 校验。
- 补空镜仅处理未绑定画面的有效镜头。失败不自动重试；取消保留已完成图片。切项目、源节点删除或镜头改动时不得把旧结果绑定回新内容。
- 一张表最多 200 镜，补图每批最多 12 镜且顺序执行。UI 显示所选图片模型、数量和执行进度，模型选择复用 UI Kit。单镜「换画面」继续支持替换，失败时保留原画面。

## 使用入口
- 剧本工作台「生成本集分镜」先保存当前草稿，再创建剧本快照与空分镜表并打开模型生成弹窗；创建本身不调用模型。
- 分镜表「补齐空镜」选择图片模型后生成并绑定；运行中可取消。图片节点继承项目生成参数，可以独立编辑与重跑。
- 分镜表「AI 诊断」准备整表只读检查请求，每镜「AI 优化本镜」准备限定该镜头的修改请求；均打开助手草稿，由用户编辑后发送。草稿使用节点引用和稳定镜头 ID，不复制镜头正文或媒体路径，发送时通过工具读取最新内容；空表、镜头删除和项目不匹配会拒绝准备请求。
- 助手与 MCP 共用 `episode_create_shotlist`、`shotlist_read`、`shotlist_update_rows`、`shotlist_generate_frames`。读取按行和字段长度分页；写入校验项目与 revision。Plan 只读，B 模式沿用确认和本轮模型引用约束，C/MCP 复用自主策略。
- 节点弹窗和 `canvas_run_nodes` 共用结构化生成服务，分镜表继承项目文本模型；生成期间改表或切项目会拒绝旧结果。镜头行、列及画面绑定可随创建批次撤销。

## 后续完善
- 镜头读取按实际 JSON 长度限制回包，避免大量转义字符被通用执行器截断。`nextTextOffset` 用于续读同页文字，返回空值后再按 `nextOffset` 翻行；每次返回实际 `textChunkSize`。
- 补图取消会立即结束本地等待并释放批次，已完成结果继续保留。再次调用只补未绑定镜头；旧供应商响应或迟到保存结果不再回填。供应商服务端任务是否同时停止，取决于其取消能力。
- 生成前后校验提示词、模型、工作流输入、分辨率和比例；排队期间修改过参数的镜头跳过，运行中的旧参数结果不回填，并结束旧请求的生成状态。
- 工具省略模型参数时，优先解析本轮显式 `@model`，然后使用项目默认模型；显式参数与本轮引用不一致仍拒绝执行。
