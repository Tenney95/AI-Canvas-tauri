# MCP 发现与结果准确性优化

状态：第一阶段代码与自动检查完成，等待运行中的应用加载新定义后实机验收；后续阶段尚未授权实施。

模块入口：[MCP 控制模块](../MCP控制模块.md)。任务类型为平台能力完善与明确缺陷修复，不调整权限矩阵。

## 已核实的事实

| 现象 | 当前证据 | 判断 |
| --- | --- | --- |
| 使用鼠标创建项目 | 实机搜索“创建项目”，第一项为 `project_create`，完整 schema 可直接读取 | 属于执行助手选工具失误；接口已经存在 |
| 未先使用媒体导入接口 | 实机搜索“导入生成的图片到画布”，第一项为 `file_import_media_to_canvas` | 导入能力可发现；已完成的分块上传扩展不需要重做 |
| 类别无法完整浏览 | 实机 `category=canvas, limit=8` 返回 8 项、`total=23`；schema 没有翻页参数 | 需要有界分页，避免只能反复猜关键词 |
| 摘要切断操作条件 | `entry()` 对说明直接 `slice(0, 120)`；实机导入说明在 uploadId 条件中间截断 | 需要显式截断标记及完整定义入口，不能把摘要当完整契约 |
| 多意图搜索混入其他能力 | “创建项目 导入图片 生成视频 剪辑导出”返回 79 个匹配，前五中包含 Blender 导出 | 一个结果列表不是完整操作流程；助手应拆分意图后搜索，当前证据不足以支持大改排序算法 |
| 运行权限说明不准确 | `canvas_run_nodes` 写“每次都需要用户确认”，实际权限由 Policy 按模式处理，MCP 自主执行 | 修正文案，不修改权限 |
| 视频被报告成图片 | `describeNode()` 优先检查 `imageUrl/thumbnailUrl`；实机视频节点返回 `outputKind: image`，探测工具确认有可解码 AVC/AAC 视频 | 修复媒体类型判定，缩略图不能覆盖主产物类型 |
| 视频参数与实际产物不一致 | `canvas_update_nodes` 只写 `seedanceResolution`，普通节点生成另读数值 `videoResolution`；该路径存在 832 默认值，而媒体入口另做标签到数值映射 | 第二阶段核对并统一有效参数计算，不能仅改显示文字 |
| 长任务记录不足以判断产物 | 第二镜旧 AgentTask 显示连接中断失败，但同一节点当前已有可解码的 3.04 秒、864×480 视频 | 已确认两处状态不一致；尚不能确定恢复或重跑的来源，不能把该视频视为原 5 秒请求成功 |

## 第一阶段：工具发现完整、返回事实准确

1. 为 `tools_search` 增加可选分页参数，保留默认 5 项、单页最多 8 项及 64 KiB 返回预算。保留现有名称、参数和 `total` 语义；新增返回条数、是否还有结果及下一页位置。无参数仍返回类别导航。
2. 摘要被裁切时返回明确标记，并指向 `detail=schema` 或 `tools_describe`。完整说明和 schema 继续来自 Registry，不能复制维护第二套接口定义。
3. 搜索提示明确说明“匹配结果不等于全部能力”，多步骤需求应拆开检索；分类浏览支持逐页覆盖。已知完整参数可以直接调用，不要求机械地每次重新搜索。
4. 修正 `canvas_run_nodes` 的权限文案，与现有 Policy 保持一致。
5. 修正 `canvas_query` 主产物类型判断。覆盖带缩略图的视频、音频、纯图片和纯文本；返回实际存在的产物，不仅凭节点声明类型推断成功。

本阶段不新增依赖，不修改安全配置，不扩大文件或网络权限，不修改媒体执行和付费重试行为，不控制电脑。

### 验收

- 类别中超过一页的工具可完整遍历，稳定目录下不重不漏；精确工具 ID 仍优先。
- 旧客户端省略新增参数仍正常；参数越界明确失败；完整 schema 超出预算时仍拒绝返回残缺内容。
- 被截断的说明明确标记；真实创建、导入、截图、生成和剪辑接口都能准确找到。
- 带缩略图的视频返回 `outputKind: video`，音频、图片与文本各自正确。
- 执行两个定向测试文件、源码与测试类型检查、改动文件 ESLint、差异和严格 UTF-8 检查。
- 实机只读回归验证目录、完整参数和现有媒体节点；不为验收重复调用付费模型。

### 第一阶段验证结果

- 目录、画布工具和既有 MCP 控制服务三个测试文件共 86 项通过。命令：`npx vitest run tests/services/mcp/mcpToolCatalog.test.ts tests/services/chat/canvasTools.test.ts tests/services/mcp/mcpControlService.test.ts --exclude '.planning/**'`；排除任务暂存副本，结果只计当前源码。
- `npm run typecheck`、`npm run test:typecheck` 与六个改动源码/测试文件的定向 ESLint 通过。未修改 Rust，也未运行或宣称全仓检查通过。
- 回归覆盖 23 项目录分三页完整遍历、摘要/schema 两种分页、默认参数兼容、非法偏移、目录变化后的可用性复核、完整说明回取、超预算 schema 拒绝，以及视频/音频带封面、正文带缩略图和无产物节点的正确类型。
- 当前实机连接仍返回不含分页/截断字段的旧目录，视频也仍被报告为图片。新定义的运行时加载与实机效果尚未验收；不能把本地测试通过写成实机已生效。

### 风险与回滚

- 工具可用性随项目或配置改变，分页不能被解释为跨状态的固定快照；调用时仍重新校验权限与上下文。
- 兼容现有返回字段，避免客户端解析失败；新增字段含义写入模块文档。
- 分阶段独立提交，仅暂存本清单，保留其他任务已有修改。需要回滚时仅回退本阶段提交，不覆盖工作区。
- 如运行中的工具定义仍为旧版，先验证目录差异，再说明需刷新 MCP 连接或应用的具体原因；不能仅凭超时要求用户反复重启。

## 执行助手立即采用的流程

优先读取当前 MCP 类别，按单个目的搜索，取得完整参数后调用并核验结果。一次搜索无命中或返回少量结果，不能据此宣称缺接口。能力确实缺失时列出具体缺口，等待用户决定是否扩展；不擅自用鼠标补位。该执行约束现在即可遵守，不依赖产品代码修改。
