## 构建兼容修复

此前[源码 CI 43407965505](https://github.com/Tenney95/AI-Canvas-tauri/actions/runs/43407965505)前端成功，Rust 在 `ort-sys` 复制 DLL 时失败。日志显示 Rust 1.100.0；[Cargo 官方文档](https://doc.rust-lang.org/cargo/reference/build-cache.html)明确该版本改变了中间目录布局，而当前 `ort-sys` 按固定父级推算输出目录。上一[成功 CI 43198093874](https://github.com/Tenney95/AI-Canvas-tauri/actions/runs/43198093874)使用 Rust 1.99.1。

本版将源码 CI 和标准／Legacy 发布编排统一固定到 Rust 1.99.1，避免工具链漂移；不禁用 ONNX，不改变依赖版本、原检查命令或门禁。实际修复结果仍以本版同 SHA CI 和平台构建为准。后续升级 Rust 时需先核对 ONNX DLL 复制与打包布局。

## 兼容与未验收边界

本版无数据库 schema 升级、依赖解析调整或 CSP 放宽。TOS 需要独立北京私有桶和对象读写凭据，已上传对象不会随签名到期自动删除。候选沿用 PNG／JPEG／WebP、大小与像素校验；只有保存了真实原任务 ID 的中断可续查，未知提交不自动重投。旧项目、较早 v4 读取器、跨设备辅助图层、Muse／小红书网页会话和各平台安装限制见发布说明。

新增用例覆盖角色上下文、原任务查询、部分产物、全模型目录、参数与候选保存；完整门禁由正常 `pre-push` 执行 `npm run ci`。发版回归补齐方舟缺配置时不采用公共图床缓存的断言，并隔离工作流编辑用例中不参与断言的预览／费用子组件；对应两文件 241 项定向用例已通过。最终完整门禁仍由本次正常推送执行，不以定向或旧 SHA 结果代替。新提交的前端与 Rust 检查、前端产物来源和构建状态保留在 Actions Summary，不为追加成功流水另建提交。

桌面验收按工作台专项矩阵，对比图片节点目录和参数，覆盖项目／剧集／全局角色、关闭重开与重启、断网续查、部分保存、配置变化、角色切换和普通图片节点回归。真实 TOS 上传、付费模型生成、小红书导入、跨平台窗口、安装升级及自动更新仍待用户操作，自动化门禁不替代这些验收。

## 发布与回退

按[发版流程](../打包与发版流程.md)，版本、发布说明和模块资料一次提交，使 `master` 和 `v0.11.4` 指向同一提交后原子推送。等待同 SHA 前端与 Rust CI、发布 Quality gate 成功且Windows 与 macOS 两个标准平台构建均已启动后，可交付「发布构建已启动，后台自动完成」；最终公开继续由所有平台、Legacy 与签名验证门禁控制，不将标签推送或构建启动称为公开完成。

回退保留项目、候选、任务回执、TOS 配置及用户桶中对象，不自动删除或重投。旧代码可能无法续查新增恢复描述，应保留原记录并恢复本版代码后继续查询。标签不可覆盖；标签推送后若需修复，使用新的补丁版本。
