# 火山方舟节点计费与用量记录系统设计

> 状态：第一版实施中；用户已确认 SQLite 与 Excel 依赖，桌面端真实调用和账单对账尚未验收。
> 归属：[模型与生成模块](../模型与生成模块.md)。
> 价格依据：用户提供的《模型价格.md》。定价会变化，实施时须复核火山方舟当期官方价格与 API 账单口径。

## 1. 目标与边界

只记录**实际由火山方舟 API 执行的节点调用**。同名 Seedance/Seedream 模型若由 APIMart 等中转商执行，不纳入火山方舟账本；仅在节点上选择模型、预览参数或本地校验失败且未尝试提交的操作，也不能记为方舟已计费调用。

一期覆盖图片和视频生成节点的运行记录、费用预估、查询、Excel 导出与清理。数据库结构预留文本、音频、3D 和向量模型类型，但这些类型的计价规则须在其调用路径核对后分别接入。生成路径不仅有节点，还存在对话和工作流；一期必须明确仅接入有稳定 `nodeId` 的火山方舟节点调用，其他火山调用不应被误记到节点账本。

系统是**本地用量账本与价格估算工具**，不是官方账单。页面始终区分“生成前预计”“根据返回 Usage 核算”“官方账单已核对”三种口径；不能把本地核算金额直接命名为官方实扣。

## 2. 身份与隔离

一条运行记录固定保存提交时的身份快照：

| 维度 | 字段 | 说明 |
|---|---|---|
| 本地项目 | `appProjectId`、`appProjectName`、`seriesOwnerId?` | 以不可变项目 ID 归属；名称只用于历史展示，改名不改归属。分集沿用真实项目 ID，剧集汇总可另按 `seriesOwnerId` 聚合。 |
| 厂商连接 | `provider='volcengine'`、`connectionId`、连接显示名 | 使用运行时实际解析的连接身份，不能只看模型名；不保存 API Key/AK/SK。 |
| 节点 | `nodeId`、`nodeType`、`nodeLabel`、`canvasRevision?` | 节点删除后仍可查询历史快照。 |
| 模型 | `modelType`、`modelId`、`modelVersion?`、`endpointId?` | 类型与 ID 共同决定计价合同；显示名不能用作价格键。 |

统计键至少包含 `appProjectId + connectionId + modelType + modelId`。允许跨本地项目查询，表格及导出只显示本地项目。方舟生成请求没有显式 `ProjectName`，不得把虚拟人像库项目写入费用账本。删除本地项目或连接时保留历史快照，清理由用户明确执行。

## 3. 存储选择

**Tauri Rust 管理的独立 SQLite 数据库**，默认跟随“文件与应用 → 文件保存位置”的保存根目录，位于 `{保存根目录}/billing/volcengine-usage.sqlite`；未设置自定义根目录时使用 `{appData}/data/billing/volcengine-usage.sqlite`。旧 `{appData}/billing/` 账本在首次同步时迁移，原库保留。用户可在用量弹窗中选择已有文件夹作为单独账本目录，优先于保存根目录；文件名固定为 `volcengine-usage.sqlite`。

配置加载与保存完成目录授权后同步账本位置，成功迁移才切换运行路径。迁移与账本读写串行，通过 [SQLite `VACUUM INTO`](https://www.sqlite.org/lang_vacuum.html) 生成包含已提交 WAL 记录的一致快照，并读取完整性校验结果；仅清理本次失败创建的目标，原库不删除。首次启动恢复已存在的目标账本时直接校验并使用，不用旧备份覆盖；运行期间换目录遇到同名账本时拒绝覆盖。目录、主库与 WAL/SHM 文件均沿用原生真实路径、普通文件与私有目录校验，不扩大文件权限。

持续增长的记录需要多条件索引、跨项目聚合、稳定分页和事务性批量清理。当前项目已有 IndexedDB（以 `src/services/indexedDb/schema.ts` 的 `DB_VERSION` 为准），适合保存 UI 筛选偏好；若把账本也放进去，需要增加 object store、升级版本，并自行处理复杂聚合与大批导出。

SQLite 使用单写入服务、参数化查询、schema 迁移和事务；开启 WAL，设置适度 busy timeout，并定期 checkpoint。数据库打开或写入失败时要显式提示“本次调用的费用记录未保存”，但不得让记录故障自动重提付费生成请求。浏览器开发模式没有 Rust SQLite 时，计费页面可显示“桌面版可用”；如需 Web 模式支持，另设计 IndexedDB 适配器并明确数据不会自动合并。

为小额 Token 费用保留精度：金额建议以**微元**（1 元 = 1,000,000 微元）的有符号整数保存，单价以十进制定点字符串保存并用十进制算法计算，汇总和显示时再按规则四舍五入。不能用“分”作为唯一存储精度，也不能用 JS 浮点数直接累加账单。货币固定记录 `CNY`，价格、税费、资源包/优惠券抵扣口径分别标记。

## 4. 数据模型

### 4.1 `billing_runs`：一次实际提交尝试

主键 `runId`（UUID）；关联字段为本地项目、连接、节点、模型类型与模型 ID。另存 `attemptNo`、`retryOfRunId?`、本地关联 `generationId?`、方舟 `requestId?` / `taskId?`、`submittedAt`、`startedAt?`、`finishedAt?`、`lastObservedAt`、`status`、`phase`、`errorCode?`、脱敏的 `errorMessage?`、`estimatedAmountMicros?`、`calculatedAmountMicros?`、`amountConfidence` 和 `priceVersion?`。

状态采用 `preparing`、`submitting`、`running`、`succeeded`、`failed`、`cancelled`、`unknown`。UI 把前三类折叠显示为“运行中”。`unknown` 表示提交结果或计费结果无法确认，不能直接当失败或 0 元；后台仅在已有任务 ID 且 API 支持时恢复查询，不自动重发请求。取消后若远端仍可能完成，费用仍为“待核对”。

同一节点每次点击生成、每次重试和批量生成中的每个远端请求均使用独立 `runId`；`retryOfRunId` 将尝试关联起来。设置远端 ID 的唯一约束时应考虑厂商与连接作用域，避免相同任务被轮询重复插入。

### 4.2 `billing_run_inputs`：提交参数快照

按模型类型保存通用字段与受约束 JSON 扩展：`prompt`、`negativePrompt?`、`promptHash`、`referenceType`（文生、图生、首帧、首尾帧、多模态参考、视频编辑等）、`referenceCount`、`requestedDurationSeconds?`、`actualDurationSeconds?`、`aspectRatio?`、`requestedResolution?`、`actualWidth?`、`actualHeight?`、`fps?`、`outputCountRequested?`、`outputCountActual?`、`inputImageCount?`、`inputVideoDurationSeconds?`、`inputTokens?`、`outputTokens?`、`cachedTokens?`、`usageJson?`、`modelParametersJson?`。

宽高比、分辨率、像素宽高分别保存，不能从一个字段反推另一个；自动时长 `-1` 是请求模式，不等于实际输出时长。提示词默认只写入本地账本，不进入日志；详情页提供显隐，导出默认脱敏。URL、文件路径、Authorization、完整请求体和密钥不写入账本。

### 4.3 `billing_references`：参考素材摘要

第一版只保留与计费有关的参考类型与数量，不保存虚拟人像库 Asset ID、Group ID 或项目名。未来若增加独立参考表，也必须维持该边界；不复制媒体字节或临时签名 URL。

### 4.4 `billing_price_catalogs` / `billing_price_rules` / `billing_price_snapshots`

价格目录保存版本、生效时间、来源、币种和审核状态；规则以 `modelType + modelId + 计费模式 + 条件` 匹配，包含计量单位、单价和计算公式。每条运行记录固化命中的规则与单价快照，即使后续价格更新，历史解释和导出也保持不变。未匹配规则返回“暂无法估价”，不得猜价或默认为 0。

### 4.5 `billing_cost_items`：费用分项

逐项记录名称、数量、单位、单价、金额、计费口径和数据来源，例如视频输出 Token、图片输入张数、成功输出张数。金额合计需与运行记录核算值一致。未来如接入官方账单核对，再增加单独的 `billing_reconciliations` 表，不覆写原始本地估算。

### 4.6 索引与生命周期

主要索引：`(submittedAt DESC, runId)`、`(appProjectId, submittedAt DESC)`、`(modelType, modelId, submittedAt DESC)`、`(status, submittedAt DESC)`；详情表按 `runId` 索引。查询使用游标/键集分页，费用合计由与筛选条件一致的聚合查询计算，不能只加总当前页。

## 5. 价格规则与费用口径

《模型价格.md》说明视频按 Token 计费，准确用量以 API 返回的 `usage.completion_tokens` 为准；预估公式含输入/输出视频时长、输出尺寸和帧率，Seedance 2.0/2.5 含视频输入时还有最低 Token 用量限制。文档给出的 16:9、5 秒价格表是**示例**，不能把任意时长/画幅直接套用 5 秒示例价。Seedance 2.5 Draft 按 480p 规格估算。仅成功生成视频计费，审核等原因失败不收费；请求未知或取消时仍需标记待核对，不能凭 UI 状态推断官方账单。

图片按模型分别处理：Seedream 5.0 Pro 有输入图首张免费、输出像素档位及图层拆分价格；4.0/4.5/5.0 Lite/Flash 各有每张输出单价。审核失败无输出图片不计费。价格引擎不能把“输出数量请求值”当成“实际成功输出数”。

计算顺序：确定真实执行厂商与模型 → 校验价格版本和适用规则 → 由**规范化后的最终请求参数**生成估价 → 提交时固化规则快照 → 完成后优先读取真实 Usage/输出信息核算 → 标记金额证据等级。若返回字段不足，只展示估算或区间，并标记“待核对”。资源包、优惠券、账户折扣和税费未知时，不声称本地计算值等于实付。

价格目录更新采用“新版本生效、不改旧记录”，需要人工核对文档、公式与样本请求。不能自动把网页价格表直接解析成生产规则。价格示例和官方计费接口的差异应记录在规则测试样例中。

## 6. 接入运行流程

```text
节点确定真实 Provider、模型、项目、参数
  → 本地预估（不产生调用记录）
  → 点击生成并建立 runId，写入 preparing/submitting 快照
  → 发出方舟请求并持久化远端 requestId/taskId
  → 轮询/流式进度更新 running
  → 成功、失败、取消或结果未知时写入终态和 Usage
  → 根据实际证据核算费用并保存价格快照
```

接入点需覆盖现有节点生成的图片与视频路径，而不是仅覆盖对话媒体的统一入口；可从 `src/services/ai/generateImage.ts`、`generateVideo.ts`、火山 Provider 适配器和节点生成调度链追踪。计费写入放服务层，组件只展示，避免节点 UI、快捷执行、重试入口各写一套。连接配置删除、项目切换、节点删除或窗口重启后，已提交任务的记录必须仍可恢复查询，且不得写回错误项目。

写入失败的优先级：提交前无法建立记录时明确提示用户，再决定是否继续付费调用；远端已提交后写入失败不能自动重发，需以远端任务 ID 尝试恢复并显示账本缺口。失败阶段与模型生成状态、产物保存状态分开：模型成功但本地保存失败，模型用量仍可能产生费用。

## 7. 节点费用预估 UI

仅当执行 Provider **实际解析为火山方舟**时，在生成节点的模型选择器后显示可点击金额：`预计 ¥x.xx`。点击打开同一个火山方舟用量查询弹窗，不触发生成。视频估算仍依据参考类型、输出时长/自动时长、画幅、分辨率、帧率、输入视频时长及最低用量规则；图片依据输入图数、输出数量和像素档位。参数或模型变化时重新估价，异步结果需防止旧请求覆盖新参数。

无精确规则时显示“待估价”，原因通过悬停提示提供；自动时长或自适应画幅可给出明确标注的 5 秒、16:9 示例预算，但真实请求的预计金额仍记为未知，不能把示例当作实扣。不能把未知价格显示为免费。费用是信息提示，不阻止正常生成；最终账单以方舟侧为准。节点运行状态仍沿用既有交互，账本状态通过 runId 关联。

## 8. 查询与详情页面

入口：`设置 → API Key → 火山方舟连接卡片 → 用量记录`；删除连接但账本仍有记录时显示“火山方舟历史用量”。两个入口均打开同一个独立弹窗，不替换 API Key 页面、不占用全局设置导航，也不混入虚拟人像库资产管理页。弹窗包含“记录查询”和“清理记录”两个视图；筛选区域固定在结果上方，表格独立滚动，分页保持在底部，详情在弹窗内部侧边展开。

查询页顶部显示当前筛选范围的核算费用和预计费用；默认本月、当前 AI Canvas 项目。筛选时间、本地项目、模型类型、模型 ID 和状态；表格展示提交时间、本地项目、节点、模型类型与 ID、状态、预计/核算金额，支持分页和详情。不展示虚拟人像库标识。

详情抽屉分“运行与项目”“模型与参数”“参考素材”“提示词”“费用分项与价格快照”“时间线与错误”。提示词默认折叠；错误文本只保留脱敏摘要。记录对应节点已不存在时仍能查看快照，但跳转节点按钮禁用。

## 9. Excel 导出

从当前查询条件或选中记录导出真正的 `.xlsx` 文件，提供导出数量预览和取消；大数据量采用分页游标流式读取与逐批写入，避免一次加载全表。Sheet 建议为“汇总”“运行记录”“费用分项”“价格依据”。时间按用户时区显示，同时保留 UTC 时间字段；金额列为数值，币种、单位、金额口径另列。导出后总数及金额须与同一筛选快照一致，运行中任务变化时标记导出时点。

提示词选项：默认脱敏，也可选择完整或不导出。对公式注入字符（`=`, `+`, `-`, `@` 等）做文本安全处理；不导出密钥、签名请求、完整媒体 URL 或本地绝对路径。实现依赖需在实施前按项目规则确认；可优先评估已有依赖是否支持 XLSX，避免为导出引入过大包。

## 10. 清理记录子页面

清理筛选与查询口径一致：时间、本地项目、模型类型、模型 ID 和状态。先预览命中数量和费用；默认排除运行中和状态未知任务。清理前提供导出，确认框要求输入精确的删除条数。删除在数据库事务内执行；不删除火山方舟云端账单或媒体文件。

保留策略第一版仅提供手动清理，不自动过期删除。删除后显示数量与时间，并写入不含提示词的本地清理摘要（条件、数量、执行时间）；清理摘要不应含密钥和逐条隐私内容。项目/连接删除不自动清理账本，避免统计历史无声消失。

## 11. 阶段、验证与回滚

| 阶段 | 内容 | 验收重点 |
|---|---|---|
| 1. 存储与定价 | SQLite schema/迁移、服务合同、版本化价格规则、视频/图片价格样例 | 金额精度、项目与模型类型隔离、旧价格可追溯 |
| 2. 节点运行接入 | 方舟图片/视频请求、状态、重试、任务恢复、Usage 采集 | 只记录真实方舟调用；超时/取消不重复付费请求 |
| 3. 节点估价 | 图片/视频参数区费用行与展开明细 | 参数变化重算；未知规则明确标示 |
| 4. 查询与导出 | 筛选、聚合、详情、Excel | 跨项目无串账；导出与查询口径一致 |
| 5. 清理与维护 | 清理预览、确认、事务删除、价格更新入口 | 不误删运行中记录；旧记录价格不变 |

定向测试应覆盖：视频含/不含参考视频、最低 Token 规则、自动时长、Draft、图片首张免费与像素档、组图实际张数、审核失败、并发轮询、重试、网络结果未知、连接/项目切换、数据库升级和大批分页导出。桌面端另验真实方舟请求、关闭重开恢复、暗/亮主题和小窗口布局；只跑离线测试不能宣称官方账单准确。每阶段通过范围内检查后再进入下一阶段。

回滚：关闭计费功能入口和写入，不影响生成服务本身；数据库迁移采取向前兼容，不自动删除已记录账本。价格规则回滚通过切回旧目录版本，新版调用不应追改旧账。清理操作不可由代码回滚恢复，实施时必须提供导出与明确确认。

## 12. 已确认边界与实施进度

用户确认第一版按独立 SQLite 账本、`rusqlite` 与 `rust_xlsxwriter` 实施。当前只接入有稳定节点 ID 的方舟图片/视频调用；Web 模式不保存账本，对话直接生成不纳入。提示词在本地保存，Excel 默认脱敏；价格目录由内置版本发布，不接官方账单。

已实现：按本地项目、模型类型及 ID 保存调用快照；图片和视频运行状态、价格估算与核算；视频任务恢复更新原记录；火山方舟连接专属弹窗内的分页查询、详情、Excel 导出和手动清理；用量弹窗支持自定义账本目录、旧库迁移与目标库校验。导出限制为单次 10000 条，包含汇总、运行记录、价格依据三个 Sheet。清理只处理已结束且非待核对记录，并对预览数量做事务内复核。
