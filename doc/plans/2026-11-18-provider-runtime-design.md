# 受管 API 的运行时、交互和发布验收

2026-11-18 · 待开发。范围是 Tauri 桌面的用户级外部接管；试用步骤和 JSON 示例见[实施计划](./2026-11-18-external-provider-management.md)。下文 A–D 编号对应[80 项证据矩阵](./2026-11-18-provider-management-research.md)。数值属于拟验收预算，尚无 AI Canvas 运行时实测。

## 当前约束下的选择

| 方案 | 外部工具接入成本／动态性 | 安全与运维代价 | 取舍 |
|---|---|---|---|
| 用现有自定义连接连本机网关 | 低；稳定路由组可在网关内切上游。Canvas 当前手动拉模型 | 用户需先填端口和标记，无法从公开端口证明对端身份 | P0 验证文本和助手，适合已有 Magpie 的用户。A01、A02 |
| 用户级版本化文件 + 原生执行 | 写入器可独立于应用运行。约定格式、冲突处理、授权世代即可热切换 | 需实现重载、原子提交和受控发送。用户级文件允许同账户软件修改 | v1 首选。在单用户桌面、低频改配置和高频读路由的条件下兼顾集成、兼容和可回退性。A10、A11、B02、B06 |
| 认证 IPC／本地服务 | 可识别已配对管理器，支持实时应答；跨平台客户端需集成额外接口 | 要处理身份、握手、令牌轮换、进程生命周期与版本协商 | 出现必须验证写入者身份或多进程共同执行的需求时单独设计。 |
| 直接写内部存储／导入其他客户端配置 | 表面简单，需跟随各应用私有格式 | 读写竞争、泄露登录态、升级破坏兼容，恢复困难 | 维持现有人工无密钥导入；外部接管使用单独的公开合同。 |

选择的依据是用户在应用关闭时也能改路由、常用操作无需新服务、凭据可留在网关。若部署要求能抵抗同一账号下恶意写入者，文件方案只可作为路由提案，自动生效必须升级为已配对的认证通道。外部网关还具有查看提示词和改选上游的能力。

## 接入合同与责任

| 边界 | 输入和输出 | 所有者 |
|---|---|---|
| 外部写入 → 用户文件 | 唯一公开文件、严格字段、版本、管理器名、公开授权世代、递增修订、profile；不带秘密。正常解除提交更高修订和空 active | 第三方写入器遵守并发锁和条件更新；不遵守协议的冲突由 Canvas 显示。 |
| 文件 → 原生配置 | 解析候选、验证已授权的槽／账号／端点／协议／模型范围。解析器只返回结构和稳定错误码。输入失败不得触发联网 | 持有执行锁的 Tauri 实例。分别记录文件修订、已提交修订和 UI 本地代次。 |
| 原生 → 业务入口 | 目录、文本提交、助手流及取消为用途固定的操作；只返回状态、安全输出及随机操作 ID。原生选择 URL、认证头、可用协议 | 已获准本地窗口。UI、插件或 MCP 传入的任意 URL、凭据条目名或覆盖头无法触发受管认证。 |
| 业务入口 → 适配器 | 复用模型协议构造的安全业务字段，绑定原生端点和身份。按发现、文本、SSE、工具、视觉、媒体异步、原任务查询和远端取消分别声明能力 | 每个协议有版本、能力清单、两套有效响应及异常样例。未知能力保持不可选。 |

第一阶段接线点为[配置加载](../../src/services/storageService.ts)、[模型目录](../../src/services/ai/providerCatalogService.ts)、[文本生成](../../src/services/ai/generateText.ts)、[助手流](../../src/services/ai/assistantStream.ts)和[原生请求注册与窗口事件](../../src-tauri/src/lib.rs)。将“能否发送”从判断明文 Key 改为判断该连接的执行能力；已有个人连接继续走原有分支。受管连接的脱敏投影不能进入个人配置自动保存、导出、Agent 工具观察值或节点历史。先核对实际调用栈中的回退、工具往返和目录探测，禁止受管流在失败后切到浏览器 fetch。

**扩展规则。** 新增协议先写 wire fixture，注明认证方案、版本路径、模型 ID、流的结束标志、工具与多模态支持、幂等作用域、恢复凭据和取消语义。核心据能力分派。对 Responses、Chat Completions、Anthropic Messages、Gemini 和自定义媒体分别验证，不能仅凭“兼容 OpenAI”解锁整族能力。通用导入始终允许手动回退，独立工具的一键支持按“桌面 OS × 双方版本 × 操作”登记。A01–A07、B10–B15、D11–D15。

## 生命周期和线性化点

**单一执行权。** 每个用户配置目录有一个长期持有的 OS 排他文件锁，锁由打开的句柄拥有，进程死亡自动释放。另一个 Canvas 实例可继续使用个人连接；受管发送与变更只在锁持有实例进行。后继实例获得锁，先重读授权、撤销记录和已接纳修订，再开放准入。网络文件系统或无法提供可靠锁的目录只提供人工导入。工作进程持锁期间禁止删除或替换锁文件。

同一权威进程用短临界区保护当前快照、授权状态、退出门闩和有界活动表。候选解析、密钥库读取、DNS、网络及事件广播均在锁外。低频控制变更另由单个串行写入队列处理。在本地权威状态的提交顺序上定义“先”和“后”；外部编辑器写盘到通知到达之间存在可观测延迟，远端服务器也有自己的提交点。

| 事件 | 决策／线性化点 | 四种交错的结果 |
|---|---|---|
| 发布修订 | 在锁外验证候选；串行核对旧世代和期望修订。先设“正在提交”门闩，私有状态原子落盘成功后在短锁内交换快照并放开准入。回复 UI 在交换之后 | 发布前已准入的请求用旧版，发布后准入的用新版。进程在落盘后、广播前死亡，继任者加载已提交新版。写盘失败保留旧版并结束本次提交。 |
| 开始外发 | 请求准备可在锁外等待凭据。最终在短锁内检查退出门闩、撤权、用途和预期快照，登记唯一 attempt。此处定义“发送已获准”；网络发送随后在锁外发生 | 已切换的普通新请求重新解析；同一助手轮可使用已固定且仍获授权的旧快照；已撤销绑定不得靠旧句柄恢复。未获准连接零次发包。 |
| 收回授权 | 先同步关闭该世代准入，再持久提交撤销；写失败保持暂停、显示“撤销未保存”，要求重试。成功才向用户报告已收回 | 快照引用存活不代表有权出网。先前已准入请求可能送达，对登记的操作尽力取消。撤销失败且随后断电时，重启按最后耐久状态显示；UI 不许宣称已永久撤权。 |
| 完成、取消、迟到回调 | attempt 的终态由一次条件更新决定，重复到达幂等。远端作业状态、账单与本地 UI 终态分开记录 | 先取消后到结果不会改写新节点；重开凭原收据续查。流结束／连接中断都只释放一次许可。 |

**实例启停。** 启动先验证私有存储及路径，再启动文件观察、首次全量读和重读校验；记录观察期间的修订变化。休眠恢复或观察器溢出后重扫，普通静默漏报以低频核对补偿（建议 5 秒）。不持有锁的多个窗口只收代次，丢包可主动重取。旧修订、同修订异内容、撤销世代和锁竞争各有独立错误码。

**退出和重启。** 主窗口关闭按应用真实生命周期判断，窗口销毁先注销该窗口的订阅和流。其他窗口／后台原作业按既有归属继续。真正退出或更新重启应在可阻止退出的阶段关闭准入、停止监听和定时器、取消连接探测、标记未知提交并保存可恢复回执；用有界等待回收工作任务和通道，最后释放执行锁。建议退出等待预算 2 秒，超时留下可重读状态。最终 Exit 回调只做兜底清理。强杀无法依赖退出回调，计费请求须在首次发包前写非秘密意向记录。恢复“有意向无回执”的任务只查询可证明的原作业，无法查询则提示核对账单。

**所有权与资源上限。** 实例持有观察器、执行锁和连接池；每个调用持有一次性许可、截止时间、取消句柄及版本引用；后台媒体作业由回执持久化接续。采用 RAII 释放活动槽，退出统一等待受跟踪任务；慢消费者或窗口消失应取消网络生产者。连接池按认证边界及 TLS 配置隔离，轮换不允许复用残留默认认证头。宿主崩溃、更新与卸载分别验证；卸载的“清除凭据”须按本应用命名空间显式操作。

## 性能预算与 0 GC 的验收口径

项目已使用 Tokio、tokio-util、reqwest、fs2、rusqlite；现有[桌面传输](../../src/services/ai/httpTransport.ts)包含 WebView Channel、ReadableStream 和编码／解码，[Rust 传输](../../src-tauri/src/lib.rs)及前端已限制请求体至 65 MiB、同时处理带 body 请求数为 2。直接复用可取消传输的结构，受管请求继承已有更严格的限制。接管调度既不要求把整个应用改写为 Rust，也不应放大现有队列。

| 范围 | 候选预算 | 如何判定 |
|---|---|---|
| Rust 稳态路由选择 | 追踪式 GC 为 0；预热后“已解析槽 ID → 取不可变快照 → 核对枚举能力”的计数分配器 alloc/realloc 增量均为 0。p99 ≤ 20 µs | 固定 release 构建，预建 1／32 个 profile，以整数槽或借用键查询，引用计数共享不可变结构，锁外回收旧快照。每组至少 100 万次，独立进程隔离分配统计，空循环校准。 |
| 并发发布与读取 | 1、4、16 个读线程，另有写线程每秒发布 10 次；暖态读 p99 ≤ 100 µs，正常通知路径写盘完成到可见 p95 ≤ 1 s | 从外部写入器完成原子替换计时，到受控新请求第一次命中新修订。将漏通知后的 5 秒补查路径单独统计。审计等待写锁、写盘和发布门闩的长尾。 |
| 请求和流 | 首版建议最多 8 个受管文本活动请求、32 个排队请求；遵守已有更低有效限制。每流暂存最多 256 KiB、总暂存最多 2 MiB | 用慢消费者和 8 路 SSE 检查实际 RSS、活动 permit、队列深度。实现有上界的 ACK／拉取或可验证的背压；超额返回忙或按合同中止，不能丢 token 后假报成功。仅限制 Rust channel 无法保证 WebView 消息队列有界。 |
| 切换与退出 | 连续 10,000 次切换，取消／完成循环后活动槽、观察器、计时器回到基线；退出耗时记录 p95/p99 | 分别统计冷启动、密钥库解锁、磁盘提交、IPC、JSON、TLS、网络首字节和首 token，发布各平台样本数、机型、版本、分位数、RSS 稳态与峰值。停止网络流后内存应回到预热后平台区间，检查增长趋势。 |

以当前个人连接路径作对照，使用同一无付费本机模拟流固定响应体、分块大小和等待。发布前测 Windows 主目标，再测 macOS/Linux，记录硬件、电源模式、构建特性。只在短锁读竞争经测量确有影响时引入读多写少快照库。Rust 所有权支持原生路由无追踪式 GC；动态解析、OS 凭据库、网络分帧、IPC 和 React/WebView 都有单独的分配与调度成本。上述预算达到前保持“待验证”。A10–A18、B08、B11、B18、C17–C19。

## 用户操作与异常反馈

| 场景 | 用户操作和界面行为 |
|---|---|
| 第一次授权 | 设置 → 厂商连接 → 选择连接 → 交给外部管理。显示应用名、模型、将接收数据的主机／端口和路径、凭据保存位置、会影响的入口。先提供不发送提示词的检查，再独立提供可能计费的试用。取消后保持个人连接。 |
| 日常切换 | 设置和模型选择器显示“个人管理／由 Magpie 管理／暂停”、当前模型、最后生效修订。保留原项目选择，打开的草稿可看到外部变化并选择重新载入。切换成功只提示一次，不抢焦点；键盘可完成授权与撤销，错误状态有文字。 |
| 离线、限流、权限不足 | 分别提供“检查网关／重新加载”“等待后重试”“重新绑定”。展示上次可用修订与当前候选错误。配置解析不发付费请求；401/403 不盲目换凭据或跨账户重试。 |
| 解除与收回 | “本次恢复个人连接”允许当前管理器日后再次启用。“收回授权”结束该世代，展示进行中的请求及已提交作业的影响。成功后重新接管需要新授权。 |
| 反馈及诊断 | 支持复制错误码、时间、版本、阶段和匿名关联 ID；示例化输出，不复制源配置、输入正文、路径、完整 URL 或上游错误体。安全日志按字段白名单，转成支持包时再次校验。 |

## 开发与发布门槛

1. **先做可观察的最小闭环。** 对同一 Magpie 文本路由验证目录、单次文本、助手 SSE、取消与网关离线；记录实际双方版本。用现有真实入口和一份旧项目。目录成功和独立管理器按钮分别登记。
2. **再完成原生权威。** 先以纯状态机验证世代、CAS、准入、撤销及有界表，再接入文件、设置、文本、助手和多窗口。为适配器提供有效／无效 JSON 黄金样例。条件并发保证要覆盖在验证前后掉电，而非只测顺序执行。A15、B06–B07。
3. **覆盖直连再扩媒体。** 凭据轮换／迁移执行到每个落盘点强停、恢复并检查无明文回写。用两个隔离模拟账户核对 301/307、未授权同域路径、代理环境变量、系统钥匙串锁定、401 和 DNS／IP 目标限制。公网 HTTPS 策略对回环、私网、链路本地等目的地按授权分类并在实际建连时复核，回环连接绕过系统代理。检查请求、日志、项目导出和支持包中的唯一假秘密。付费提交、续查和下载分别核对认证目的地。A08–A14、D01、D07–D15。
4. **自动化和实机故障清单。** 两个读者遇到切换、两个写入方抢同一修订、撤权与准入同时发生、文件替换／休眠／丢通知、两个宿主竞争执行锁、取消与最后一块 SSE 同时到达、关闭窗口后迟到回调、关机／更新重启、磁盘已满、钥匙串交互取消、崩溃前后各个写盘点。断言每个 attempt 至多一次本地终态，重复事件无额外请求，原回执始终回到原账户，撤权后新准入为零。检查 Rust、前端及跨进程三层。
5. **放量与退回。** 先只给主动选择的桌面用户启用本机文本，再开放已验收协议。发现目的地越权、明文泄露、重复付费提交或撤权失效，关闭对应受管入口，保留个人配置、原回执和撤销记录。只有状态机、故障注入、平台矩阵、性能数据与支持包脱敏结果齐全，才将相应能力标记为“已验证”。协议维护者负责样例与合同，原生维护者负责秘密和并发，桌面维护者负责多窗口与无障碍，发布负责人记录验收版本及未覆盖项。

本次只完成证据和设计。缺陷率、平台兼容性和延迟属于待测结果；上述不变量和退出条件供开发、维护及评审逐项复核。
