## 1. 设置与运行选择

在「UI 切图再生 → 模型设置」分别配置 **识别与结构理解**、**图片编辑与再生**。每个用途独立选择本地执行或云端连接，云端配置可绑定同一连接，也可各用不同模型、协议和凭据。第一次打开默认本地。用户可从已有模型选配，也可在插件内打开宿主设置页创建专用连接并输入 Key。设置完成后只显示来源、连接名、模型、有效协议和可用性。测试连接分为「验证配置」和「带测试图试跑」，联网试跑使用固定合成图并显示目标连接。

| 凭据来源 | 持久化与解析 | 界面与失败 |
| --- | --- | --- |
| 使用 AI Canvas 已配置的 Key | 引用宿主稳定连接 ID 与模型 ID。仅在宿主执行边界解析现有连接和该连接的凭据。连接级更新和轮换随启用配置生效 | 显示「AI Canvas 连接」。删除、禁用或缺凭据时保留选择和离线结果，指向原设置位置修复 |
| 使用插件专用 Key | 连接、模型、Base URL、使用目的和协议均由宿主管理的插件专用配置持有。Key 进入 Rust 凭据存储的专用命名空间，由宿主解析 | 显示「插件专用」。支持新建、替换、清除。清除后对应调用停用。用户可显式选择已有宿主连接恢复 |
| 当前用途为本地 | 持有本地执行选项和适配器版本 | 显示本地能力。云绑定可作为未激活的设置保留 |

从宿主模型建立绑定时默认采用该模型的已选协议，包括高级 JSON 或 Responses 插件预设。模型无独立配置时，选择器为「跟随连接对话协议」。用户仍可在切图设置中为当前用途选其他协议。专用连接也提供连接级对话协议，默认沿用宿主新连接的初始值。保存前同时显示生效协议、服务端点和模型。改变凭据来源、连接、认证、Base URL 或模型时重新预检相应组合。

凭据与已确认的目标绑定。连接 ID、模型引用和协议选择是引用关系，源 Key 或 Key 指纹均不进入插件存储或作业清单。从插件专用切至共享后，专用配置保留为可选项，是否清除由用户发起。遇到认证失败、模型不可用或插件预设失效时，任务留在对应诊断状态，其他凭据由用户明确选择后才能发起新的外发意图。

### 绑定与解析顺序

宿主按用途持久化版本化绑定。本地绑定保存本地算法选项。云绑定保存凭据来源、连接 ID、模型 ID、协议选择及配置 revision。共享模型初次选中时以宿主当前设置填充，显式选择「跟随连接对话协议」时只解析该连接的对话协议。高级 JSON 绑定到明确的模型配置版本，Responses 插件预设绑定到 `pluginId/presetId`。专用连接复用现有连接和模型配置结构，通过宿主受限目录解析。保存时显示实际生效的协议与端点。执行时先以绑定解析连接和模型，再解析有效协议和能力，核对本次授权与活动 revision 后才取 Key 并提交。设置变更使旧任务的外发绑定失效，已审本地结果仍可恢复。缺失或无效配置指向原设置入口。

## 2. 协议矩阵与宿主接口

下表是「识别与结构理解」的完整选项。宿主 Base URL 按连接既有规则配置版本前缀，表中路径为适配器追加的相对路径。支持协议选项以请求保留实际授权图片、结果经统一校验并在真实连接上可用为验收标准。API Key 来源与协议选择独立。

| 选项 | 宿主当前实现 | 切图请求与验收要求 |
| --- | --- | --- |
| 跟随连接对话协议 | 文本模型未设独立协议时解析连接 `chatApiProtocol`。旧连接缺省为 `openai-compatible` | 连接级四种有效值逐一跑真正的带图请求。换连接默认值只影响新获准的调用。已选的独立模型协议在产品设置中明确展示 |
| OpenAI Chat | 模型级 `openai-chat` 是声明式预设，连接级 `openai-compatible` 使用原生 Chat 构造器 | `/chat/completions`，Bearer，消息视觉部件为 `image_url`。保留两条现有路径的多图顺序、结果映射和结束信息。 [OpenAI 图像输入](https://developers.openai.com/api/docs/guides/images-vision/) |
| OpenAI Responses | 内置 `openai-responses`，另可由已启用的 `ai-canvas.openai-responses/responses` 提供同一原生适配器 | `/responses`，Bearer，图片为 `input_image`。内置与插件来源分别验收。插件来源走活动预设租约，停用或升级阻止该轮投递。 [OpenAI 图像输入](https://developers.openai.com/api/docs/guides/images-vision/) |
| Anthropic Messages | 模型级 `anthropic-chat` 对应连接级 `anthropic-compatible` | `/messages`，`x-api-key`，宿主管理 `anthropic-version`，逐张映射到 Base64/媒体类型的 image content block。输出上限按有效模型预算设置。 [Anthropic Vision](https://platform.claude.com/docs/en/build-with-claude/vision) |
| Google Gemini generateContent | 模型级 `gemini-chat` 对应连接级 `gemini-native` | `/models/{id}:generateContent`，`x-goog-api-key`，图像为 `inlineData` part。检查模型 ID 归一化、MIME、图片数、候选终止状态和内容阻断。 [Gemini 图片理解](https://ai.google.dev/gemini-api/docs/image-understanding) |
| 高级自定义 JSON | 复用模型协议编辑、规范化、验证、构造、解析和轮询。当前文本请求提供 `model`、`prompt`、已物化的 `messages` 与 `stream` | 支持现有的同步文本/JSON 与有界异步文本结果映射。验证已选模板实际消费视觉输入并保留 ROI 顺序。需要专用图片变量时，通过同一宿主变量目录、编辑器与验证器增量支持，保留已有协议文档的可读性。 [模型协议主入口](../../../src/services/ai/modelProtocol.ts) · [变量目录](../../../src/services/ai/modelProtocolVariables.ts) · [结果合同](../../../src/services/ai/modelCapabilityValidation.ts) |

当前选项和执行分支可从设置映射、生成入口和协议适配器复核。现有 `model.generate` 按模型类别调用 `generateText` 或 `generateImage`，插件可见目录为脱敏信息。通用执行入口目前按已配置的宿主连接取 Key，且文本生成回传主要是文本。切图需要在可信宿主层增加用途受限的连接解析、结构化的结束原因与用量、严格预算及可取消任务上下文。可提取共享的构造/解码能力供已有入口与切图共同调用，保留现有调用者返回值和默认行为。 [设置映射](../../../src/components/settings/modelProtocol/protocolFormMappings.ts) · [现有插件模型调用](../../../src/services/plugins/pluginRuntime.ts) · [模型目录](../../../src/services/plugins/pluginModelCatalog.ts) · [文本入口](../../../src/services/ai/generateText.ts) · [Chat 请求与响应](../../../src/services/ai/chatApiProtocol.ts) · [Responses 适配器](../../../src/services/ai/responsesApiProtocol.ts)

### 图片编辑能力

识别的四种通用适配器和两种配置方式统一返回切图计划。再生用途通过图片适配器或声明式媒体协议提交已审 ROI。选择器依据 **参考图输入、同尺寸或可复投、图片输出、蒙版约定、任务查询与成本** 筛选。原稿、模型响应和掩膜始终在原生像素链合成并核验。一个连接若同时支持识别与图片编辑，可在两个用途分别绑定并复用同一凭据。 [图片执行入口](../../../src/services/ai/generateImage.ts) · [媒体适配器](../../../src/services/ai/mediaProviderRegistry.ts)

| 通路 | 再生适配约束 |
| --- | --- |
| OpenAI Images 编辑及 Responses 图像工具 | 使用现有官方 Images 蒙版约定为起点，按实际模型、目标地址、图像/蒙版尺寸、MIME 与输出验证。产品当前的 Responses 文本路径已经支持带图理解，若要调用图像工具，开发并单独验收图片通路及结果类型。 [现有蒙版约定](../../../src/services/ai/characterImageMask.ts) · [官方图像生成与编辑](https://developers.openai.com/api/docs/guides/image-generation/) |
| Gemini 图片编辑 | 采用宿主已选的图片模型和编辑适配器。纯提示图像编辑只有在用户选择该能力并通过回投后才作为再生候选。原生蒙版权限由实际适配器的合同和试跑证明。 [Google 图片生成与编辑](https://ai.google.dev/gemini-api/docs/image-generation/) |
| OpenAI Chat、Anthropic Messages 或其他识别接口 | 用于定位、分层、补区建议。图片输出绑定另一个实测支持的图片通路，凭据来源仍各自可选 |
| 高级自定义 JSON 图片协议 | 复用现有 JSON、multipart、二进制或媒体结果映射与受控异步查询。只有支持的宿主变量可装配 ROI 或蒙版。专用蒙版变量沿宿主能力声明和版本验证扩展，确认读取响应为有效图片之后才进入像素合成 |

## 3. 凭据边界与任务生命周期

- 现有 `providerSecretService` 用引用摘除保存前的明文。托管连接正常运行时在可信宿主取得已有配置。现有 Rust 文件存储的保护来自文件权限和应用访问限制。插件专用方案扩展已有原生凭据接口和 namespace，通用 Renderer secret 命令拒绝该前缀。由宿主设置界面提交或清除，原生固定操作内部推导条目名，隔离 UI、QuickJS 和插件设置只收到状态和受限连接 ID。对外包、IndexedDB 普通设置、导入模板和诊断只保存脱敏字段。 [配置凭据服务](../../../src/services/providerSecretService.ts) · [Rust 存储及访问规则](../../../src-tauri/src/secret_store.rs)
- 专用连接的配置与 Key 通过序列化提交维护。新建或替换先原生保存新凭据版本，再条件提交新的活动引用。提交失败保留旧活动引用，暂存由恢复过程按所有权清理。清除先撤销引用和活动权限，再条件回收凭据。表单空白表达「保留」，清除是独立动作。凭据存储不可用时，UI 明示保存失败，桌面保持本地工作流和既有配置。
- 原生任务 ID、项目、用途、连接修订、协议及预设修订、源快照和 ROI 摘要共同绑定一次云调用。最终发送前在同一个可信调度边界登记 attempt 与预算，再调用已选适配器。换 Key、换地址、清除连接、撤权和停用预设使旧绑定失效。已提交调用可产生远端用量。按收据记录实际状态，隔离迟到结果并阻止写入新审核版本。
- 授权摘要包含目标、协议、模型、图片数量、原图或 ROI、上传字节上限和费用可知程度。任务只传获准的图块。适配器限制真实地址、请求大小、重定向、网络与结果回读。高级 JSON 的路径、变量、认证、响应下载与查询均经过现有白名单，最终地址和认证来源再绑定连接。带认证重定向与异步轮询限于已授权的同源和路径语义。无认证的远端结果下载使用经过验证的受限下载路径，不带原凭据。 [声明式安全边界](../../../src/services/ai/modelProtocolShared.ts) · [请求构造](../../../src/services/ai/modelProtocolRequest.ts) · [轮询与结果](../../../src/services/ai/modelProtocolPoll.ts)
- 带图调用按用途走敏感传输。实现时核对 HTTP 调试和错误路径，包括请求体、回显、原始错误、Header、查询认证和二进制媒体。现有 `corsSafeFetch` 敏感分支有专门日志判断，切图调用需实测错误响应也只保留稳定错误码、脱敏 attempt ID、状态和长度。错误页和报告不可直接展示供应商原始 JSON。 [传输代码](../../../src/services/ai/httpTransport.ts)
- 失败结果区分无有效凭据、连接/协议变更、图片输入不支持、模板未映射图片、能力预检失败、拒答、截断、限流、协议或 schema 异常、取消和已提交状态未知。识别可以在额度内对失败 ROI 明确重新发起。会产生费用的提交在状态不明时保留收据，并按可核验的远端任务 ID 继续查询。未知任务不得以另一条凭据自动重投。

## 4. 请求校验与协议放行

1. 协议与模型能力分开检查。适配器读取宿主声明，并按账号、地址、模型、协议及版本探测实际模态。识别必须有图片输入与可解析文本输出。JSON Schema 是否能在供应商侧约束单独声明，未支持时使用输出指令和相同的本地结构校验。角色、ID、框和缺项经过统一校验，截断、拒答和不完整状态不能提交为成功批次。
2. 宿主为每张概览和 ROI 绑定本地编号、原图坐标、实际尺寸和变换。试跑应检查装配后图片的数量、顺序、MIME、像素哈希及请求字节。高级 JSON 的文本视觉夹具用包含两张合成图的 `messages` 映射，另加包含有效任务 ID 和最终文本结果的异步夹具。缺图片映射明确报错。适配器返回候选结构给切图任务，连接配置和凭据保持在宿主生命周期内。
3. 离线协议测试矩阵为 2 种凭据来源 × 6 项协议。跟随连接子矩阵覆盖 4 个有效值，以及旧连接缺省。Responses 子矩阵覆盖内置/预设、五图编码和中途停用。高级 JSON 子矩阵覆盖同步、异步、认证类型、无图映射、非法路径和含回显密钥的伪错误。每例用不同合成凭据对照精确捕获上游地址和认证，检查完成后凭据不进入设置、日志、导出及错误内容。
