# UI 切图实现与维护手册

2026-11-24 · 开发与维护基线 · [产品总入口](00_需求与设计决策.md) · [批次与像素契约](02_架构契约与实施验收.md) · [模型协议与双密钥](04_模型协议与双密钥来源.md)

## 1. 一次整页操作的交付

1. 用户从图片节点进入插件，选择快照、模板和交付要求，点击「分析整页」。首屏在原位叠加候选框，旁边显示应交付项、小件、重叠、待审核和缺项。每个规格都可追踪到一个或多个实例。
2. 插件按页执行规则、原件匹配、OCR 和按需视觉分析。原位图、透明底和层级树共用一个审核版本。支持框、套索、参考线、锁定、拆组、批量确认同类确定性候选与局部重跑。模型调用用当前用途的连接和权限。已手调对象在区域重跑后仍按原改动显示，新意见作为候选。
3. 用户可批量选择去字、补遮挡或新状态。每组请求明确关联目标、允许改动区域和保护区。模型完成后对照查看原片、已合成结果和差异，选中的版本参与出包。
4. 一次发布导出原尺寸 PNG、结构与回贴坐标、素材复用关系、像素档及缺项报告。成功标准为已确认交付项全部具有可核对状态。每个文件经原生回读，导出完成后可选部分素材写回画布。 [任务生命周期](02_架构契约与实施验收.md#4-生命周期恢复与安全)

## 2. 提高切图完整率与可复用率

### 原件、规则和图块的优先级

| 输入证据 | 实施方法 | 审核和降级 |
| --- | --- | --- |
| PSD 图层或已知透明原件 | 优先读取获准的源图层/素材。按尺度、色彩、裁边和原位几何核对。可使用签名建议候选，严格逐像素验证后赋予像素档 | 原位像素与独立源像素各自比较，遮挡下的未知部分由原件证据确定。受剪贴、混合模式和效果依赖的图层保留依赖 |
| 人工参考线、规则格与透明图集 | 用受检整数半开框生成，先统计准确为零的 alpha 沟槽。以候选空列/行及触线计数分支。透明连通域为补充证据，按工作量限制行程表和队列 | 空格、有软阴影跨线、对象粘连分别给出证据。分块工作区溢出时降为有界 ROI 或待审。 [区域网格规则](03_ImageToSlice专项对标与优化.md#31-前移确定性切片) |
| 平面效果图和混排区域 | 先做整页缩略图和分层区域提议，再对小件、文字密集、图块交界、父子嵌套和低置信区排队。使用原图 ROI 跑局部检测和 OCR。规格列出的缺项也触发定向 ROI | 先保留整体位置和角色，再用高分辨率局部修边。返回待查区域及预算耗尽原因，保留可离线审核的结果 |
| 局部背景与遮挡 | OCR 给出覆盖提示，分割给出轮廓和孔洞，图像模型补齐已审缺口。用原稿或同一项目中的可验证素材优先填补隐藏部分 | 按每个底板合并已审掩膜。保留原片、前景图、保护区和生成版本，未获得可靠回投时保留缺项 |

原图坐标始终为源快照左上原点、整数半开区间。以主契约的 1024px 分块、160px 交叠为起点，分别对短边 ≤32px 的小目标和长条控件做消融。每个图块保存原图范围、可接受有效区和图像变换。中心落在有效区时作为该图块的优先证据。接缝或目标超出有效区时，保留候选、请求包含完整对象的局部图或进入复核。任务已耗尽预算时直接记录该范围，因此缩小分析图也有可见的覆盖边界。 [坐标契约与回投示例](02_架构契约与实施验收.md#几何透明和归档兼容)

### 合并候选与小件保留

- 以来源范围、角色、父子关系和证据优先级匹配同一实例。对同角色的接缝重复框，用 IoU、中心距离、尺寸差和 ROI 位置做确定性匹配。相同像素但位置不同保留独立实例。只有多项证据一致才自动合并，存在冲突时在同一审核组展示。空间索引和候选数受主契约预算约束。
- 底板、文字、角标和图标可共享像素范围。覆盖关系独立于父子和叠放关系。用户锁定、显式拒绝、原件匹配和模型建议均有独立来源；同一字段的手工审核结果优先。局部重跑按受影响范围提交一个审核版本，稳定顺序取原位坐标、角色、候选 ID，无关区域沿用已审核值。
- OCR 将 `28:58`、`02:36:18`、`50/100` 和 `x100` 作为专项输入。小面积符号与已知文字词组保留关联，原图短边 1–7px 的候选由角色、上下文和边界证据审核。重复卡片应用共享外观候选，动态计数、开灯/熄灭和按压/禁用状态分别留实例或缺项。
- 第一轮逐模板记录区域覆盖率。同图比较「固定网格」「整页视觉模型」「规则与局部精修」的混淆表，用漏掉的规格驱动局部提示。人工修改结果可做脱敏标注回流，训练或外发按项目原有授权执行。 [上游缺陷探针与同稿设计](03_ImageToSlice专项对标与优化.md#4-同稿实验与放行)

例如奖励卡内的货币图标、数量 `x100` 和右上角标各对应独立交付项。低倍率整页分析只发现卡片时，规格缺项会触发卡片原像素 ROI。OCR 确认数量，局部分割复核图标和角标，卡片本身保留底板候选。另一张同款卡片保持独立回贴位置，匹配到同一货币原件并验证通过后才共用 PNG。确有去字、遮挡或未展示状态的需求时，分别保留可审的掩膜或缺项。

### 边缘、残底与再生

1. 精确矩形直接以源 RGBA 出片。硬边人工选区保留内部原 RGBA 并在外部写透明黑。透明边保留原 alpha；裁边产物记录裁边前尺寸与偏移。按源快照核对边缘、孔、透明 RGB 策略和整片校验值。
2. 单张不透明图的独立软边走估计档。对多色背景、发光和玻璃，以背景区域连续性、前景/背景种子和最小可写区域构造局部掩膜。按已知前景、已知背景、边缘不确定区复核，边缘去色只作用于估计档。预览使用棋盘格、黑白与对比色底进行残底和断边检查。内容完整性不明时保留组合裁片或要求原稿。
3. 去字识别遮罩先覆盖实际字形、投影和抗锯齿，保留实心边框、图标、非去除文字和相邻底板的保护掩膜。无细节的可验证纯色或简单渐变先用本地补区候选。复杂纹理、被遮挡物和新状态走获准的图像再生。ROI 可包含上下文，允许写入范围仍由已审掩膜决定。
4. 回投记录输入比例、填充、原图 ROI、返回尺寸以及变换有效区，偏移不确定时进入人工复核。原生将已核验候选合成到快照，在掩膜零值和保护区走逐字节拷贝，验收逐像素比较。可写 A8 只改变选区内的合成程度。导出标注生成来源，原始图像和模型版本以受限引用复查。 [像素档及颜色](02_架构契约与实施验收.md#像素档) · [蒙版协议](04_模型协议与双密钥来源.md#图片编辑能力)

## 3. 作业配置、取消与恢复

每个整页作业冻结源快照、模板与阈值版本、审核基线、允许的推理用途、预算和各模型连接修订。候选与修补产物保留其输入摘要和处理方式。审核版本是单向递增，撤销以创建新版本表达，已发布包由相同审核意图和收据识别。包清单中记录端侧与协议适配版本的脱敏摘要，供重放和回归定位。

| 失败节点 | 维护动作与用户恢复入口 |
| --- | --- |
| 未获准发送、连接或预设失效 | 显示对应设置入口，保留本地候选。新绑定经预检后对受影响范围重跑 |
| 发送后断网、超时或应用退出 | 保留可核对的提交状态及收据。具有远端任务 ID 时按原获准通路查询。状态未知时提示核对费用及任务，用户可确认新的尝试 |
| 版本已变化或用户已取消 | 停止新工作和旧回写。跟踪已发生的远端提交，分离可回收工作区和正式发布目录，重开可恢复到最后可证明的审核状态 |
| 暂存损坏、写盘失败或目标冲突 | 根据原生收据和文件摘要判定未提交、已提交或提交未知。用户可重选目标或校验完整旧包后回填收据 |
| 包与宿主版本不一致 | 版本化读已知格式。旧格式用只读转换或保留并提示升级。回退时保持素材文件可读、导出报告可访问，验证未知格式失败清晰 |

### 4.1 离线首版实施记录

2026 年 11 月 24 日，`0.1.0` 写入独立插件的图片节点入口、隔离审核面板和宿主 `image.uiSlice` 能力。先从已保存到项目的静态 PNG 或 JPEG 解码出带 EXIF 方向的原尺寸画布。面板支持严格透明沟槽建议、矩形、硬边单环套索、原图坐标及区域等分网格。宿主绑定项目租约、活动插件版本和审核对应的源图 SHA-256。

当前交付介质为一个 ZIP。最多 128 个切片，包含 `assets/*.png`、`manifest.json` 和 `review.json`。规范图与 PNG 均使用 RGBA8，矩形采用左闭右开坐标，套索外部写透明黑。单片按原图坐标裁切并回读比较 RGBA，整包在同目录暂存并回读条目与文件摘要。相同输入与审核提交到同目录时，对同名包核验完整摘要再复用。Windows 沿用原生文件句柄无覆盖发布。非 Windows 使用已有归档发布函数。关闭面板或切换项目会请求取消，进程异常退出可留下 `.ui-slice-*.pending`。

在桌面宿主中安装 `plugins/ui-slice` 开发目录，从项目图片节点工具栏打开。测试样本至少覆盖 36 项混合选区、奇数网格、alpha 为 1 的沟槽、隐含 RGB、EXIF 方向、输出占用、重复导出和关闭时取消。验收时在仓库根执行 `npm run check`，在 `src-tauri` 执行 `cargo check` 和 `cargo test ui_slice`，再验证 Windows 打包版。回退操作为停用该插件，已导出的 PNG 和清单仍可读取。

本次完成清单、源码与 SHA-256 的静态核对。桌面安装、打包、回贴互操作、崩溃恢复和 0GC 分配计数待验证。参考线和回贴、双 Key、六类协议与 Responses 预设、OCR、AI 整页识别及蒙版再生按后续阶段接入。

## 5. 后续版本维护

- **协议维护。** 每次改适配器留请求和响应夹具，对比同一图像内容、顺序、认证和结束原因。宿主共用修改要回归文本节点、对话、图片模型和 Responses 预设。高级 JSON 增变量时同步维护变量目录、编辑器说明、导入、旧模板和错误文案。只有取得真实渠道证据才更新可用性矩阵。 [协议矩阵](04_模型协议与双密钥来源.md#2-协议矩阵与宿主接口)
- **切图维护。** 规则变化时更新透明图集、混排网格、首充原位裁片、过渡边和 alpha 历史夹具。模型、提示词或阈值变化时单独版本化，可按任务恢复旧策略，成对比较效果。图层/素材字段变化需经新旧包互读、真实导入器重开和无权限目录异常测试。
- **发布与恢复。** 桌面对应宿主版本先验证插件能力声明、凭据升级、原生 ABI、命令权限和窗口隔离。发布记录填宿主/插件/协议版本组合、模型能力和分组基准、失败恢复、启用范围和回退操作。无法放行的网络能力可按用途关闭，用户可继续完成已审离线包。 [插件开发规范](../../../doc/插件开发规范.md) · [发版流程](../../../doc/打包与发版流程.md)
- **核验入口。** 实现后经授权在仓库根运行 `npm run check` 及相关单测，在 `src-tauri` 运行相应的 `cargo check`、`cargo test` 和 Release 分配专项。随后在打包桌面执行双密钥与六协议、真实修补、大图、杀进程恢复、同目录并发和版本回退。验证资料优先用合成图片和测试凭据。记录阶段、稳定错误码、耗时与版本以复现问题。 [仓库开发指南](../../../doc/开发指南.md)
