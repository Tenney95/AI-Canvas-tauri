# PS-Tidy 与 AI Canvas 切图工作包互通

评审稿。基线为 PS-Tidy 0.7.5（`e4aef4f`）与 AI Canvas「UI 切图再生」0.3.2（宿主 `56f0d14a` 加当前工作树）。承接[前序调研与开发会话](codex://threads/01a20c50-c14e-7880-8a8a-5e3b6cb24520)、[Image To Slice 专项对标](03_ImageToSlice专项对标与优化.md)和[可编辑工作台方案](06_可编辑切图工作台与PSD实施报告.md)。

## 1. 交付目标

用户在任一端「导出切图工作包」，另一端从「导入切图工作包」独立打开，查看原图和原位选框，继续调整名称、角色、取样框、硬边套索、摆放位置、分组、层序、显隐及审核状态。保存后可从任一端再次导出，往返保留稳定对象 ID、像素来源、图层关系、已审与待补状态。编辑、导入和出包可离线完成。各端项目拥有本地副本，回传有明确的版本关系。

工作包扩展名拟定为 `.uislice.zip`，两端沿用原有 PNG 目录或交付 ZIP 入口。分层 PSD 承担 Photoshop 图层交付，画布节点承担作品排版。首轮在 PS-Tidy 切图面板编辑并回传。Photoshop 原生文字、智能对象、混合链及直接修改 PSD 后回传属于图层适配阶段。

## 4. V1 工作包契约

下面的字段和上限是实施提案。开工先冻结 JSON Schema、Rust 类型、双端迁移夹具及黄金像素向量。JSON Schema 校验结构，Rust 校验引用、树、坐标、预算和像素一致性。 [JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-core)

| 项 | V1 约定 |
| --- | --- |
| 包内容 | `manifest.json`、`source.png`、清单引用的 `assets/<uuid>.png`。原图确定性裁片由几何重新生成，缓存可省略，无法由源图重建的素材必须内嵌。归档用 ZIP Stored、单卷、无加密、无 ZIP64。固定 ASCII 条目格式，中文名称保存在 JSON。 [ZIP 规范](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT) |
| 工作稿身份 | `schema: "ui-slice-workpack/1"`、`documentId`、`revisionId`、`parentRevisionId`，根版本父项为 `null`。结构主体为 `source`、`assets`、`nodes`、`rootOrder` 和 `gaps`。改名、摆放和重排保留对象 ID，复制、合并和拆分创建新 ID。旧格式以源包身份和固定条目身份派生可重现的 UUID，重复导入得出同一组 ID。 |
| 源图 | `source.png` 是不重采样的静态 PNG，RGBA8、straight alpha、显式 sRGB、归一化方向、保留零 alpha 的隐藏 RGB。记录尺寸、规范版本、规范 PNG 文件摘要和按行 RGBA 摘要，可附原输入格式、原文件摘要、色彩依据与方向映射。各端只规范化一次，后续从规范 PNG 复算摘要，避免 JPEG 解码器、ICC 与 EXIF 差异。原 PSD 文件需单独交付。 |
| 素材与实例 | 素材 `id`、`kind`、`pixelClass`、`origin`、`review`，及 `sampling` 或嵌入 `file`。原图取样保存 `rect` 和可编辑的 `rings`；嵌入 PNG 保存尺寸和两种摘要。实例 `id`、`assetId`、`name`、`role`、整数 `placement`、`visible`、`locked` 及交付资格。保留用途和可转写文字的语义。多个实例可共享素材；仅改一个实例的取样时分派新素材 ID。 |
| 图层树 | 有序 `rootOrder` 和各组的 `childOrder` 从底层到顶层。每个节点出现一次，拒绝环与悬空引用。组内沿用画布坐标。合成卡与拆解子层保留当前可见分支，原位验收检查重复叠绘和隐藏状态。 |
| 缺项和证据 | `gaps` 带稳定 ID、范围或节点关联、原因、审核状态和可用候选引用。区分 `exact-rgba`、`exact-composite-rect`、`masked-source`、`estimated-alpha`、`generated`。像素档、审核状态和识别分数分开。索引缺省显示未知。改动取样或结果像素时清理失效验证并回到待审。 |
| 摘要 | 文件 SHA-256 验证传输字节，RGBA SHA-256 验证逐行像素。工作稿语义摘要对规范 JSON 投影计算，包括资源尺寸与像素摘要，排除包级时间戳、传输元数据及编码字节摘要。建议以 RFC 8785 固定序列化并增加 Rust/JS 共用向量。套用同样的身份规则后，重新编码无损 PNG 仍可识别为同稿。重复 revision ID 只接受相同语义摘要；导入仍验证各载荷的文件摘要。 [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html) |

### 几何与像素

- `rect=[x0,y0,x1,y1)` 是规范原图的整数像素边界，左上原点。`placement=(x,y)` 表示未裁边素材的摆放原点。嵌入 PNG 的透明裁边偏移 `trimOffset=(dx,dy)` 独立记录，最终摆放为 `(x+dx,y+dy)`。取样与摆放可以分别改变，原位预览按画布裁剪，单片 PNG 保留完整尺寸。例：取样 `[30,40,130,100)`、摆放 `(40,38)`、偏移 `(7,3)`、PNG 80 × 50，得到原位矩形 `[47,41,127,91)`。
- 多环硬边轮廓使用规范原图边界整数坐标，按全局奇偶填充判断像素中心，扫描线纵向半开，左交点包含、右交点排除。区域内保留原始 RGBA，区域外写透明黑。所见即所得从实际渲染校验。PS 旧单环入口继续支持，新工作包须完成多环渲染和编辑后放行，孔洞、边界取整和相交规则使用共享黄金向量验证。
- 首轮双端共编辑矩形、多环硬边、栅格图层、分组和审核。A8 软边、文字层、旋转、矢量和 AI 修补完整版本作为可声明的新能力。遇到未支持的必需能力，保留原档并显示可用预览或明确拒绝编辑，报告到具体对象。估计透明或已生成的 PNG 可作为带来源的嵌入资产调整摆放，重新取样需新素材版本。

### 旧包迁移与重绑

| 输入 | 对应动作 |
| --- | --- |
| PS `slice-v1` | 校验清单与 PNG 尺寸/文件摘要，`left/top/width/height` 转半开框，非空 `polygon` 变成单环。保留已确认语义、角色及 `origin`，用原始 `quality` 与像素证据确定质量，历史同名称按条目 ID 区分。 |
| AI Canvas `ai-canvas-ui-slice/1` | 校验 `reviewSha256`、个别文件/像素摘要和 asset/instance 对应。保留多环；旧包未携带的角色和审核状态置为未知/待审。缺项仅恢复有实际记录的条目，其他以旧稿缺项资料未知表示。 |
| 两类旧包缺原图 | 先进入素材模式，支持查看、改名、摆放和分组，等待原图后开放重取样。如果有源字节摘要就按原文件核验，也可在有规范像素摘要时按声明的旧规范验证尺寸与像素。没有同源证据时可显式新建源和分支，再人工确认旧框。重绑后生成完整工作包。 |
| 后续 Image To Slice ZIP | 可先适配位置、PNG、圆角和 AI 处理标志。迁移按素材模式处理，SVG 单独验收。执行时只解释白名单字段。 |

PS 当前 5 项限制同时用于审核队列及 worker 的 `slice-v1` 请求。工作包编辑器须能保存完整整页稿（目标 128 项），原生工作包直接从冻结稿出包。旧 PNG 可走原有 5 项批次与用户指定的交付选择。整页工作包保存全局层树、审核和 ID。

## 5. 工程接入、版本和生命周期

| 部位 | 复用与改动 |
| --- | --- |
| 公共协议与像素 | 先共享 schema、迁移夹具和黄金向量，复用两端现有 Rust 裁切链，靠同一测试向量对齐多环及色彩。纯 Rust 模块负责结构、几何、像素和封装。稳定后验证两端通过固定版本源码或 Rust crate 分发，无需互相依赖本机路径。 |
| PS-Tidy | `lib/slice-panel.js` 负责打开、编辑及审核；`lib/slice-workflow.js` 协调所有者、快照和写入；现有 runner/worker 派发专用预检、加载和封装。Photoshop 快照继续经宿主副本产生。只有重新从 Photoshop 取图才需要打开源文档。 |
| AI Canvas | `plugins/ui-slice/ui.js` 扩展专用 `image.uiSlice` effect；`pluginUiSliceService.ts` 复用宿主文件选择与项目绑定；`host_effects.rs` 和 `ui_slice.rs` 保留权限、租约、revision 校验及原生 I/O。UI 接收有限结构、缩略图与租约。无选中节点时，导入前经宿主建立或绑定规范源节点。 |
| 工作稿存储 | 各端项目域保存规范源、内容寻址资源、工作稿和有界撤销版本。两端归档和导出由各自宿主管理。异步和临时句柄由作业持有，关闭后重开读取已提交稿。 [AI Canvas 文件与存储](../../文件与存储模块.md) |

1. **打开**按「选择 → 原生预检 → 暂存校验 → 提交 → 切换」。校验失败保留旧稿和资源，提交后方切换。重复导入相同稿件返回已有收据。
2. **编辑**按工作稿串行，以 `expectedRevisionId` 比较并提交。一次编辑形成一个修订和一次撤销。取样与派生像素变更重新待审。改名、调整位置与层序维持像素证据，已有交付仍可查。
3. **回传**同修订及语义摘要相同则显示已有。相同修订 ID 对应不同摘要视为完整性错误。仅在本地干净且直接父修订匹配或有可验证祖先链时快进。双端各改、身份冲突或祖先未知时，提供保存为分支和版本比较入口，保留双方内容。
4. **导出**固定 revision、源身份和选中内容。目标目录独占暂存，按单片写入、flush/sync、回读 SHA-256 后无覆盖发布。发布前可取消并清理当次暂存；发布后按实际收据确认。退出或重启只清理本作业登记的未提交资源，恢复须验证项目所有者、版本和文件身份。
5. **AI**单列「等待发送确认」「已发送，等待模型」「候选已接收」「复核」。等待确认单独计时。结果写回前核对源、ROI、基线 revision 和调用租约。重跑保留已审、锁定与手动改动，冲突意见作为可审核候选。打开、迁移、保存和往返全程可离线。

### 安全与性能预算

- 原生检查中央目录、实际条目、解包方法、CRC、条目和累计上限。只接受清单与固定资源路径，拒绝绝对路径、越界、重复或大小写冲突、链接、特殊条目及未引用资源。使用已授权文件句柄读写，独占暂存目录由宿主生成。数据字段无法开启新权限。包中排除本机路径、凭据、令牌和句柄。
- 提议首轮对齐源宽高各 ≤8192、总面积 ≤3200 万像素；单片 ≤800 万；最多 128 项及 6400 万批次像素；单项总顶点 ≤128。ZIP ≤512 MiB、JSON ≤4 MiB、节点与缺项各 ≤512、层树深度 ≤16。源 PNG 暂按 64 MiB 预检。高熵规范源可能先触及该字节上限，保留原稿并提示超限。新增条目数、临时磁盘和 RSS 门槛在参考机压测后冻结。
- 串行处理单个原图 RGBA 和单片缓冲，源、输出与回读缓冲错峰，避免持有整包。面板按可视区加载缩略图，拖拽复用缓冲。0GC 门槛适用于预热且缓冲预分配后的原生裁切、奇偶填充与合成热循环，计数为 0 次分配、0 次重分配、0 字节。编码、ZIP、IPC、WebView GC 与模型耗时分别观测。 [PS 已有性能证据](<../../../../../PSD2UI/analysis/效果图AI切图_20261123/08_首版实施与放行判定.md>) · [AI Canvas 性能设计](06_可编辑切图工作台与PSD实施报告.md)

## 6. 精准切图接入

先用 PSD 可取证层、透明源、网格及边缘规则建立确定性候选，OCR 和视觉模型补角色、重复状态、规格与可能的遮挡。整页优先识别可交付组件，待审树可展开图标、文字、底板和角标。小图标、细描边和低对比文字走原图 ROI 精修，坐标回投到冻结的规范源。模型分数用于排序，交付质量由来源和像素验证推导。保护已审核及已锁定选区。使用同稿标注衡量组件召回、误切、边缘 IoU、逐像素一致性和人工修订时间。

首充用「60钻石充值卡」作为组件，价格、货币图和角标作为子件。动态文字有转写及区域，像素版本留在原位。合成底板按复合来源处理，被压住的完整底板留待补。工作包传播同一证据和审核决策，真实 AI 输出另用同稿验收。

## 7. 实施顺序与验收

| 阶段 | 放行标准 |
| --- | --- |
| P0 · 协议与夹具 | 冻结 schema、规范 PNG、ID/摘要及像素向量。双端同一夹具核验近边界、孔洞、透明隐藏 RGB、中文名、重复引用、裁边偏移、非正常 EXIF 方向和已知 ICC。PNG 重编码可改变文件摘要，几何、像素和工作稿语义仍须一致。 |
| P1 · 双端往返 | 实作旧包迁移、编辑、保存、工作包导出及回传。首充稿执行 PS-Tidy→AI Canvas→PS-Tidy 和 AI Canvas→PS-Tidy→AI Canvas；各改一个框、一个轮廓、一个摆放位置和子层顺序。验证 ID、像素档、缺项和未改素材哈希，原位零偏移。用 128 项整页稿覆盖 PS 持有、编辑及再出包。 |
| P2 · 稳定性与旧版本 | 模拟取消、磁盘满、只读、进程中断、异常条目、超预算、未知能力、重绑失败和双端改稿。检查失败前旧稿可读、提交后收据可追溯、重复导入幂等。回归原有 PNG/ZIP 交付、Windows CEP 和 AI Canvas 两种面板运行时。功能入口可按宿主能力停用。 |
| P3 · 扩展 | PSD 图层映射、软边、再生结果的完整版本往返按单独能力放行，先固定各端可编辑和只读的降级夹具。用真实模型和同一首充标注稿验证组件层次、局部精修和审阅成本。 |

本轮完成外部源码、前序文档、当前源码及首充验收清单的对照。开发、双端实机互导、像素精度和性能放行待实施。

## 8. 实施进度

2026-11-25 开始实施。PS-Tidy 原生裁切内核增加多环奇偶填充和灰度覆盖率计算，worker 可接收多环参数，既有单环请求保持兼容。预分配后的像素循环已执行零分配测试。灰度覆盖率能力目前仅在原生内核中，尚未接入工作包和蒙版编辑界面。

AI Canvas 识别后的待补项现在随素材 ZIP 写入 `manifest.json` 和 `review.json`，并经过宿主与原生层校验。识别候选的完整编辑状态、再生像素和工作包修订尚未持久化。旧 ZIP 发布路径保持可用。AI Canvas 宿主构建和桌面端导出需要按项目测试约定另行验收。

AI Canvas 与 PS-Tidy 新增识别草稿的保存和打开入口，归档包含规范化原图、裁片、选框、多环及待补说明。AI Canvas 打开时要求绑定同像素源图节点，核验清单摘要、文件和裁片像素，并在替换当前结果前请求确认。草稿不包含再生候选与独立图层、柔边蒙版或修订，文件名使用 `ui-slice-draft-*.zip`。旧宿主通过能力标记隐藏草稿入口。

已用 PS-Tidy 原生 worker 生成包含双环孔洞和待补项的草稿，再由 AI Canvas 原生层打开并导出，最后由 PS-Tidy 原生 worker 重新导入。该自动化样例通过像素和摘要校验。桌面宿主已安装 0.3.5，并在真实首充图片上取得 18 项切片和 9 项待补。上述结果覆盖现有识别草稿，图形界面下的双端导入导出仍待验证。

正式共享工作包 schema、独立层树、柔边蒙版、修订与原图重绑、项目收件、PSD 图层回采和双端完整往返尚未完成。发布前仍需按第 7 节逐项验收，不应将普通素材 ZIP 当作完整工作包。
