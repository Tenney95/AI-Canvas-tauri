## 建议先交付什么

用户在设置里为一个文本连接选择“交给外部管理”，看到由谁提供路由、哪些请求会走它，并能随时收回。个人连接继续可用。已授权的管理器可在应用运行中选择模型、切换线路和解除接管。项目里保存稳定的模型选择；每次新请求才解析它当前指向哪里。

先用 **Magpie 本机网关 + 现有自定义连接** 验证真实需求。随后发布 **AI Canvas 自己的、只含非秘密数据的版本化配置文件**，供任意管理器实现。优先打通受管文本请求和流式助手，再处理有远端作业身份的媒体。将“可以使用网关”“可以写配置热切换”“管理器界面内可一键接管”分别记录版本和验收结果。

## 今天可试的路径

1. 在同一台机器上启动 Magpie，确认它显示的本机端口，并在其中选好可用的文本模型或路由组。默认端口为 3425。可先用不带凭据的 `GET /api/hello` 检查返回的产品名和版本。这是连通性检查。
2. AI Canvas 桌面 → 设置 → API Key／厂商连接 → 从 JSON 文件导入，选择[本机 Magpie 连接样例](./examples/magpie-local-connection.json)。也可手动新增“自定义接口”，选 OpenAI 兼容，填 `http://127.0.0.1:3425/v1`。非默认端口请在保存和拉取模型前修改。
3. 在该连接的 Key 栏填公开应用标记 `magpie-ai-canvas`。上游厂商 Key 只在 Magpie 内设置。本机 Magpie 接受该标记用于用量归属，任何同机客户端都能填同样的值。只在用户选定的本机 Magpie 连接上使用它。
4. 拉取模型、勾选需要的文本模型并保存。在文本节点或助手显式选择该连接的模型。若需由 Magpie 调度，选择其目录里真实存在的路由组 ID；选定具体模型 ID 时，应用会继续请求该 ID。先用无敏感信息的短文本发起一轮；生成可能计费。核对 Magpie 的请求归属，再切换路由组成员发起第二轮。目录变更目前通过设置手动刷新。
5. 改回个人连接即可结束试用。样例是一次性导入，新导入会生成连接 ID。重复导入不能更新原连接。当前尚未执行真实 Magpie、CC Switch 或上游账户联调。[Magpie 接入说明](https://usemagpie.ai/docs/integrate)

只做一次性导入开发量最低，适合当前试用。文件方案能在应用关闭时写入，启动后读取，也便于没有 SDK 的管理器集成。为配置单独开 HTTP 服务会增加鉴权、端口和生命周期负担；v1 使用文件即可。直接改 IndexedDB、复制其他应用的登录文件或向外开放现有秘密目录，都会把内部存储格式和凭据权限变成第三方依赖，排除这些做法。

## 外部文件 v1（拟议合同）

位置为 Tauri `app_config_dir()/provider-management/routes.v1.json`，以桌面标识 `com.aicanvas.app` 解析。设置页提供“打开配置目录”、复制实际文件位置、示例及“重新加载”。实施时随版本发布 Windows、macOS、Linux 的路径表和 JSON Schema，并在三个桌面平台核对解析结果。浏览器演示维持会话级设置。仅监听固定的用户文件；项目、插件、导入包及同步盘里的同名文件都没有接管权。

以下为**待实现**的配置示例。上面的 Magpie 导入样例适用于现有版本，两种文件有独立的格式标识和生命周期。

```json
{
  "kind": "ai-canvas/provider-routes",
  "version": 1,
  "managerId": "magpie",
  "grantEpoch": "d8278c83-c3ea-4cfe-aadc-0e88c65d1e09",
  "revision": 12,
  "active": "writing",
  "profiles": [
    {
      "id": "writing",
      "baseUrl": "http://127.0.0.1:3425/v1",
      "protocol": "openai-compatible",
      "authBinding": "local-magpie",
      "model": "writing-group"
    }
  ]
}
```

- `active` 为 profile ID 或 `null`。示例中的模型名须替换成网关实际提供的 ID。v1 对应用户显式授权的一个文本连接槽；当前项目中显式指定其他连接的节点和助手保持各自选择。多个预定义 profile 可在授权范围内动态切换。App 管理的连接和映射保持独立，解除后复用个人连接 ID 和当时有效的个人设置。
- `grantEpoch` 是每次授权后由 Canvas 生成并交给写入器的公开世代 ID，示例值仅供识别格式。旧文件中的世代必须与当前私有授权匹配；复制当前公开 ID 无法证明写入方身份。候选预览可在绑定前完成，生效须使用本次授权的 ID。
- `authBinding` 是用户在本机绑定的公开别名。Rust 私有记录把它限制到管理器、连接槽、协议、规范化 origin、端口、API 路径前缀、认证类型和账户范围。公开文件里写出这个名字、本机账号名或高版本号都不能赋予权限。首版支持本机网关公开标记；受管 HTTPS 直连须先实现原生凭据发送。用户可以预授权多个目的地，日常切换无需重复确认；新增目的地先展示将接收提示词的地址和用途。
- 使用严格 UTF-8 JSON，字段白名单、拒绝重复键、未知版本、同名 profile、悬空 `active`、过长或不规范 ID。建议上限 64 KiB、32 个 profile。禁止嵌套命令、动态模板、任意环境变量名、私有条目路径、任意请求头、userinfo、query 和 fragment。只对明确授权的字面回环 IP 允许 HTTP，远程使用 HTTPS。校验原始输入后再规范化；协议路径由客户端生成。防止绝对路径覆盖、越出已绑定前缀和带认证重定向。目录和文件打开时防符号链接、junction／reparse 替换。
- 使用固定协议枚举，首期只开放 `openai-compatible` 文本，逐项验收再扩展。网关地址和客户端最终请求路径要成对验证。例如 AI Canvas 当前会直接追加 `/messages`，接 Anthropic Messages 时应最终得到 `/v1/messages`，不能照搬由其他 SDK 自动补版本的示例。模型列表只显示被验证的能力；工具、视觉、推理和流式分别标记。

## 写入、热加载与解除

| 事件 | 建议行为 |
|---|---|
| 首次接管 | 应用默认使用内部设置。用户为指定槽启用接管，预览管理器、有效端点、模型和允许切换的范围；保存私有授权。已存在的文件只产生候选，直到获得授权。受管字段在 UI 中展示来源和修订号；独立设置仍可编辑。 |
| 写文件／换模型 | 同一授权只选择一个写入方。写入方在同目录持固定文件锁，重读并核对预期修订，再写同目录临时文件、同步并原子替换。应用监听父目录以兼容 rename，合并重复通知，稳定读取整份候选，经解析和授权后原子发布不可变快照。修订单调递增；同版同内容幂等，同版异内容和旧版报冲突。单靠文件格式无法约束绕过锁的程序。 |
| 多窗口／休眠／漏事件 | 同一用户配置目录同时只有一个原生实例持有受管发送权，其他实例提示回到持有窗口。权威实例保存已接纳的修订与无秘密快照，发布递增的本地代次；窗口事件只发代次和状态。启动、唤醒、手动刷新及漏事件补查时重新核对，迟到的解析结果不得覆盖新代次。本地正常通知路径目标为稳定写入后 1 秒内新请求可见。 |
| 损坏、半写、文件消失或管理器退出 | 短暂竞争有界重读。保留最后有效快照及错误码，显示当前仍生效的修订；网关离线则该路由不可用。首次启动若没有可验证的已授权快照，受管槽暂停。错误、文件删除和网关退出均不能自动切到付费直连或新的数据目的地。 |
| 管理器正常解除／用户收回 | 已授权写入方提交更高修订和 `active: null`，按预告恢复该槽个人选择，仍允许以后在原授权内重启接管。用户点击“收回控制”则撤销授权、使旧文件失效并立即停止给旧授权签发新请求；再次接管由用户重新绑定。草稿以打开时的代次校验，过期时显示差异。 |
| 两个管理器竞争 | 不以文件时间、进程名或 `managerId` 自证身份。切换管理器由用户在设置中交接并创建新授权世代，保存不同文件内容指纹／修订的冲突摘要。若要抵抗同用户其他程序冒名写入，须另行配对并验证签名或受认证 IPC；普通文件模式的安全承诺仅限获准目的地和操作范围。 |

**请求边界。** 文本每次提交固定连接、模型、绑定、代次。流式响应持续到结束或取消；对话下一条用户消息可用新路由。助手同一轮的模型调用和工具往返固定同一快照，授权撤销时阻止后续外发；送达上游的字节无法撤回。切换期间排队但未出网的工作按提交时约定核对授权；失效即暂停并显示原因。显式选择的模型消失时保留选择并标记不可用，避免自动换成列表第一项。网关可在其内部动态分配上游，客户端只能固定网关、请求模型和路由组，实际账户和账单归属以网关可提供的回执为准。

**长任务边界。** 媒体阶段持久化无秘密的原路由身份、账户绑定、协议版本、远端任务 ID 和幂等／本地申请 ID；不持久化认证头、带签名下载 URL 或旧 Key。只向原作业授权的目标续查，轮换后的凭据须仍属于已绑定账户。网关若无法凭任务 ID 固定上游，标记该协议不支持异步接管。旧回执无法唯一定位时暂停并提示人工恢复；提交结果不明时禁止自动重投。第三方 CDN 单独下载，不能继承厂商 Authorization。

## 密钥的保护范围

1. **优先让网关持有厂商 Key。** Canvas 本机 Magpie 模式只用公开归属标记。网关能看到发给它的提示词、附件和工具结果，并可自行记录或选上游；首次授权应展示这个数据边界。回环和 `/api/hello` 都不能认证对端进程，本机恶意进程占用端口仍属风险。高敏场景应选经过认证的本地通道或可信 TLS 端点；首版不把公开标记当作机密或访问控制。
2. **直连凭据只在原生层使用。** 对受管连接新增独立命名空间，由 Rust 根据私有绑定注入认证，只接收操作枚举、模型及受校验业务输入。Renderer 获取就绪状态和安全摘要。既有通用 `secret_get` 也必须拒绝读取新命名空间；创建、轮换、撤销通过专用设置动作。禁止借用 MCP 令牌、其他厂商 Key、云存储密钥、登录 Cookie 或从子进程环境中枚举秘密。即使同一个服务域名托管多个租户也按 API 根和账户分别授权。
3. **区分本机落盘与运行时暴露。** Windows 候选为当前用户 DPAPI，macOS 为 Keychain，Linux 为 Secret Service。先验证签名构建、锁屏、无桌面密钥环与多实例行为。不可用时提供仅本次会话输入或使用外部网关。把现有本地直连也迁到同一保证范围，需要逐条改造所有消费者；仅加密文件仍会让原来的 Renderer 读到值。管理员、已控制当前会话的进程及用户授权的网关超出绝对保密保证。
4. **轮换与迁移可中断。** 按凭据逐条执行“读旧版本 → 写系统库 → 原生核对 → 条件提交引用 → 条件清理旧值”，使用原存储的锁与比较更新。崩溃可重入；中途失败保留已验证可用的一侧并提示，不写明文备份。回滚关闭新接管入口，保留可读的已迁移记录；旧客户端不能读新库时提示重新输入，不将密钥降级写回文件。旧备份可能已经含明文，若曾意外共享，需在厂商侧轮换。
5. **诊断按字段白名单输出。** 事件、控制台、崩溃报告、网络错误、项目导出、剪贴板和支持包只保留允许的状态、修订与错误码。禁传原文配置、HTTP 头体、任务签名和提示词；失败响应也可能回显秘密。真实网关令牌按凭据处理，绝不放入 URL、命令行、公开样例或项目。现有文件导入、插件、Agent、MCP 和通用网络桥均不新增秘密读取能力。

## 桌面验收与维护

前置条件为隔离的桌面用户数据、两个可区分的模拟路由 A／B、一份旧个人连接及唯一的假密钥标记。默认使用假响应。真实供应商、系统密钥库提示及管理器发行版另列平台验收。

| 操作 | 应看到的结果 |
|---|---|
| 应用关闭时写 A，启动；启用接管；两窗口打开设置，原子替换为 B | 授权前仍由用户管理；授权后窗口显示相同修订；下一次文本节点和新一轮助手走 B，进行中的 A 流正常结束。无需重启。 |
| 改协议、端口、路径前缀、账户或绑定名；返回跨源重定向；模拟上游在错误中回显假 Key | 未授权请求在发出前失败，第二目标收到零次带凭据请求，日志、事件、导出、支持包和错误提示均找不到标记。 |
| 文件半写、删除再创建、重复事件、旧修订、同版异内容、未知大版本、链接替换、休眠后恢复 | 不出现临时路由；显示最后已生效修订和错误原因。恢复合法新修订后只应用一次。两写入方冲突可以诊断。 |
| 编辑个人设置草稿时外部切换；正常解除、强制收回、重启并放回旧文件 | 草稿不能回写外部状态。正常解除回到有效个人设置；强制收回后仅放回旧文件不能重新接管。项目归档不携带管理器授权。 |
| 关网关、轮换／撤销测试 Key、锁定 OS 凭据库、迁移中断及磁盘写满 | 不中途更换账户、弹出可操作的恢复提示、不回落明文。原连接可按迁移阶段恢复，撤销后的新外发被拒绝。 |
| A 提交异步任务后切 B、重开，模拟 CDN 下载及无远端 ID 的超时 | 只查询原 A 的作业，最多一次付费提交，CDN 收不到 A 的认证。缺失身份时明确提示人工核对。 |
| 通过 Magpie／CC Switch 的目标发行版连接、切换、解除，再比对原配置 | 独立记录网关、流式、工具调用及一键适配结果。撤销只作用于应用授权槽；不能把某个协议成功推广为全应用已兼容。 |

可复用的回归入口包括 [连接分享](../../tests/services/providerConnectionTransfer.test.ts)、[凭据存储](../../tests/services/providerSecretService.test.ts)、[配置落盘](../../tests/services/configSecretStorage.test.ts)、[文本节点](../../tests/services/generateTextProtocol.test.ts)、[流式助手](../../tests/services/assistantStreamProtocol.test.ts)、[传输](../../tests/services/httpTransport.test.ts)和[任务恢复](../../tests/services/pollManager.test.ts)。新合同增加一组跨 Rust、前端和第三方写入器共用的有效／无效样例。每次变更协议、上游路由、凭据后端或回执版本时，登记测试平台、双方版本、通过项、失败项和回滚结果。大版本不兼容时并行读取旧合同，显式迁移；失效授权不得因降级复活。
