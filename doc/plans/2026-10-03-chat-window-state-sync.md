# 对话助手双窗口状态同步

日期：2026-10-03。范围：完善已有双窗口对话能力，主窗口 Store 继续作为唯一写入源。

## 行为变化

- 内嵌助手和独立窗口共用主窗口生成的文本模型分组、媒体模型目录及可用状态，包括厂商品牌、显示过滤和工作流模型；独立窗口不接收厂商凭据、连接地址或工作流正文。
- 当前会话、消息、任务、审批及模式继续由既有快照与补丁同步。切换展示方式不创建、重启或中止执行任务，执行期间的消息和任务状态继续更新。
- 未发送草稿按会话保存在运行期 Store；延迟输入携带原会话 ID，关窗和收回时携带最后一次编辑。主窗口草稿立即保存，独立窗口合并输入后发送 IPC。
- 会话列表、对话和任务中心视图纳入共享状态。新窗口首帧与收回内嵌均恢复对应视图和草稿，包括清空后的输入框。
- 独立窗口忽略旧版本快照；补丁缺少前帧时请求完整快照。切换期间尚未完成的发送不能提交旧同步状态；握手超时继续等待真实状态，不显示空会话假象。

## 源码与边界

- `src/store/store.chat.ts`、`src/types/chat.ts`：会话草稿和当前视图；不新增持久化格式。
- `src/services/chat/chatWindowService.ts`：模型、草稿和视图字段，输入会话绑定与最终编辑交接，接收版本检查。
- `src/services/chat/detachedChatSyncController.ts`：统一目录、操作路由及发送期间的切换保护。
- `src/components/chat/ChatPanel.tsx`、`ChatInput.tsx`、`ChatWindow.tsx`：消费共享状态、保留尚未确认的本地输入、关窗交接和初始化等待。
- 不新增依赖、不修改 Rust 或窗口权限。运行期草稿不保证应用重启后恢复；窗口尺寸、弹出菜单等窗口自身状态不作为共享对话状态。

## 2026-10-12 打开失败补丁

- 吉祥物、侧栏与助手标题栏统一经 `chatWindowLifecycle.ts` 打开；同一时间只提交一次原生命令。失败恢复内嵌助手，保留会话、草稿与当前视图，并展示有界、脱敏的原生错误。
- `lib.rs` 对打开/关闭串行处理；存在助手窗口时恢复、显示并聚焦，保留窗口和同步状态。关闭等待标签释放后才允许重开，不再关闭后立即同名重建。
- `native_rendering.rs` 的性能参数仅经进程环境应用，保留 Wry 默认 EnvironmentOptions。此前仅主窗口覆盖 `additionalBrowserArgs` 会使共享 profile 的窗口参数不一致；[WebView2 文档](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/webview2-idl?view=webview2-1.0.2420.47#CreateCoreWebView2EnvironmentWithOptions) 说明这种情况会导致 `ERROR_INVALID_STATE`。需完整重启应用。
- 已通过：窗口生命周期/监听/同步 3 个 Vitest 文件共 21 项，定向 ESLint、测试类型检查、`cargo check --lib`、`cargo test --lib --no-default-features native_rendering::tests` 共 4 项。未进行原生双窗口实机验收；截图只提供通用失败提示，不能据此断言实际命中了哪条路径。

桌面验收：分别关闭/开启性能模式并完整重启，双击吉祥物首次打开；输入草稿后重复双击，应只聚焦同一窗口；最小化后重开应恢复；快速收回/重开、关闭后重开应成功并保留草稿。标题栏、侧栏与吉祥物三入口均检查。若仍失败，记录新提示里的具体错误；内嵌助手应仍可使用。原有任务、审批、模型目录与跨会话草稿同步作为回归项。

## 2026-11-11 重复展示与关闭交接修复

状态：已实现并补充回归源码，本次未运行测试、类型检查、lint、构建、Rust 检查或桌面交互验收。上方历史检查不作为本轮证据。包含 Rust 命令修改，需重新编译并启动桌面端，不能只热更新前端。

- `openChatWithDraft` 不再直接撤销独立状态：分镜优化、剧本浏览等共享入口先等待草稿交接与真实销毁，再打开内嵌助手。同一交接只保留最后一次请求；等待期间项目、会话、画布版本、导航上下文或窗口实例变化时取消注入，保留原会话草稿。工作台创作和 MCP 用户选择沿已有独立偏好重开／聚焦窗口，展示失败保留原任务及选择等待，不另开内嵌助手。
- `finishChatWindowClose` 按 session 合并原生关闭，销毁成功后才结束会话；在途打开先等结果再核对真实窗口，不能把尚未创建的标签当作已关闭。交接中输入只读并显示进度，失败恢复编辑、保留授权及草稿并允许重试。旧会话草稿与窗口生命周期分别核验：只接受同 session 曾发布的来源、原会话归属与未被替换的草稿；运行期删除标记阻止软删除尚未落盘时的旧交接复写。发送成功后拒绝用旧基线恢复已发送正文，发送后的新编辑仍可保存。普通任务和写操作继续要求当前帧，跨项目的无会话草稿不能填入当前输入框。
- 原生打开／关闭仅接受本地主窗口；复用要求真实 URL 的唯一 `session` 和 `view=chat` 绑定匹配。已声明仅复用却已不存在的窗口不能用旧 nonce 重建；旧关闭请求不得销毁新实例。关闭使用宿主 `destroy` 并等待标签释放，避免依赖子 Renderer 再次处理 `close`。仅本次新建窗口的显示／聚焦失败才清理该句柄，复用失败保留已有窗口。
- 截图 CSP 来源静态对应 SDK 的 Zod 空 `Function` 探测，异常本已捕获，不能据此断言是卡关闭根因。`mcpSdkCsp.ts` 先于 SDK schema 初始化配置 `jitless`，保持解释式协议校验；不修改依赖版本、CSP 或原有远端 schema 策略。
