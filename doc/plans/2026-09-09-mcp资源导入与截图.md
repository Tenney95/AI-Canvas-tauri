# MCP 资源导入与截图

状态：实现和定向验证完成；原生图片链路通过解码单测，当前系统剪贴板实测为文本。

## 范围与行为

用户在宣传片制作中遇到逐张鼠标导图效率低的问题，授权补齐本地资源导入、剪贴板入口，并补充实测缺失的截图能力。

| 工具 | 输入 | 结果 |
|---|---|---|
| `file_import_media_to_canvas` | `files: [{path, label?, x?, y?}]`，可选起始 `x/y` | 同序节点 ID、类型、坐标、revision |
| `canvas_paste_external` | 可选 `x/y` | 系统图片/纯文本对应的素材节点 |
| `ui_capture_to_canvas` | 可选 `maxWidth/x/y/label` | 主窗口真实界面截图对应的图片节点 |

只使用已有文件服务、Store Action 和 Policy；无新依赖，无数据库迁移，不修改 `tauri.conf.json`。原生 `read_canvas_clipboard` 登记应用命令权限并在执行时限定可信主窗口；不授予插件读取权限，不改变任何本地目录授权。

资源先准备后提交，整批只记录一次历史。取消、项目切换、revision 或节点/连线/分组变化会阻止回填。复制发生在提交前，失败可能留下项目内的未引用素材，保留给现有存储管理，不自动删除源文件或半成品。

## 验证

- 应用类型、测试类型、改动文件 ESLint 通过；严格 UTF-8 与差异空白检查通过。
- 7 个定向 Vitest 入口（运行器展开 12 个测试文件）共 113 项通过，覆盖批量原子提交、路径/格式输入、错误脱敏、取消、项目/revision/交互状态变化、系统图片与文本、原生路由、截图入画布、截图文本节点与敏感元素过滤、Registry、Policy、目录发现及现有剪贴板服务。
- `cargo check --lib` 通过。`cargo test --lib --no-default-features clipboard_read::tests` 两项通过，覆盖主窗口限定、UTF-16 编码/长度及 PNG/DIB 解码。默认特性 Rust 单测在链接 ONNX 时被本机旧 MSVC 的 LNK2019/LNK1120 阻断，不能视为默认特性单测通过。
- 扩展文件下载测试有一项既有断言失败：基线 `fetch(url, {signal})` 与仅断言一个参数的测试不一致；本次未修改该下载实现或断言。
- 实机 MCP：发现三个新工具；一次导入两张已授权截图；一次撤销移除整批、重做恢复；素材节点成功连接 H3 视频节点。未授权的新截图读取被拒绝，整批无节点写入。
- 实机 MCP：Windows 原生剪贴板文本直接入画布；修复后的只读截图返回真实图像；主窗口截图直接入画布后成功连线。实测无需文件选择框或模拟键盘粘贴。

## 剩余边界

- 新目录仍需要通过现有应用设置、文件选择或拖入获得一次授权；MCP 路径参数不是授权。
- Windows 系统位图实机粘贴、其他平台剪贴板、归档往返和默认 ONNX 特性完整链接不在已通过的实机验收内。
- Webview 截图是当前应用渲染内容，不包含其他软件或系统对话框；敏感元素过滤按现有标记工作，不承诺识别所有业务文本中的秘密。

## 回滚

撤销本批工具、资源服务、剪贴板原生命令注册与权限条目，保留原有手动上传/粘贴入口。移除新节点可使用画布撤销；已经保存的项目媒体仍能由原有素材节点读取。无需迁移或删除用户项目。
