# 大画布交互性能优化

主模块：[画布与项目](../画布与项目模块.md)。前六批为性能修复，第七批为已确认的节点渲染分层收敛。

## 第一批范围与状态

已完成连接按钮集中缩放补偿和图片节点分档预览，并通过自动化与隔离浏览器验证。保留完整 Store 图、React Flow 可见元素渲染、交互暂停标记、节点尺寸、连线和历史语义。

- `Canvas.tsx` 集中更新连接按钮的 CSS 缩放补偿；`GooeyBtn.tsx` 不再逐实例订阅原始 zoom。
- `CanvasPreviewImage.tsx` 根据节点屏幕尺寸和设备像素比选择 256/512/1024 像素预览，超过最大档时使用原图；微小缩放与纯平移不改变尺寸档。
- `canvasImagePreviewCache.ts` 按完整来源（包含外部文件刷新版本）和尺寸档共享派生。每次仅处理一张图片，交互时暂停启动后续处理；请求超过 10 秒向消费者回退原图。不可取消的位图解码/编码仍等待结束并释放资源，避免超时导致并发堆积。
- 在用预览由租约保护，内存空闲项按估算 RGBA 内存 32 MiB、128 项、30 秒限制回收。取消排队任务、切换来源、高清原图档和卸载都会释放相应租约，位图关闭、画布清理及 object URL 回收有独立回归。第二批已在此基础上增加项目磁盘层。
- 动图、未知格式、读取或派生失败继续使用原图；源图编码读取上限 32 MiB，派生前复用既有尺寸与解码预算。远程 CORS 不可读时不增加原生下载路径。

## 行为边界

画布缩略图不得写入 `imageUrl`、`thumbnailUrl`、Store、IndexedDB 或历史。全屏、编辑器、复制和生成引用仍读取原图；原始宽高及标注坐标不改变。已有 `thumbnailUrl` 经常是原图别名，本批不改变其持久化含义。

缩放换档时保留正在显示的旧预览，直到新结果就绪；来源改变后旧结果不得显示。进入原图档时卸载缩略图持有者，使旧资源进入空闲缓存。缓存限制不包含当前仍在画布使用的缩略图，不能将空闲缓存上限描述为应用总内存上限。

## 第二批：项目磁盘缩略图

用户已授权完善两级缓存，并明确 Windows、macOS、Linux 统一使用项目目录下的 `.thumbnail`。本批类型为产品能力完善，不修改节点数据结构、数据库版本或 Tauri 安全配置。

- 查找顺序为内存、项目磁盘、原图派生。磁盘命中只读取经过校验的小图，不读取/缩放解码原图；首次缺失时立即展示生成的内存预览，由后台单写队列持久化。队列最多 64 项且编码 Blob 总计 8 MiB，另有一个至多 4 MiB 的在途写；超出时跳过可重建的磁盘副本，避免拖住画布。
- `.thumbnail` 位于现有项目媒体数据目录，分集复用剧集目录。Windows 额外设置 Hidden，macOS/Linux 依靠点目录隐藏；来自其他平台的缓存在 Windows 首次命中时也补隐藏属性。
- 原生缓存覆盖已落盘、实际显示源位于该项目内的静态图片。远程地址、data/blob、项目外图片和不支持的格式继续使用原有内存/原图路径，不擅自下载或搬移源文件。
- 每个相对源路径与尺寸档对应一个 `v1-<摘要>.cache` 文件，内部保存源版本、宽高、缩略图字节和 SHA-256 完整性校验；文件名不依赖项目绝对目录。源版本依据文件大小与修改时间纳秒，读取后和原子替换前复核；保留大小与时间戳的人为文件替换不在此失效检测范围内。
- 只接受 256/512/1024 档和至多 4 MiB 的 PNG/WebP 派生结果，原生限制尺寸及解码内存。损坏、缺失或手工删除缓存目录后按需重建；同一原图更新会原子替换该档缓存，保留目录中其他文件。缓存不是原图或备份，不进入节点、历史或 IndexedDB。
- `ImageNode` 只新增当前项目 ID 的标量订阅。组件换项目时取消旧请求；缓存 key 包含项目范围，原生读写捕获实际项目目录和源版本，不使用异步结束时的当前项目。不会触发资产变更通知或自动保存。
- `prepare_project_thumbnail` / `write_project_thumbnail` 仅主窗口可调用，复用真实路径授权并限制源文件属于项目目录，拒绝缓存后代中的符号链接与 Windows 重解析点。精确注册两条命令，没有新增依赖、通用路径入口或放宽权限。
- 项目素材遍历在进入根 `.thumbnail` 前排除缓存，避免污染索引或消耗文件数量上限；项目占用/孤儿/重复文件扫描和导出同样排除。分组、回收站和外部登记目录中的同名用户目录仍按原语义处理；项目改名保留缓存，导入和项目复制首次显示时重建。
- 引用图片 watcher 同样过滤真实项目根 `.thumbnail` 本身及后代事件，避免缓存创建引发整批原图刷新；只在 watcher 重建时解析项目目录，切换项目时更新过滤范围并清理过时注册，继续支持外部工具原子替换保存。

新增验证入口：`tests/services/thumbnailCache.test.ts`、`tests/services/projectThumbnailExclusion.test.ts`、`tests/services/storageServiceProjectLoad.test.ts`、`thumbnail_cache::tests` 和 `project_archive::tests`；原内存缓存与组件回归覆盖磁盘命中、项目隔离、取消和后台写不阻塞显示。

第二批验证结果：前端 14 个定向测试文件合计 180 项通过，产品/测试 TypeScript 与 18 文件定向 ESLint 通过；缓存 watcher 修复后的相关组件再次回归通过。隔离真实浏览器复跑通过，6 个 object URL 和 7 个 ImageBitmap 全部释放，无页面错误。Rust 缩略图 6 项及归档 3 项测试使用 `--offline --locked --no-default-features` 通过，默认特性 `cargo check --offline --locked --lib` 通过；本机默认特性测试链接被既有 ONNX/VS2019 的 LNK1120（39 个符号）阻断，未改动依赖。Windows Hidden、同大小原图修改、损坏/删除后重建、项目目录移动已做原生文件测试；macOS/Linux 尚未实机运行，用户大项目 Tauri 帧率仍待采样。本批未打包。

## 第三批：降低节点常驻开销

用户已确认继续优化。本批按一次性性能修复实施，保留完整 Store 图、React Flow 节点和连线、历史、编辑器及项目持久化语义。

- 图片、文本、音频、全景和视频节点使用 `NodeToolbarShell`：工具条首次可见时才挂载，首次打开后隐藏时保留子树，避免丢失未保存输入和弹窗；沿用 React Flow 节点出视口卸载。未使用工具条不创建按钮、图标或订阅插件列表。
- 视频待机显示静态封面，单选或显式播放、截帧等操作才挂载播放器；多选不会批量加载视频。正在播放的节点保活，暂停且不再单选时释放，重新启用恢复播放位置、音量和静音。全屏与紧凑播放器互斥，关闭后保持打开前的播放/暂停状态。
- 新增共享视频封面队列，单次只处理一个来源；画布交互期间暂停启动后续任务。封面最长边 640 像素，来源相同复用，取消、超时和卸载释放解码器。空闲缓存按估算 RGBA 32 MiB、64 项、30 秒回收，在用租约受保护；不可取消的编码仍等待结束，避免超时后不断叠加任务。
- 视频封面目前仅内存缓存，项目 `.thumbnail` 磁盘层仍覆盖静态图片。派生失败暂显示占位，显式播放继续使用视频源；有效独立封面直接显示，视频 URL 别名不当作封面。缓存不写入节点或历史，尺寸派生回写检查项目、revision 和来源。
- 截帧和反推等待视频像素就绪，任务取消追踪覆盖完整取帧流程；切源、项目切换或播放器卸载后丢弃旧结果并抑制迟到报错。上传新视频清除旧封面和远程出处，防止新内容一直显示旧封面。
- `HistoryTimelinePanel` 收起或隐藏时不订阅实时节点/边/分组，也不计算历史条目差异；打开时按当前状态恢复。锁定检查与插件工具条节点类型查询复用既有完整节点索引，避免每个节点各自线性扫描整图。

## 第四批：普通滚轮细步短过渡缩放

针对用户反馈的 54 张图片、16 个视频场景及滚轮步幅过大，增加 `useCanvasWheelZoom.ts`，由 `Canvas.tsx` 接入；本批不修改媒体数据或缓存格式。

- 默认模式的普通滚轮归一化为细步缩放，标准 120 单位输入放大 8%，缩小按其倒数；同一帧输入合并，由单个 RAF 驱动 60 ms 短过渡，首个渲染帧开始变化。鼠标下的画布坐标保持不动，沿用 0.1～5 倍范围；反向滚动从当前显示位置掉头，不继续追赶旧目标。
- 独立 `wheel` 交互状态覆盖待提交输入和短过渡，过渡结束立即释放，没有额外尾部等待；已有浮动输入框仍按原流程更新锚点。媒体派生延续既有单任务队列与交互暂停，系统开启减少动态效果时跳过插值，保留同样的缩放步幅。
- 指针按下、页面失焦/隐藏、切项目或交互模式改变会取消尚未完成的滚轮过渡；统一视口服务、适应画布和浮层自动平移在接管前主动取消旧过渡，避免覆盖新导航目标。
- `nowheel`、工具条/面板、输入框和富文本编辑区保留自身滚动；传统模式普通滚轮平移、Mac 桌面双指平移，以及 Ctrl 捏合等原生手势保持现有处理。实现使用公开视口 API；`panOnScrollSpeed` 只控制平移，不能用于缩放灵敏度，参见 [React Flow 交互属性](https://reactflow.dev/api-reference/react-flow#interaction-props)。

验证：7 文件 96 项定向测试通过，产品/测试 TypeScript、3 文件 ESLint、严格 UTF-8 和差异检查通过。Hook 测试验证首帧变化、60 ms 到达目标、立即释放交互状态、反向响应及减少动态效果。真实 Windows Edge 使用完整生产 Canvas、节点组件、MiniMap 和隔离 Store，构造 54 张图片及 16 个视频；对照原滚轮，标准一格放大由约 18.1% 降至 8%，观察到中间过渡且到位后不再追加视口变化，鼠标锚点保持，真实鼠标事件未与原缩放叠加。缩放期间未启动新图片派生，输入框滚动、传统模式平移、自动定位接管和切项目取消通过，无页面错误。

此验证为合成媒体和视口行为检查，不代表用户项目帧率，亦未覆盖实际 Tauri、Mac/Linux 输入硬件或在线图标加载。本批未打包；回滚仅撤销新 Hook、Canvas 接入及对应测试，前三批优化保持可用。

## 第五批：输入响应与每帧附带开销

滚轮时钟、小地图重复处理及控件补偿的逐帧根样式广播已修复；标准 8% 作为灵敏度基准，保留末次输入后 60 ms 收敛和原有跨平台交互方式。

- 滚轮改为对数空间指数追随：收到同向输入时先按旧目标推进到真实输入时刻，再接收新目标；RAF 只负责显示。新输入不重置已累积的时间，事件不直接写视口，每帧至多提交一次，状态大小不随输入数量增长。反向从实际显示倍率重新开始，取消后仍让新导航接管。
- 倍率连续计算，不取整到固定档位；保留小于一格的增量，也不把浏览器合并后的大增量截断成单格。相同总输入以一次或多次事件到达时具有相同目标倍率，最终仍受 0.1～5 倍范围约束。
- 受控时间线复现原实现的延迟：10 次细输入累计目标为 8%，事件在每帧前 1 ms 到达时，第 10 帧仅显示约 1.82% 增幅；修复后约 6.82%，余量在短收尾中完成。同一输入时间线按 60 Hz 和 120 Hz 显示时，共同采样点的倍率与位置一致；不是为不同设备叠加另一套灵敏度。
- 小地图缓存 SVG 屏幕宽度，仅连接或 resize 时测量；自身圆角路径写回不会再次计算，已有遮罩仍连接时跳过无关 DOM 变动造成的全局查询。连续 100 次视口路径变化的定向测试中，尺寸测量与查询各仅一次，仍覆盖窗口 resize、隐藏重显、替换和卸载。
- 缩放中的工具条与连接按钮只在控件自身设置局部补偿，避免继承变量使整张媒体卡片重新计算样式；本轮已触达的淡出控件继续跟踪，断连控件释放。仅交互期间监听相关挂载、选中状态及 hover，覆盖新显示控件，不读取布局或监听自身样式写入。最后一个交互来源释放时，先向根发布最终值，再清理局部覆盖；普通平移跳过逐帧查询与补偿写入。

## Mac 通用鼠标滚轮与 Windows 默认模式统一

状态：方案及 Mac 依赖已获批准，源码实现与下述本地检查完成；完整 Mac 构建及硬件验收未完成。本问题保持 `ITERABLE`，范围仅限本次修复及验收，实机通过后恢复 `LOCKED`。类型为一次性修复，主归属画布交互，涉及 Mac 原生输入适配。

目标：默认/Figma 模式下，Mac 普通实体滚轮鼠标直接缩放，无须按 Ctrl，复用现有连续倍率、8% 标准输入基准、60ms 收敛及鼠标锚点算法。触摸板双指平移、惯性滚动和捏合保留现有路径；经典模式仍保留滚轮平移与 Ctrl+滚轮缩放。

### 已确认事实与方案

- `Canvas.tsx` 将 Mac 桌面统一设置为 `panOnScroll: true`，并关闭该平台的 `useCanvasWheelZoom`；这同时影响普通鼠标，导致两平台默认模式的操作和缩放响应不同。
- WebKit 的 DOM 滚轮接口没有原生连续滚动及手势阶段字段，鼠标和触摸板都可能产生像素单位滚动。按步幅、整数或频率推断设备存在误判，不能保证触摸板快速滑动保持原行为。依据：[DOM WheelEvent 接口](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/dom/WheelEvent.idl)、[Mac 原生滚轮转换](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/Shared/mac/WebEventFactory.mm)。
- 已增加应用内 Tauri 输入插件，仅在 Mac 主画布窗口处理系统明确标记为非连续、且无手势/惯性阶段的普通滚轮。连续、带修饰键或鼠标按键、水平/混合轴及来源不明确的输入原样交给 WebKit；不监听其他应用。持续触摸板输入不逐帧派发桥接脚本，仅从鼠标缩放切换到其他交互时取消旧缩放。
- 原生鼠标输入交给当前画布的滚轮处理器，复用现有排除区域、模式、倍率与取消逻辑。前端确认消费后不再交给 React Flow 原始处理；未消费的事件按顺序交回 AppKit，并用原事件指针阻止重复捕获。未决事件有界，重复/过期回执被忽略；失焦、按键、拖动、手势接管与关闭清理旧事件，切项目后的迟到输入不写入新项目。跨原生与前端的完整时序仍需 Mac 实机验收。
- 部分第三方平滑滚动驱动会把普通鼠标转换为连续事件；该情况保留旧路径，不能声称覆盖。当前 Windows 工作环境无法替代 Mac 硬件与 WKWebView 实测。
