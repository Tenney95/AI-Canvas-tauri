# 快捷指令文件夹与紧凑二级菜单

状态：已实现，待用户验收。已补充回归用例；本次未运行自动化测试、类型检查、lint、构建或桌面交互验收。

## 行为与边界

- 文本、图片、视频、音频快捷指令各自支持一层逻辑文件夹，管理器在「新建」下方提供「新建文件夹」。支持改名、移除和通过详情页选择指令所属文件夹。
- 管理器的无分类指令直接显示，只有用户创建的文件夹显示文件夹行，不自动增加「未分组」文件夹。
- `/` 菜单一级显示「快捷指令」及指令总数，直接打开二级列表。无分类指令直接列出，自建文件夹以二级列表内的分区标题显示，不增加第三层菜单。子项显示名称和执行方式，说明保留在悬浮提示；空的自建文件夹保留分区，没有当前类型的指令与文件夹时隐藏入口。
- 同类型同名文件夹、空名、保留名「未分组」和超过 80 字符的名称被拒绝；不同类型可同名。改名保留 ID；删除分类不删除指令、模板、模型覆盖或高级配置。
- 文件夹集合使用 IndexedDB v22 的既有 `metadata` 记录 `preset-folders`；指令新增可选 `folderId`，无需数据库升级。失效和跨类型关联回到未分组。
- 保存与分类移除通过同一 Store 队列串行执行；删除分类在一个 IndexedDB 事务中解除所有关联。事务失败保留原数据，写入成功后才更新内存。移除分类不清空正在编辑的其他字段，保存失败保留草稿。
- 本次解决的是菜单名称和说明拥挤，不修改提示词填充、追加、直接生成或高级顺序执行逻辑；工具栏仍通过原指令 ID 引用。文件夹不对应磁盘目录。
- 复用已有 `ui-*` 控件、菜单结构及主题 token，不新增 UI Kit 样式或依赖。

## 桌面验收

前置条件：使用 Tauri 桌面端，准备旧的未分组指令、基础直接触发/加入提示词指令及高级顺序指令。以下步骤需用户验收，不能以结构用例代替桌面交互。

1. 打开快捷指令管理器，在未创建文件夹的图片标签中应直接看到旧指令，不出现「未分组」文件夹行。新建「人物」文件夹，再在文件夹内新建指令；编辑名称、说明与模板后保存。将已有指令通过「所属文件夹」归入其中；应保留选中指令，保存后列表分类和数量同步更新，无分类指令仍直接列出。
2. 在图片节点提示词栏打开 `/`，一级显示「快捷指令」与总数。鼠标悬浮或点击该入口，二级直接显示指令，不出现「未分组」菜单；自建「人物」文件夹作为二级列表内的分区标题，子项单行显示名称与执行方式，长名截断，悬浮可查看说明。方向键右移可进入二级、左移返回，Esc 和外部点击关闭。未创建文件夹时同样直接打开二级指令列表。
3. 执行直接触发、加入提示词和高级顺序指令，核对与旧版一致的模板填充、模型/尺寸覆盖及顺序执行入口；已有工具栏指令继续可用。不要为验收分类主动发起付费调用，可在实际生成前取消。
4. 创建空文件夹、改名并重启；空文件夹和名字应保留，旧的无分类指令仍直接显示。文本/图片/视频/音频标签之间分类独立，允许不同类型同名，拒绝同类型重复、空白和保留名。
5. 编辑某指令的未保存名称和模板，再移除它的文件夹；应只改变分类，草稿保留，原指令回到直接显示的无分类列表，不额外创建文件夹。保存并重启后，指令与模板仍存在，分类已清除。
6. 对保存与删除制造存储失败（使用专用测试环境，避免损伤真实数据），应显示失败且原分类、指令和编辑草稿保留；恢复后可重试。检查先保存后移除、先移除后提交旧草稿两种顺序均不会恢复已删除分类。
7. 分别检查深浅主题、长名称、大量指令、靠近窗口边缘的菜单、滚动列表及键盘操作；二级菜单应留在可见区域并可滚动，内置指令与 Skill 菜单维持原行为。
