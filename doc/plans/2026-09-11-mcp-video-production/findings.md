# 实施发现

- 创建项目、截图与导入均已注册，不需新建替代路径。
- 工具描述与 app_get_state 在上一轮均返回任务已取消；当前通用错误将信号中止、任务缺失和任务终态混在一起，需先确认触发分支。
- 现有 videoEditorService 负责工程与节点/镜头表映射，videoEditorMediaService 已有合成导出与批量抽帧。独立编辑器自行持久化工程，MCP 写入必须防止覆盖正在编辑的窗口。
- canvas_query 不返回媒体路径；新增验片工具应以节点 ID 定位并直接返回瞬时 MCP 图片与脱敏参数。
- 动态 ComfyUI 校验绑定单 taskId，与每个 MCP 请求新建任务不匹配；已导入的 ComfyUI 工作流是另一条可复用执行链。

## 当前确认结果

- 开发版的业务 MCP 曾恢复并完成项目创建、真实界面截图、剪辑创建、后台合成、保存、回填和抽帧；不能将所有历史失败归为业务工具缺失。
- 后续故障明确落在任务记录缺失分支。开发热更新存在静态监听器与动态执行模块可能持有不同 Store 的缺口；现补丁在模块首次载入即保留 Store，刷新 action 时仍绑定原实例。测试覆盖该缺口；最终重新载入后，真实 MCP 描述与应用状态查询成功。没有把此前失败的重开或单测当作实机恢复证据。
- 真片探测：3 秒、1920×1080、AVC、可解码、无音轨；请求 0、1.5、2.9 秒均返回对应实际时间，样本持续时间为 1/30 秒。这是接口验收素材，不是正式宣传片。
- 新增工程使用独立 ID，避免覆盖已有人工工程。更新在同一 IDB 事务中比较完整快照；人工保存保留自动化版本，拒绝旧窗口覆盖已更新工程。
- 导出复用 WebCodecs/mediabunny 合成与现有文件授权。项目或来源变化会阻止回填；如写盘完成后才变化，明确返回已保存但未添加节点，不擅自删除文件。
