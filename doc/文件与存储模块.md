## 节点正文落盘与分组归档

`nodeTextFilePersistence.ts` 接入既有 `syncGroupFiles`：桌面端自动保存及项目首次打开时，为没有文件引用、已有非空正文且未在生成中的 `ai-text`、`source-text`、`ai-markdown` 补建 UTF-8 `.txt`／`.md` 文件，回填真实文件身份，再按原分组迁移日志归档。覆盖历史 MCP 创建的纯正文节点，不依赖打开编辑器或重新导入；同名分配新名称，不覆盖已有文件。异步写入后复核项目、revision、节点正文和文件关联，过期结果不回写。

MCP `canvas_update_nodes` 更新已有文本文件时，先整批读取真实磁盘基线，再一次提交画布草稿，并通过既有 `saveAssetTextFile` 摘要校验逐文件保存。磁盘已是新正文则跳过；与原节点正文不符、读取失败或部分写入失败时保留草稿并明确返回未完成及各节点状态，不自动重试、不承诺跨文件原子提交。手工 Markdown 编辑继续使用原保存队列及冲突保护。

分组归档按节点已绑定的项目内普通路径处理，允许已入组的 `images/EP000/...` 等多层素材迁入分组目录；未分组的深层素材保持原目录，不遍历或扁平化整库。隐藏、私有、穿越和链接路径继续拒绝；迁移仍先复制、提交引用日志并保存项目，再清理旧文件，共享引用按原所有者拆分，失败保留原文件。

## 项目云存储与资产同步

「设置 → 存储 → 项目云同步 · S3 连接」管理 HTTP／HTTPS Endpoint、Region、Bucket、根前缀、寻址方式及专用凭据。「资源库 → 项目文件／创作资产 → 项目共享」创建／加入 `libraryId/sharedProjectId` 共享项目并校验存储能力；「立即同步」先预览上传、下载和冲突，再显式应用。分集沿用整部剧 owner；全局资产和外部目录不纳入。P1 为手动同步，自动监听及删除传播仍未启用。

- 统一业务入口是 `services/fs/sharedAssetSync.ts` 的 `projectAssetSyncService`：预览、应用、读取恢复状态及当前文件视图。界面通过 `store.assetSync.ts` 发起操作，通用文件扫描不反向依赖云调度器。`sharedAssetSyncFormat.ts`、`indexedDb/sharedAssetSyncRepository.ts` 和 `fs/sharedAssetStorage.ts` 分别负责内部格式、事务和固定 IPC；Rust `files/object_storage/` 负责实际 S3 传输。后续自动触发复用此入口，不往节点分散加云请求。
- 原生命令仅主窗口可调用，并再次校验真实调用方、绑定与受管路径。支持用户显式填写的 HTTP 或 HTTPS Endpoint；HTTP 为明文传输，适用于可信网络中的自建 RustFS／MinIO。HTTPS 保留证书验证且不自动降级，两种协议都禁止重定向。HTTP 兼容已补前端与原生回归用例，本次未运行测试，待桌面能力探测及实际上传／恢复验收。Endpoint 填服务根地址；虚拟主机模式由原生添加 Bucket 子域名，IP 地址只支持 Path-style。
- 非敏感连接、项目绑定和能力版本存原生独立 catalog，不进入普通项目导出。AK/SK/SessionToken 仅经原生专用命令保存；`object-storage/` 域禁止通用凭据接口访问。前端不回读明文。名称修改保留凭据；连接目标变化不继承原目标凭据，旧能力立即失效。P1 新增映射、待办和冲突三张表，当前 IndexedDB 为 v27；保留已升级客户端的兼容字段和索引，不降版本，保留项目、配置、映射及未完成队列。凭据和运行控制器不进入这些表。
- catalog 用文件锁、原子替换、单调版本及 owner 代数保护；远端等待结束后在同一锁内复核连接、绑定和取消状态。Store 拒绝旧版本快照；切项目加载、换连接时取消旧任务。关闭项目共享弹窗只取消页面自己的能力探测／绑定请求，已启动的资产同步由 Store 在应用运行期间继续持有；重新打开保留进度、结果和待确认预览，不重复发起活动同步。暂停按钮仍显式取消传输，项目、连接、目录或源资产变化仍沿用原守卫；退出应用后的未完成操作须手动恢复核对，不作为独立后台服务。绑定和解绑均复核共享项目身份；已删除项目的孤立本机绑定可在设置清理，且必须先完成本机项目目录加载。清理、解绑或删连接均不删除远端资产或本地媒体。
- S3 客户端禁重定向、禁自动重试，HTTPS 验证 TLS，只使用显式保存的凭据；能力请求响应有体积和超时限制。条件写要验证竞争者恰有一方成功及最终内容，清理失败会显示未清理状态，不静默退化为覆盖。探测仅创建应用小对象和必要项目描述，不上传本机资产。真实部署通过探测仍不等于完整同步或跨平台验收通过。
- 凭据与 catalog 是两份受保护文件，不是跨文件事务。若凭据先写入而 catalog 落盘失败，连接 revision／目标摘要不匹配会阻止使用，可能需要重新填写或重试；不得宣称已完整保存或自动恢复。

## 关键边界

浏览器降级文件选择由 `fs/core.ts` 的 `browserOpenFile()` 统一处理 change/cancel/focus 的一次性收尾，普通上传与 Skill 上传共用；各调用方仍保留类型、大小与编码校验，Tauri 对话框和原生路径权限沿用原规则。画布菜单文本读取与异步导入的边界见[画布与项目模块](./画布与项目模块.md#画布文件导入)。

- 素材使用位置按文件稳定身份、精确路径和真实 @ 协议查询持久化项目/剧集、全局创作卡片、历史和对话，并叠加当前画布；删除前复核影响，读取失败不视为无引用。失效文件与外部目录可预览并显式重连：有旧内容摘要则严格比较，无摘要旧记录只标元数据匹配并逐项确认；同名、歧义、权限失败或身份冲突不自动替换。托管素材仍复制到对应项目/全局受管目录，索引与引用由同一媒体迁移事务提交，旧位置保留迟到保存保护，原生路径授权不扩宽。入口、范围与待验收步骤见[使用位置与失效修复](./plans/2026-10-24-asset-usage-repair.md)，本次未运行测试，待 Tauri 桌面验收。

- 资源库的「ComfyUI 角色」是 ComfyUI RefMod 的独立目录，`config.comfyRefmodAssets` 只保存服务指纹、加载格式、精确相对文件名与显示元数据；不扩展普通文件类别、不复制模型、不保存插件返回的绝对路径。只读目录结果用于在线可用性，离线缓存只供展示，不能冒充文件仍存在；普通资产文件扫描仅在文件页运行。源码为 `assets/RefModAssetsPanel.tsx`、`assets/ComfyRefmodPicker.tsx` 和 `comfyRefmodService.ts`；生成、角色关联、验收及回滚见 [RefMod 接入计划](./plans/2026-10-22-comfyui-refmod-library.md)。本次未运行测试，待用户验收。

- 系统文件拖放统一经 `utils/nativeDropPosition.ts` 换算 DOM 落点：当前锁定 Wry 0.55.1 的 macOS 实现返回 AppKit 逻辑点，不再次除以 Retina 倍率；Windows/Linux 沿用物理像素换算。工作流导入、插件安装、资产目录接收和画布落点共用此入口，窗口物理坐标 API 不适用这一规则。图片合成器同时接收目标 WebView 与窗口通道，重复 drop 只导入一次，关闭后释放监听并恢复原有拖放占用。升级 Wry 时须重新核对平台坐标契约。已补充坐标、工作流、插件和画布回归用例；本次未运行测试，待用户验收。
- 项目生成、粘贴、复制与节点改名使用普通文件名，不追加随机哈希；同名按 `名称_1.ext`、`名称_2.ext` 递增，已带序号的冲突继续递增，相同扩展名不重复追加。Windows 保留设备名加前导下划线，复制结果返回实际磁盘文件名。会话内已分配的输出路径与迁移日志旧路径仍视为占用，防止并发写入与迟到保存关联错文件；查重失败或迁移日志损坏时停止写入。解散分组、跨组移动和共享旧媒体拆分复用此规则，先保留原件并提交引用迁移，再清理源文件，不覆盖根目录的同名内容。内容去重按名称、大小与 SHA-256 校验，同内容重试复用，不同内容加序号；扫描期间已被搬走的候选可跳过，权限错误不吞掉，最终复用前复核迁移与取消状态。兼容复用旧摘要文件，不批量改名已有文件。
- 项目文件占位、去重及迁移旧路径保护共用 `mediaFileAllocationKey`：Windows 忽略大小写，macOS 对新文件保守地忽略大小写并合并 Unicode 等价形式，Linux 保留大小写与 Unicode 形式差异。只规范查重键，不改磁盘文件名，不把 macOS 大小写敏感卷上已有不同大小写文件的引用合并。

## 失效记录清理

资源库的「修复失效素材」弹窗提供「重连素材」「清理失效记录」两种模式，复用 UI Kit 的 `ui-dialog-surface`、卡片标题/说明/内容/底部操作与 `PopupCloseButton`；长列表单独滚动，标题和操作区保留。清理只允许勾选当前扫描明确判为 `missing` 的项；在线、权限错误、冲突和未扫描项不能混作缺失处理。

外部目录的重新定位入口集中在「外部文件夹」标题右侧，复用 UI Kit 无背景、无边框图标按钮；仅一个根目录时直接打开，多个根目录时先从菜单明确选择目标，目录行不再重复放置入口。只读引用选择器不显示管理操作。此位置调整尚待桌面验收：核对单/多目录、宽面板与窄抽屉、深浅主题及键盘关闭菜单，目录移除仍只取消引用。

确认清理前先显示素材使用位置，再复查文件仍缺失、索引身份及位置未变。相关索引、资产专属提示词/标签/参考图关联、最近使用及对应输出历史在同一 IndexedDB 事务中清理；只按历史输出身份匹配，有 `filePath` 时以它为准，避免另一份副本的旧来源地址造成误删。提示词正文或输入参考中提到某文件不作为删除归属。事务保留清理标记，拒绝旧资产及已删历史身份的迟到写回，按清理时点拦截旧路径输出历史恢复；图片信息查询不能从未变的旧画布节点自动还原已清内容。提交成功后刷新内存和历史数量、保留历史筛选并使旧加载请求失效，不因视图取消漏掉已提交结果。

清理不可撤销，但不删除画布节点、对话正文、磁盘文件或共享参考图副本，也不移除外部文件夹登记；保留的节点和正文可能继续含失效引用，需要用户重连或重新选择。原文件重新出现、状态冲突、读取或事务失败时停止提交；已恢复文件不作为失效记录清理。

1. 准备一份已登记且带提示词、标签、参考图关联、最近使用与生成历史的素材；另放同名不同文件、正常在线项和权限异常项。将目标素材移到别处后进入清理模式，预期只有明确缺失项可选择，长列表在深浅主题及窄窗口中独立滚动。

### MCP 资源导入

- `file_import_media_to_canvas`：一次创建 1–20 个素材节点，按输入顺序返回节点 ID。每项 `path` / `uploadId` 二选一，允许混合：path 位于当前项目或所属剧集共享目录时直接复用原文件，只为当前分集建立画布节点；已授权的外部图片、视频、音频仍复制入项目，uploadId 领取当前 MCP 对话已完成的图片。支持名称、单项坐标和默认网格排列；不修改源文件、不调用生成模型、不自动扩大目录权限。
- 复用沿用分集 → 剧集素材目录映射，不按名称或内容猜测归属。原生 `copy_file_streamed` 仅在显式提供 `reuseRoot` 时复用：保留调用方、源文件读取、目标写入与目录真实路径授权，再检查源/目标为同一普通文件且位于共享根内；失效、越界或迁移中的路径失败关闭，不回退创建副本。普通节点复制仍创建独立文件。
- 同一目录被剧集与分集共用时，删除节点、分组及撤销新增节点只改变画布引用，不随之把共享文件或目录移入回收站；素材库显式文件删除与整部剧删除沿用原入口。旧 `_1` 文件不自动合并或删除。
- `file_media_upload`：MCP 客户端分块发送 PNG/JPEG/WebP 字节，无文件或单批总字节数业务上限。固定 256 KiB 块、末块余量，流式落盘并按 `sha256-chain-v1` 读回复核；文件头与 MIME/尺寸须匹配。绑定项目、对话、revision 和存储配置；空闲十分钟失效，可查询或取消。已完成 uploadId 在批量导入后消费一次，正文与路径不进入 MCP 审计。协议、故障残留和验证见[图片上传导入计划](./plans/2026-09-11-mcp图片上传导入.md)。
- `canvas_paste_external`：读取系统图片或纯文本。Windows 桌面端使用仅主窗口可调用的 `read_canvas_clipboard`，支持 PNG / DIB / DIBV5 和 UTF-16 文本；其他平台保留 Web Clipboard 读取并报告权限失败。不跟随 HTML、URL 或文件路径，不使用应用内部节点剪贴板。
- `ui_capture_to_canvas`：把主窗口真实可见界面截图直接持久化为图片节点，始终启用敏感元素过滤；截图字节不进入工具结果。
- 三个入口共用 [资源导入服务](../src/services/canvasResourceImportService.ts) 和既有文件服务、Store 批量写入。整批准备成功后提交一次历史；项目、revision、画布状态变化或取消时不回填。已复制但未提交的媒体可能留在项目素材目录中，不自动删除。
- 原生剪贴板限制输入 32 MiB、文本 100000 UTF-16 单元、图像边长 8192 和解码字节 128 MiB；结果只返回节点 ID、类型、坐标和 revision，不记录路径、剪贴板正文或图像 Base64。
- 验证与回滚见 [资源导入与截图计划](./plans/2026-09-09-mcp资源导入与截图.md)。
