# AI Canvas 开发指南

> 本文档面向开发者，涵盖本地环境搭建、项目结构、开发约定、调试技巧和常见问题。
> 当前版本：`0.9.0`；最后更新：2026-08-30

## 1. 环境准备

### 1.1 必需工具

| 工具 | 最低版本 | 说明 |
|------|---------|------|
| Node.js | `^20.19.0` 或 `>=22.12.0` | 满足 Vite 8 的运行要求 |
| npm | 随 Node.js 安装 | 包管理器 |
| Rust | stable | Tauri 编译工具链 |
| Visual Studio Build Tools | 2022 | Windows 上编译 Rust 需要 C++ 工具链 |

### 1.2 Windows 额外配置

安装 [Visual Studio Build Tools](https://visualstudio.microsoft.com/downloads/#build-tools-for-visual-studio-2022)，选择「使用 C++ 的桌面开发」工作负载。

### 1.3 安装依赖

```bash
cd AI-Canvas-tauri
npm install
```

## 2. 启动开发

### 2.1 仅前端开发（不需要 Tauri 运行时）

```bash
npm run dev
```

启动后访问 `http://localhost:1420`。此模式下：

- 文件操作自动降级为浏览器 API（File Input + IndexedDB）
- 原生对话框不可用
- Tauri 官方插件功能受限
- 用户代码插件无法完成原生信任注册、QuickJS / Python 执行和启停
- 桌面端凭据存储不可用，API Key 只在当前会话有效，刷新后需要重新填写
- 项目整体导出/导入、MCP 控制桥、本地 ONNX 推理不可用
- 3D 导演台独立窗口和运行资源下载不可用

### 2.2 完整 Tauri 桌面应用开发

```bash
npm run tauri dev
```

此命令会：

1. 先启动 Vite 开发服务器（端口 1420）
2. 编译 Rust 后端
3. 打开 Tauri 桌面窗口

`npm run tauri dev` 不会拉取或启动 3D 导演台源码。首次创建并使用 `lightweight-web` 导演台节点时，应用会按正式环境的流程下载该运行时的固定构建产物；Blender 运行时使用随主应用编译内嵌的另一套资源，不走这条下载链路。

### 2.3 生产构建

```bash
npm run build          # 构建前端 (dist/)
npm run tauri build    # 构建桌面安装包
```

### 2.3.1 检查与测试

```bash
npm run typecheck        # tsc -b
npm run lint             # ESLint（见 7. 常见问题的已知阻断）
npm run test             # Vitest 全量
npm run check            # lint + typecheck + 测试类型 + 测试
npm run ci               # check + build
npx vitest run tests/services/xxx.test.ts   # 定向测试
```

测试位于 `tests/`，按 `components` / `hooks` / `services` / `store` / `utils` / `scripts` 分类，使用 Vitest 与 `fake-indexeddb`。改动服务或 Store 时优先补对应目录下的定向测试。

### 2.4 轻量网页 3D 导演台开发模式

AI Canvas 的 `lightweight-web` 导演台在开发和生产环境中都通过 `director-desk://localhost/index.html` 加载已校验的固定构建产物。主项目不使用 iframe，不启动端口 `5178`，也不依赖 Git、Node.js 或 npm 来运行该网页运行时。

需要修改导演台本体时，在独立仓库中开发：

```bash
git clone https://github.com/Tenney95/3d-director-desk.git
cd 3d-director-desk
npm install
npm run dev
```

独立仓库的 Vite 服务只用于导演台本体开发。AI Canvas 的集成验证仍应使用 GitHub Release 构建产物。

## 3. 项目约定

### 3.1 文件命名

| 类型 | 命名规则 | 示例 |
|------|---------|------|
| 组件文件 | PascalCase + `.tsx` | `TextNode.tsx` |
| Hook 文件 | `use` 前缀 + camelCase + `.ts` | `useNodeCreation.ts` |
| 服务文件 | camelCase + `Service.ts` | `fileService.ts` |
| Store 文件 | `store.` 前缀 + 职责 + `.ts` | `store.nodes.ts` |
| 样式文件 | kebab-case + `.css` | `model-selector.css` |
| 类型文件 | `index.ts` | `types/index.ts` |

### 3.2 导入顺序

```tsx
// 1. React / 框架
import { useState, useCallback } from "react";

// 2. 第三方库
import { useReactFlow } from "@xyflow/react";

// 3. 本地组件
import TextNode from "./nodes/TextNode";

// 4. Hooks
import { useAppStore } from "../store/useAppStore";

// 5. 类型
import type { BaseNodeData } from "../types";
```

### 3.3 组件编写规范

- 节点组件用 `React.memo` 包裹
- 接收 `{ data, selected }` props
- 数据变更通过 `useAppStore().updateNodeData(nodeId, data)`
- 禁止在节点组件内直接修改 store 状态

```tsx
// ✅ 正确
const TextNode = React.memo(({ data, selected }: NodeProps) => {
  const updateNodeData = useAppStore((s) => s.updateNodeData);
  // ...
});

// ❌ 错误
const TextNode = ({ data }: NodeProps) => {
  useAppStore.setState({ ... }); // 禁止
};
```

### 3.4 类型定义

通用画布类型定义在 `src/types/index.ts`：
- `NodeType` — 节点类型联合类型
- `BaseNodeData` — 节点数据接口
- `CanvasProject` — 项目元数据
- `AppConfig` / `ApiProviderConfig` — API 配置
- `GeneralModelConfig` — 用户自建通用模型
- `ModelOption` / `ModelGroup` — 模型选项
- `WorkflowDefinition` — ComfyUI 工作流
- `UserPreset` — 用户预设
- `NodeGroup` — 节点分组

领域类型按模块拆分：`chat.ts`、`agent.ts`、`subAgent.ts`、`mcp.ts`、`plugin.ts`、`agentPackage.ts`、`canvasNote.ts`、`dramaAssets.ts`、`media.ts`、`memory.ts`、`aiTypes.ts`、`composerTypes.ts`。

新增类型优先加到对应文件，禁止在组件文件中重复定义。持久化类型不得包含 `AbortController`、本地绝对路径、密钥或 MCP 令牌。

### 3.5 样式约定

- 业务样式优先使用 Tailwind class
- 禁止 `!important`、硬编码颜色值、内联 `style.cssText`
- 复用 `tailwind.config.js` 中的 `canvas-*` 颜色 token（暗色基线）
- 浅色主题是低饱和马卡龙配色，由 `src/styles/base.css` 中的 `[data-theme='light']` 覆盖；新增可见面板必须同时确认两种主题
- React Flow 样式覆盖统一放 `src/styles/reactflow.css`
- 新增组件独立样式放入 `src/styles/` 目录，并在 `src/index.css` 中 `@import`
- 滚动条由 `OverlayScrollbarLayer` 统一接管，不要给单个容器加原生滚动条样式
- 节点类型 Header 使用语义色：文本=indigo、图像=green、视频=blue、音频=orange、全景=cyan

### 3.6 状态管理约定

- 所有状态变更必须通过 Store Actions
- 不可变更新：使用扩展运算符或 `immer`-style 更新
- 新增 slice 在 `src/store/` 下新建 `store.xxx.ts`，在 `useAppStore.ts` 中聚合
- Slice 会进入主窗口静态启动图，顶层不得导入模型协议、Provider、完整 Agent Runtime 或编辑器运行时
- 删除前清理、同步取消和状态迁移必须使用轻量服务，不能等待动态导入
- 组件内选择器保持精简，避免不必要的重渲染：

```tsx
// ✅ 精确选择
const nodes = useAppStore((s) => s.nodes);

// ❌ 全量选择（任何状态变更都会重渲染）
const store = useAppStore();
```

### 3.7 节点快捷键

画布快捷键由 `src/hooks/useKeyboardShortcuts.ts` 统一处理。不要在节点组件中新增全局 `keydown` 监听。

| 快捷键 | 作用 |
|---|---|
| `1` 到 `7`（含小键盘） | 创建文本、图像、视频、音频、全景、动画、3D 导演台节点 |
| `Alt + 1` 到 `Alt + 5` | 创建文本、图像、视频、音频、Markdown 源节点 |
| `Ctrl/Cmd/Alt + S` | 保存项目 |
| `Ctrl/Cmd + C` / `V` | 复制 / 粘贴节点 |
| `Ctrl/Cmd + Z`、`Ctrl/Cmd + Shift + Z`、`Ctrl/Cmd + Y` | 撤销 / 重做 |
| `Ctrl/Cmd/Alt + G` | 分组 / 取消分组 |
| `Ctrl/Cmd + Shift + M` | 切换吉祥物显示 |
| `Delete` / `Backspace` | 删除选中 |
| `Space` | 单选节点时打开 AI 对话框 |
| `F` / `M` / `Escape` | 适应视图 / 小地图 / 关闭浮层 |
| `F12` | 开发者工具 |

画布笔记工具通过 `CanvasDrawingToolbar` 选择，不占用数字快捷键。

新增数字快捷键时，同步更新 `CanvasContextMenu.tsx` 和 `Sidebar.tsx` 的帮助说明。创建入口必须复用同一组节点尺寸、角色和初始状态。

### 3.8 启动依赖与运行时分层

主窗口启动图包含 Store、全局 Hook 和首屏组件的静态依赖。提交代码前，按以下规则选择导入位置：

1. 把同步取消、状态迁移和运行时注册表放入轻量控制模块。
2. 让 Store Slice 直接调用轻量模块，保持 Action 的同步或异步契约。
3. 把模型上下文、流式协议、Provider 和工具执行器留在懒加载功能边界。
4. 不要用 `manualChunks` 掩盖静态依赖。模块仍在启动图时，分 chunk 不会减少启动解析成本。
5. 不要把同步中止改成 `import()`。异步加载会产生删除后的任务写回窗口。

Agent 的当前分层可作为参考：`agentTaskControl.ts` 进入共享启动 chunk，`agentRuntime.ts` 由 ChatPanel 按需加载，`agentRoundExecutor.ts` 与 `contextManager.ts` 落在独立的按需 chunk。`agentRuntime.ts` 重导出控制 API，既有聊天调用保持兼容；Store 应直接导入 `agentTaskControl.ts`。

### 3.9 安全边界约定

以下边界不是可选优化，绕过任何一条都会把 Renderer 的一次注入放大成系统级读写：

1. **凭据**：API Key 只经 `services/providerSecretService.ts` 交给 Rust `secret_store`。配置里只留条目名，禁止把明文写回 IndexedDB、导出归档、消息或日志。
2. **原生路径命令**：新增接收路径参数的自定义 command 必须调用 `path_policy.rs` 做调用方窗口校验和真实路径校验。自定义命令不经过 fs 插件 scope，不校验等于任意文件读写。
3. **Agent 出网**：只走 `agent/web.rs`（搜索与网页读取）和 `agent/provider_docs.rs`（厂商文档）。通用 `proxy_fetch` 不注册为 Agent 工具。
4. **工具权限**：新工具只能 `registerAgentTool()` 注册并声明准确的 effect；Policy Engine 的矩阵是本地固定边界，任何模型输出、网页、Skill 或 MCP 输入都不能修改它。
5. **用户插件**：安装与更新必须经过 `stage → IndexedDB persist → activate`。普通执行只提交 `pluginId + sourceDigest + toolId + invocationId + input`，源码和 runtime 由 Rust 私有注册表读取并重新核对摘要。JavaScript 在独立 QuickJS Runtime 中运行，远程媒体写回受来源集合约束；Python 是拥有当前用户完整系统权限的可信本机代码。`plugin-private` 必须同时拒绝 fs、asset protocol 和通用路径命令访问。
6. **MCP**：只暴露当前项目中已注册且可用的 Agent 工具，并固定使用 C 自主模式。`read`、`canvas_write`、`file_write`、`permanent_delete`、`media_generation`、`memory_write`、`config_write` 和 `asset_write` 均直接执行，不进入 B 模式审批；会产生模型开销的工具（如 `agent_run_sub_agent`）也可发现并执行。MCP 不能调用审批解决接口。工具的 `isAvailable` 不得依赖 `context.taskId`——发现阶段没有真实任务，会让工具从 MCP 列表里静默消失；需要任务上下文的判断放进 `authorize`。

### 5.7 启动依赖与 sourcemap 调试

性能拆包必须验证源码归属，不能只比较 chunk 文件名。Windows PowerShell 可在系统临时目录生成生产 sourcemap：

$perfOut = Join-Path $env:TEMP 'ai-canvas-perf-build'
npx vite build --sourcemap --outDir $perfOut --emptyOutDir

检查结果应满足以下条件：

- `agentRuntime.ts` 只出现在 ChatPanel chunk，`agentRoundExecutor.ts` 与 `contextManager.ts` 只出现在按需 chunk

- 相关同步 Action 的回归测试通过

chunk 体积和文件名会随功能与内容哈希变化。每次性能复核都应记录当次构建统计，并以 sourcemap 中的源码路径判断归属；不要把旧版本数值或 chunk 文件名当作长期基线。

### 5.8 MCP 控制桥调试

MCP 默认关闭，可以在 **设置 > MCP 控制** 手动开启，也可以显式启用“启动软件时自动开启”。端口可留空让每次会话随机分配，或配置 `1024–65535` 的固定端口。256-bit 固定令牌由 `mcpSessionConfig.ts` 生成并写入 Rust `secret_store` 的 `mcp/token` 条目，不进入 IndexedDB；凭据存储不可用时才退回本次会话令牌。令牌泄露或需要废止旧客户端配置时使用设置页的轮换操作，随后重新复制客户端配置。

两种传输最终都进入同一个 `mcpControlService.ts`、Tool Registry、Policy 和 AgentTask 审计链：

1. **本机 stdio**：默认传输。`scripts/ai-canvas-mcp.mjs` 通过 `127.0.0.1` 的固定或随机端口连接 Rust bridge；客户端配置把令牌放进 `AI_CANVAS_MCP_TOKEN` 环境变量，不写入命令行参数。
2. **远程 Streamable HTTP**：服务监听 `0.0.0.0:<port>/mcp`，允许局域网、Docker 或其他可达主机连接。请求必须携带 `Authorization: Bearer <token>`；Rust 还限制 Host 为 IPv4、`localhost` 或受支持的 Docker 主机名，有 Origin 时要求同主机同端口，并把请求体限制为 1 MiB、并发限制为 4。当前服务是明文 HTTP，Bearer Token 会随请求发送；只应在受信网络或隔离环境中开启，不要直接暴露到公网。
3. **执行语义**：stdio 与 Streamable HTTP 都固定使用 C 自主模式。已注册且通过 `isAvailable` / `authorize` 的读、画布写、文件写、永久删除、媒体生成、记忆写、配置写和资产写 effect 均不逐次审批；产生模型开销的可用工具（如 `agent_run_sub_agent`）也能执行。`user_choice` 仍表示等待用户作答，不是风险审批；MCP 客户端不能调用审批解决接口。
4. 每次调用都会在当前项目的「MCP 控制」会话中生成 AgentTask，可在任务时间线核对 Tool Registry 可用性、Policy 决策、执行与脱敏结果。

## 7. 常见问题

### Q: 前端开发模式下文件操作不可用？
A: 正常现象。Tauri 插件（fs、dialog）仅在 Tauri 桌面环境中可用。浏览器模式下自动降级为 File Input API + IndexedDB。同时凭据存储、项目导出/导入、MCP 控制桥和本地 ONNX 也不可用。

### Q: `npm run lint` 报 `scopeManager.addGlobals is not a function`？

A: 这是 ESLint 10 与解析器的既有兼容问题，不是本项目代码问题。遇到时记录该错误，改跑改动文件的定向检查：

```bash
npx eslint src/path/to/changed-file.ts
```

不要为了绕开它去改依赖版本，除非任务本身就是修工具链。

### Q: 浏览器模式下 API Key 每次都要重填？
A: 正常现象。凭据存储是 Rust 侧能力，浏览器模式没有它，API Key 只在当前会话内存中有效。桌面端凭据落在 `{appData}/secrets/credentials.json`。

### Q: 如何清除所有本地数据？
A: 打开浏览器 DevTools → Application → IndexedDB → 删除 `ai-canvas-db` 数据库。桌面端还需要删除项目数据目录和 `{appData}/secrets/`，前者可在 **设置 > 存储健康** 查看。

### Q: Tailwind class 不生效？
A: 检查 `tailwind.config.js` 的 `content` 配置是否包含对应文件路径。新增文件后可能需要重启开发服务器。

### Q: Tauri 构建失败？
A: 常见原因：
- Rust 工具链未安装或版本过低
- Visual Studio Build Tools 未安装
- `src-tauri/target/` 缓存损坏：删除后重试

### Q: Cargo 无法删除 `ai-canvas-tauri.exe`？

A: 旧的 Tauri 窗口仍占用 `src-tauri/target/debug/ai-canvas-tauri.exe`。先关闭应用窗口，并在任务管理器中结束残留的 `ai-canvas-tauri.exe`，再运行 `npm run tauri dev`。不要在进程仍运行时删除整个 `target` 目录。

### Q: 3D 导演台反复提示下载？

A: 应用只识别固定清单中的版本。检查 `scripts/director-desk-release.json`，确认本地目录包含匹配版本的 `index.html` 和 `director-desk-release.json`。开发环境可以在 **设置 > 存储健康** 删除资源后重新下载。

### Q: 3D 导演台下载失败？

A: 检查 GitHub Release 是否公开、产物名是否与清单一致，以及 `.sha256` 是否绑定同一文件。应用还会拒绝超过限制、包含不安全路径或协议元数据不匹配的归档。
