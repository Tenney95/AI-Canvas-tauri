# AI Canvas 架构说明

> 本文档描述 AI Canvas 当前的系统边界、模块职责、核心数据流和扩展约束。
> 当前版本：`0.6.13`；最后更新：2026-07-31。

## 1. 项目定位

AI Canvas 是一个基于 **Tauri 2 + React 19 + React Flow 12** 的桌面端 AI 多模态画布。你可以在无限画布中组织文本、图像、视频、音频、动画、全景图、Markdown、分镜、3D 导演台和手绘笔记节点，通过连线、引用、批量执行及对话 Agent 完成内容生成与画布操作。

项目同时支持：

- Tauri 桌面环境与有限的浏览器降级运行；
- 多项目、工作流、模型预设、技能、风格、角色库和短剧资产管理；
- 多厂商文本、图像、视频、音频生成，以及声明式自定义模型执行协议；
- ComfyUI 工作流、Dreamina 登录态调用和本地 ONNX 推理；
- 主画布、独立聊天窗口、独立资产搜索窗口和 3D 导演台窗口；
- 手动开启的会话级本地 MCP 控制桥，让外部客户端复用同一套工具与 Policy。

## 2. 总体架构

```text
┌──────────────────────────────────────────────────────────────┐
│ Tauri 2 桌面层                                               │
│ Rust commands / plugins / window / fs / updater / ONNX       │
│ path_policy / secret_store / mcp_bridge / project_archive    │
│ Director Desk download / validation / local URI protocol     │
└──────────────────────────────┬───────────────────────────────┘
                               │ IPC
┌──────────────────────────────▼───────────────────────────────┐
│ React 19 表现层                                               │
│ App / Canvas / Notes / Nodes / Panels / Agent / Windows      │
└──────────────────────────────┬───────────────────────────────┘
                               │ actions + selectors
┌──────────────────────────────▼───────────────────────────────┐
│ Zustand 5 全局状态                                            │
│ 19 slices：画布、项目、聊天、Agent、记忆、资产、配置和 UI 等     │
└──────────────────────────────┬───────────────────────────────┘
                               │ service calls
┌──────────────────────────────▼───────────────────────────────┐
│ 领域服务与运行时                                               │
│ AI generation / chat pipeline / polling / batch DAG / files  │
│ sub-agents / MCP control / character library / transfer      │
└───────────────┬──────────────────────────────┬───────────────┘
                │                              │
┌───────────────▼──────────────┐ ┌────────────▼────────────────┐
│ IndexedDB / 项目数据目录      │ │ 外部模型 API / ComfyUI       │
│ appLocalDataDir 运行资源      │ │ Dreamina / 本地 ONNX         │
│ appData/secrets 凭据文件      │ │ MCP 客户端（stdio）          │
└──────────────────────────────┘ └─────────────────────────────┘
```

核心边界如下：

- 组件负责展示和收集交互，不直接实现厂商协议或持久化细节；
- `useAppStore` 是前端共享业务状态的唯一入口；
- `services/` 负责 AI 请求、轮询、文件、数据库、聊天管线和外部控制映射；
- Rust 层负责浏览器无法安全或稳定完成的系统能力，并承担路径、凭据和网络出口的安全闸；
- 生成结果优先保存到项目数据目录，Store 中保存可恢复的资源引用；
- API Key 不进入前端持久化层，只按条目名向 Rust 凭据存储索取；
- 外部可选运行时必须锁定版本和校验值，并安装到应用本地数据目录；
- 外部控制协议（MCP）不新增能力，只复用已注册工具和既有 Policy。

## 3. 运行入口与窗口

`src/main.tsx` 复用同一套前端入口，通过 URL 参数选择 AI Canvas 根视图：

| 入口 | 根组件 | 用途 |
|---|---|---|
| 无 | `App` | 主画布窗口 |
| `?view=chat` | `ChatWindow` | 独立聊天助手窗口 |
| `?view=assets` | `AssetSearchWindow` | 独立资产搜索窗口 |
| `director-desk://localhost/index.html` | 预构建 3D 导演台 | 固定标签 `director-desk` 的独立窗口 |

`App.tsx` 负责装配主窗口级组件，包括 `Canvas`、`Header`、`Sidebar`、`Titlebar`、节点菜单、设置、工作流、资产、角色库、短剧资产、项目库、输出历史、聊天面板、Toast、开屏动画、首次启动引导、吉祥物和更新提示。应用启动时从 IndexedDB 恢复数据，并在 Tauri 窗口关闭前静默保存当前项目和清理撤销暂存目录。

MCP 控制桥没有独立窗口。适配器进程通过 loopback 连接 Rust，请求经 Tauri Event 转发给主窗口的 `mcpControlService.ts` 处理，因此外部调用与用户操作共用同一个 Store 写入源。

轻量网页导演台不经过 `src/main.tsx`，也不嵌入 iframe。`directorRuntimeRegistry.ts` 先解析节点选择的运行时；只有 `lightweight-web` 会交给 `directorDeskWindowService.ts` 创建或复用单一 `WebviewWindow`。窗口使用 `instanceId` 绑定当前导演节点，主窗口仍是节点数据的唯一写入源。Blender 在固定场景协议和受限脚本接入前只呈现不可用状态。

## 4. 前端表现层

### 4.1 画布与交互

`src/components/Canvas.tsx` 是 React Flow 的集成边界，负责节点/边渲染和画布事件编排。复杂交互拆分到 `components/canvas/` 与 `hooks/`：

| 模块 | 职责 |
|---|---|
| `CanvasToolbar` | 缩放、视图和画布工具 |
| `CanvasDrawingToolbar` | 笔记与绘图工具选择（形状、箭头、自由绘制、文本、图片、橡皮擦） |
| `CanvasNoteStylePanel` | 选中笔记的线条、填充、粗糙度、字体和层级设置 |
| `CanvasContextMenu` / `NodeContextMenu` | 画布与节点右键操作 |
| `ConnectionMenu` | 连线释放后的节点选择 |
| `MultiSelectToolbar` | 多选节点对齐、分布和批量操作 |
| `DistributionGapHandles` | 平均分布后的间距拖拽调整 |
| `HistoryTimelinePanel` | 画布右上角操作记录浮层 |
| `SelectedNodeFlowEdge` | 选中节点的连线高亮边 |
| `useNodeCreation` | 节点创建和文件拖入 |
| `useCanvasDrawing` | 笔记绘制的指针交互、几何生成和样式套用 |
| `useNodeSnap` | 单选与多选包围盒吸附、对齐参考线 |
| `useKeyboardShortcuts` | 保存、撤销、删除，以及数字键 `1-7` 创建内容节点等全局快捷键 |
| `useToolbarEdit` | 节点工具栏的可编辑布局与「更多」菜单 |
| `useAutoSave` | 项目自动保存 |

项目层的浮层组件与画布并列挂在 `App.tsx`：`SeriesRail` 是贴窗口右缘的剧集栏（原著、剧本、分集列表与本集大纲），`ProjectAssetsOverlay` 按集展示整部剧已生成的图片与视频，`ProjectSwitchOverlay` 在切换画布期间盖住画布区显示 Logo 加载动画。

说明性弹层同样挂在 `App.tsx` 与 `Sidebar` 两处：`OnboardingDialog` 由 `App.tsx` 在开屏动画结束后按 `localStorage` 标记 `ai-canvas-onboarding-seen` 弹一次，集中说明悬停提示和隐藏操作；`HelpCenterDialog` 挂在 `Sidebar` 的头像菜单下，按场景分类展示完整说明。两者的开关状态统一收在 `store.ui.ts` 的 `helpOpen`，引导弹窗因此可以直接把用户交给帮助中心。帮助中心里的操作演示（`HelpDemo` 与 `HelpMentionDemo`）复用真实组件和真实 chip 构造器：`HelpMentionDemo` 直接渲染 `MentionPicker` 并调用 `buildWorkflowChipEl` 生成工作流 IO 芯片，演示的样式即用户在提示词框里看到的样式。

画布笔记（`canvas-note`）不是独立图层，而是普通 React Flow 节点：它复用同一套选择、吸附、分组、复制和历史语义，几何计算集中在 `utils/canvasNoteGeometry.ts`，渲染拆分在 `components/noteNodes/`。

### 4.2 节点体系

节点类型统一定义在 `src/types/index.ts`。当前渲染组件包括：

| 组件 | 主要职责 |
|---|---|
| `TextNode` | 文本提示词、引用、流式文本生成与编辑（同时用于 `source-text` 与 `comment`） |
| `ImageNode` | 文生图/图生图、批量结果、生成历史、裁剪、扩图、抠图、合成、机位工作台等 |
| `VideoNode` | 文生视频/图生视频/视频到视频与视频参数 |
| `AudioNode` | 音频生成、参考音色、上传和播放 |
| `PanoramaNode` | 全景图生成与预览 |
| `AnimationNode` | 逐帧动画参数、生成与播放预览 |
| `DirectorDeskNode` | 导演台独立窗口、截图同步和下游媒体引用 |
| `MarkdownNode` | Markdown 内容编辑与渲染 |
| `StoryboardNode` | 分镜宫格、单格覆盖与素材组织 |
| `GroupNode` | 节点分组容器 |
| `CanvasNoteNode` | 形状、箭头、自由绘制、文本笔记和图片笔记 |

`ai-director` 的 `directorRuntimeKind` 是持久化运行时选择，旧项目字段缺失时由 resolver 解释为 `lightweight-web`；未知非空值失败关闭，不自动回退。`directorInstanceId` 是节点唯一运行时实例身份，`directorStatus` 表示当前会话状态，通用 `status` 表示节点是否已有可用截图或视频。复制会保留已有媒体和运行时选择，但必须生成新的实例 ID，并清除 `loading`、`error` 等瞬时状态。

共享编辑器和选择器位于 `components/nodes/shared/`，其中包括模型选择、提示词 Composer、@引用、预设（含高级序列）、技能、风格、质量比例、音视频参数，以及裁剪、扩图、抠图、多图合成、机位工作台和宫格编辑等能力。图像标注与全景查看已收敛到 `@tenney95/xiaoluo-image-editor` 和 `xiaoluo-vr-panorama` 两个外部包。新增通用节点交互应优先复用这里的组件。

节点工具栏由 `components/nodes/shared/toolbar/` 的注册表描述：用户可以调整常用操作在栏内的位置，其余动作进入「更多」菜单，布局按节点类型持久化到 IndexedDB。

`components/director/` 管理导演台运行资源的状态检查、下载确认、进度和错误恢复。`components/settings/DirectorDeskStorageManager.tsx` 展示已安装版本与占用，并提供应用内删除入口。

### 4.3 聊天助手

`components/chat/` 提供嵌入式和独立窗口共用的聊天 UI。业务逻辑由以下模块协作：

- `agentTaskControl.ts`：启动期轻量任务控制、状态迁移、同步中止、审批等待和调度队列清理；
- `agentRuntime.ts` / `agentRoundExecutor.ts`：ChatPanel 按需加载的多轮“模型、工具、Observation、模型”循环、上下文预算和工具执行；
- `toolRegistry.ts`：工具注册、可用性过滤和本地 schema 校验；
- `policyEngine.ts`：Plan/B/C 模式与工具 effect 的固定权限矩阵；
- `agentTaskService.ts` / `store.agent.ts`：任务持久化、后台状态和重启修复；
- `agentBudgetService.ts` / `agentCheckpointService.ts` / `agentRewindService.ts`：预算核算、画布 checkpoint 与回退；
- `agentInterjection.ts` / `agentJournal.ts` / `agentLifecycle.ts`：运行中插话、执行日志和生命周期事件；
- `subAgentService.ts` / `subAgentProfileService.ts` / `subAgentMaterials.ts`：只读子智能体的运行、配置与材料装配；
- `expertTaskService.ts`：内置只读专家复核角色；
- `contextManager.ts` / `contextCompressionService.ts`：上下文预算、历史组装和压缩；
- `projectMemoryService.ts` / `memoryRetrieval.ts` / `store.memory.ts`：用户确认的项目记忆及召回；
- `fileGrantService.ts` / `webAccessGrantService.ts` / `providerDocsGrantService.ts`：绑定会话的临时本地文件、网页与厂商文档授权；
- `skillCatalog.ts` / `skillManifest.ts`：Skill 索引与按需加载的渐进披露；
- `rulesEngine.ts` / `promptLearningService.ts`：项目规则与提示词沉淀；
- `tools/seriesTools.ts`：`series_read` 读取原著与剧本正文，`series_split_episodes` 只追加地批量创建分集并写入大纲；
- `services/ai/assistantStream.ts`：Provider 流式文本和工具调用协议。

`store.chat.ts` 和 `store.projects.ts` 直接调用轻量控制层，因此删除会话或项目时可以同步中止后台任务。`agentRuntime.ts` 继续重导出控制 API，聊天侧既有调用保持兼容；两个入口使用同一份控制器与审批 resolver，不会创建重复运行时状态。

Plan 模式只放行只读工具。B 模式的画布写操作需要确认，C 模式可自动执行。文件写入、永久删除、媒体生成、记忆写入和厂商配置写入始终需要确认。画布写入还必须校验 `projectId`、canvas revision，并提交撤销历史。

#### 4.3.1 只读子智能体

子智能体是配置数据而非代码：用户在助手内定义名称、派用场景、角色说明书（绑定 Skill 或内联提示词）、可读材料和轮次上限，配置持久化在 `subAgentProfiles`，内置典范不落库、运行时合并。

与主任务的差别在于隔离而非并行调度：子任务不加载会话历史，自建“角色说明书 + 材料 + 分派任务”消息序列，因此复用 `executeAgentRound` 而不是 `runAgentLoop`；它只读、不写画布、不产生会话消息，所以绕过会话调度队列，并行度直接由 round executor 既有的只读工具并发提供。单个父任务最多派出 6 个子任务，产出在回传和持久化前分别按上限截断。

### 4.4 MCP 控制层

`services/mcp/` 是外部控制协议在前端的唯一落点：

- `mcpBridgeService.ts`：监听 Rust 转发的 bridge 请求并回送响应；
- `mcpControlService.ts`：把请求映射到已注册 Agent 工具，执行 schema、可用性、Policy、执行前项目与授权复核，并写入专用审计任务；
- `mcpSessionConfig.ts`：会话开关与适配器参数。

`scripts/ai-canvas-mcp.mjs` 是 stdio 侧适配器，基于官方 `@modelcontextprotocol/sdk`，只连接 Rust 在 loopback 随机端口开出的会话。工具发现使用占位 taskId，因此工具的 `isAvailable` 不能依赖任务查询；需要任务上下文的判断放在 `authorize` 中。详见 [ADR 0004](adr/0004-local-mcp-control-bridge.md)。

## 5. 状态管理

`src/store/useAppStore.ts` 使用 Zustand Slice 模式聚合 19 个 slice：

| Slice | 职责 |
|---|---|
| `store.nodes.ts` | 节点、边、选择状态、画布笔记及节点数据更新 |
| `store.ui.ts` | 面板、菜单、弹窗和画布 UI 状态 |
| `store.toast.ts` | 全局通知 |
| `store.history.ts` | 画布快照的撤销/重做 |
| `store.historyRecord.ts` | 节点生成输出历史记录 |
| `store.config.ts` | 主题、模型提供商、通用模型及应用配置 |
| `store.workflows.ts` | ComfyUI 工作流 |
| `store.presets.ts` | 提示词预设 |
| `store.skills.ts` | 技能库 |
| `store.subAgents.ts` | 用户可配置的只读子智能体角色 |
| `store.styles.ts` | 风格库 |
| `store.groups.ts` | 节点分组 |
| `store.clipboard.ts` | 节点及系统剪贴板操作 |
| `store.projects.ts` | 多项目、剧集与分集、保存、加载和切换 |
| `store.chat.ts` | 聊天会话、消息、请求和画布操作日志 |
| `store.agent.ts` | AgentTask、步骤、审批和后台任务状态 |
| `store.memory.ts` | 项目记忆及候选确认状态 |
| `store.toolbar.ts` | 节点工具栏布局 |
| `store.dramaAssets.ts` | 短剧人物、场景、道具资产及角色声音 |

状态使用规则：

1. 组件通过 selector 订阅所需的最小状态；
2. 共享业务状态必须通过 Store Action 修改；
3. 异步协议和持久化细节留在 Service，slice 只负责编排和状态收口；
4. 画布结构性变更应接入撤销历史和聊天 revision；
5. 异步派生结果回写前经 `canvasDerivationGuard` 复核项目、源节点和 revision，避免写入已切换的画布；
6. 大体积媒体数据不直接写入 Store，保存文件路径、asset URL 或远端源地址；
7. API Key 等凭据在持久化前由 `providerSecretService.ts` 摘出，配置里只保留条目引用；
8. Slice 会进入主窗口静态启动图，顶层只导入轻量服务；模型协议、Provider、编辑器和完整 Agent Runtime 由懒加载功能边界引入。

## 6. 服务层与 AI 运行时

### 6.1 AI 生成

`services/aiService.ts` 保留统一公开入口，具体实现拆分在 `services/ai/`：

- `generateText.ts`、`generateImage.ts`、`generateVideo.ts`、`generateAudio.ts`：按媒体类型组织请求；
- `generationRuntime.ts`：对话侧媒体生成的统一入口；
- `generationService.ts`：工具栏快捷指令与节点弹窗共用的节点生成执行器；
- `mediaProviderRegistry.ts`：图片、视频、音频三类参考媒体到厂商适配器的统一分发；
- `connectedReferenceMedia.ts`：从连线与提示词中解析参考媒体；
- `modelProtocol.ts` / `modelProtocolRuntime.ts` / `modelProtocolImport.ts`：声明式自定义模型执行协议的解析、执行与文档导入；
- `providers/`：厂商特定适配器；
- `providerCatalogService.ts`：厂商与模型目录；
- `promptResolver.ts`、`nodeReferenceService.ts`：解析节点引用和生成输入；
- `pollTask.ts`、`pollManager.ts`：异步生成任务轮询与生命周期管理；
- `comfyWorkflowService.ts`：ComfyUI 工作流执行，含图片与音频输入注入，未用 `@` 指定节点时注入到工作流的默认 IO 节点；
- `presetSequenceService.ts`：高级预设的多步生成序列；
- `imageBatchService.ts`：批量图片结果的原子保存与派生节点更新；
- `transcribeAudio.ts`：音频转写；
- `dreaminaService.ts`：Dreamina 登录态和生成调用；
- `onnxService.ts`：本地超分、主体抠图和角色方向图接口；
- `uploadService.ts`：需要公网输入时的媒体上传与 URL 转换。

新增厂商差异应收口到适配器或对应 service，避免在节点组件和 Store 中散落 provider 分支。模型协议只映射受信变量，不执行代码、不覆盖鉴权头、不改写请求源。

### 6.2 批量执行

`src/utils/batchExecute.ts` 负责选中节点的批量生成：

1. 过滤缺少模型、提供商、提示词或正在执行的节点；
2. 对选中范围内有连线的节点使用 Kahn 算法拓扑排序并顺序执行；
3. 无依赖的孤立节点并发执行；
4. 两组任务并行推进；
5. 每个结果更新节点状态、保存媒体并写入输出历史。

### 6.3 文件与持久化

| 服务 | 职责 |
|---|---|
| `fileService.ts` | 项目文件、生成结果、导入导出和跨环境文件操作入口 |
| `services/fs/core.ts` | 文件系统基础能力 |
| `services/fs/assetLibrary.ts` / `assetIndex.ts` | 项目资产库与资产索引 |
| `services/fs/trash.ts` | 可撤销删除与清理 |
| `services/fs/storageHealth.ts` | 存储占用统计与清理入口 |
| `indexedDbService.ts` | 浏览器侧结构化持久化 |
| `providerSecretService.ts` | 凭据摘出与 Rust 凭据存储的桥接 |
| `projectTransferService.ts` | 项目整体导出为 `.aicanvas` 并以新 ID 导入 |
| `projectSnapshotService.ts` | 画布缩略图生成（必要时借助 Worker） |
| `projectSettingsService.ts` | 项目创作基线的纯解析规则 |

项目归档由前端组装清单、项目记录和对话文本，Rust `project_archive.rs` 负责 tar.gz 打包解包。素材在项目记录中本就以相对路径保存，归档内 `assets/` 与项目目录一一对应，因此导入后无需重写路径；导入始终分配新的项目 ID 和数据目录，重复导入不会互相覆盖。

### 6.4 3D 导演台运行时

`directorRuntimeRegistry.ts` 是固定、不可动态注册的运行时门面。当前正式可用适配器为 `lightweight-web`；`blender` 已进入节点数据与 UI 契约，但在固定场景协议、应用内固定脚本和结果清单接入前稳定返回 unavailable，不会调用网页导演台、Tauri 进程、Shell 或 Python。未知运行时同样失败关闭。

轻量网页导演台来自独立仓库 `Tenney95/3d-director-desk`。它是面向不安装 Blender 用户的正式方案，不是待删除的兼容层。主项目不拉取源码、不执行 npm 安装，也不启动额外 HTTP 服务。开发与生产环境使用同一条运行链路：

1. `scripts/director-desk-release.json` 固定仓库、版本、产物 URL、协议、大小和 SHA-256；
2. 显式新建 `lightweight-web` 节点时，Store 请求 `DirectorDeskRuntimeManager` 检查运行资源；批量新建整批只请求一次，项目恢复、粘贴和 Ctrl 拖拽复制不自动提示或打开；
3. 用户确认后，前端调用 Rust command 下载、校验并安装资源；
4. 安装完成后重新确认节点仍存在、实例 ID 未变化且仍选择 `lightweight-web`，再由运行时门面打开窗口；
5. `directorDeskWindowService.ts` 通过 `director-desk://localhost/index.html` 打开独立窗口；
6. 主窗口与导演台使用限定消息类型的 Tauri Event 信封通信；
7. 截图和扩展操作结果回写当前 `instanceId` 对应的画布节点。

运行资源安装在 `appLocalDataDir/director-desk/<version>`。安装过程使用临时下载文件和 staging 目录，失败或取消时清理临时内容。成功安装后保留当前版本和最多一个旧版本。

同项目复制保留截图、参考视频及其文件引用，但运行时实例彼此独立。跨项目导演节点的多媒体结构化搬运尚未在本阶段收敛，不能把单个 `filePath` 当成全部截图与视频的共同来源。

应用内删除入口会关闭导演台窗口并移除整个运行资源目录。Windows NSIS 卸载钩子也会删除该目录；macOS 和 Linux 依赖应用内入口或平台对应用数据目录的清理策略。项目、配置和对话数据不属于该清理范围。

## 8. Rust / Tauri 原生层

`src-tauri/src/lib.rs` 负责插件注册、窗口管理和 IPC command 装配。当前插件包括：

- `fs`、`dialog`、`global-shortcut`、`shell`；
- `drag`；
- `updater`、`process`。

原生能力主要分为：

| 类别 | 能力 |
|---|---|
| 网络与文件 | 代理请求与流式代理、图片转 data URL、移入回收站、指定应用打开文件、文件管理器定位、剪贴板文件写入 |
| 受限出网 | Agent 网页搜索与读取、厂商文档读取（协议、DNS/IP、重定向和体积校验） |
| 文件传输 | 可取消的流式复制与下载 |
| 项目归档 | `.aicanvas` 打包与解包 |
| 凭据 | 凭据条目的读写删除与可用性查询 |
| MCP | 控制桥启动、停止、状态查询和响应回送 |
| 窗口 | 开关独立聊天窗口、锁定、开发者工具、自定义窗口行为 |
| 3D 导演台 | 固定 Release 下载、校验、取消、删除和 `director-desk://` 文件响应 |
| Dreamina | 登录窗口、会话运行时、状态、退出、生成和结果查询 |
| ComfyUI | 启动本地 ComfyUI |
| ONNX | 模型目录、模型检查/下载、图片超分、主体抠图、角色方向图、GPU 状态 |
| 更新 | 检查、下载、安装并重启应用 |

Rust 子模块位于 `src-tauri/src/` 下的 `path_policy.rs`、`secret_store.rs`、`mcp_bridge.rs`、`project_archive.rs`、`assistant_web.rs`、`provider_docs.rs`、`clipboard.rs`、`director_desk_runtime.rs`、`file_transfer.rs`、`dreamina.rs`、`comfyui/` 和 `onnx/`。Windows 下额外处理 WebView2 GPU 参数，并使用 ONNX Runtime DirectML 执行本地推理。

安全闸分三层：

- `path_policy.rs`：自定义命令不经过 fs 插件 scope，因此由本模块补上调用方窗口校验（拒绝远程页面，例如 Dreamina 登录窗）和真实路径校验（解析符号链接后要求落在应用数据目录或用户显式授权的 fs scope 内）。
- `secret_store.rs`：凭据文件在 fs 插件 scope、asset 协议 scope 和 `path_policy` 三条路径上都被显式拒绝，Renderer 只能按条目名逐条索取，无法枚举或整份导出；unix 下文件权限为 0600。
- `assistant_web.rs` / `provider_docs.rs`：Agent 出网只走固定搜索端点和通过 DNS/IP、重定向、体积校验的公开地址，通用 `proxy_fetch` 不对 Agent 开放。

`director_desk_runtime.rs` 只接受固定 GitHub Release URL，并限制压缩包为 100 MB、展开内容为 300 MB、归档条目为 10,000 个。协议处理器只允许标签为 `director-desk` 的窗口访问当前版本目录，并验证规范路径、MIME 类型和单段 Range 请求。

`mcp_bridge.rs` 只监听 IPv4 loopback 随机端口，承担端口、鉴权、会话生命周期、请求关联和 Tauri Event 转发；它不解释 Agent 工具，也不访问 IndexedDB。一次性令牌只存在于前端组件状态、Rust 会话内存和适配器进程参数中，并在转发给 WebView 前被移除。

## 9. 核心数据流

### 9.1 节点生成

```text
节点交互
  → Store 将节点置为 loading
  → 解析 @节点引用 / 技能 / 风格 / 角色 / 模型参数
  → connectedReferenceMedia 收集连线与提示词中的参考图片、视频、音频
  → mediaProviderRegistry 分发到对应厂商适配器
  → aiService 媒体入口
  → provider、模型协议、ComfyUI、Dreamina 或 ONNX
  → 同步返回或 pollManager 轮询
  → canvasDerivationGuard 复核项目与 revision
  → fileService 保存结果
  → Store 回填 URL、路径、尺寸、状态
  → historyRecord 记录生成历史
```

### 9.2 聊天助手

```text
ChatInput
  → conversationExecutionController 创建消息和 AgentTask
  → agentScheduler 按会话启动或排队
  → agentTaskControl 注册 AbortController 并迁移任务状态
  → 按需 agentRuntime 组装上下文并调用 assistantStream
  → toolRegistry 校验 schema，policyEngine 决定执行或确认
  → 工具结果作为 Observation 进入下一轮模型请求
  → 画布工具校验 projectId / revision 并提交撤销历史
  → 消息、步骤、事件和任务状态写入 IndexedDB
```

### 9.3 MCP 工具调用

```text
外部 MCP 客户端（stdio）
  → scripts/ai-canvas-mcp.mjs 适配器
  → loopback 连接 + 一次性令牌鉴权
  → mcp_bridge 去掉令牌并按请求 ID 转发 Tauri Event
  → 主窗口 mcpControlService 查 Tool Registry
  → 本地 schema、可用性、policyEngine 决策
  → 高影响操作在 AI Canvas 内弹出审批卡片
  → 执行前复核项目、会话与授权，必要时建立画布 checkpoint
  → 结果脱敏后回送，并写入「MCP 控制」会话的 AgentTask 时间线
```

### 9.4 项目恢复

```text
应用启动
  → initFromDb
  → 恢复配置、项目、工作流、预设、技能、风格、子智能体和全局角色
  → 从 Rust 凭据存储按条目名补齐 API Key
  → 目标是剧集时改为打开它的第一集
  → 加载当前项目节点/边（含画布笔记）
  → 迁移并加载输出历史
  → 加载项目短剧资产与项目记忆
  → 加载项目聊天会话并修复异常中断状态（未完成任务恢复为 paused）
```

### 9.5 3D 导演台首次使用

```text
显式新建 lightweight-web 节点，或用户点击打开已恢复/复制的节点
  → 固定 registry 解析 directorRuntimeKind
  → Blender/未知运行时直接显示不可用，不触发网页运行时
  → lightweight-web 检查当前固定版本是否安装
  → 批量新建只为第一个 lightweight-web 节点请求一次；恢复和复制不主动检查
  → 主窗口显示下载确认
  → Rust 流式下载并计算 SHA-256
  → 校验归档路径、类型、体积、index.html 和协议元数据
  → staging 目录切换为版本目录
  → 再确认节点、instanceId 和运行时选择仍匹配
  → director-desk:// 加载本地静态资源
  → Tauri Event 绑定 instanceId 并交换会话、截图和请求结果
```

## 10. 样式与性能

- Tailwind CSS 3 用于组件级工具类，颜色复用 `canvas-*` token；
- 全局入口为 `src/index.css`，只做 `@import` 聚合，功能样式拆分到 `src/styles/*.css`；
- React Flow 覆盖集中在 `src/styles/reactflow.css`；
- 暗色是基线配色，浅色为低饱和马卡龙方案，由 `src/styles/base.css` 中的 `[data-theme='light']` 覆盖；
- 滚动条统一由 `OverlayScrollbarLayer` 接管，原生滚动条全局隐藏；
- 节点按媒体类型拆分样式，编辑器也按能力拆分；
- 节点组件使用 `React.memo`，Store 使用细粒度 selector；节点弹窗只订阅所需字段，避免无关全局状态触发重渲染；
- Three.js、GSAP 等大体积吉祥物依赖按需懒加载；
- 帮助中心、首次引导及其 GSAP 演示时间线按需加载，已看过引导的用户不会加载引导 chunk；
- 长聊天节点引用订阅稳定的 displayId 派生快照，画布位置和选中变化不会触发全部引用文本重渲染；
- 图片合成、抠图、扩图、机位工作台、自定义宫格编辑器和全景查看器按需加载；
- Agent 的同步控制层进入启动图，模型上下文、流式协议和工具轮次执行进入按需 chunk；
- `DirectorDeskNode` 和下载管理 UI 按需加载，导演台静态资源不进入主应用 `dist` 或安装包；
- 高频拖拽、缩放、绘制和对齐计算避免写入持久化层，交互结束后再提交历史；
- 保存与加载画布时，文件仍停在记录的 `relativePath` 上就直接沿用已有的 `assetId`，不再逐个节点 `stat` 加重写资产索引；
- 项目素材目录的全量扫描只在有节点解析不到文件时触发（外部改名或移动），常规切换不扫盘；
- 画布缩略图只在从项目库切换时重拍，标签栏与剧集栏之间切换不做截图。

`0.6.13` 的生产构建基线：包含 Store 与 `agentTaskControl.ts` 的共享启动 chunk 为 `559.12 kB`，gzip 后 `175.98 kB`。源码图应保持 `agentTaskControl.ts` 位于共享启动 chunk，`agentRuntime.ts` 位于 ChatPanel chunk，`agentRoundExecutor.ts` 与 `contextManager.ts` 位于独立的按需 chunk。构建产物名会随内容变化，验证时以 sourcemap 中的源码归属为准，不要按 chunk 文件名判断。

## 12. 设计约束与演进方向

1. **Store 是状态入口，不是协议实现层**：厂商请求、文件和数据库逻辑继续留在 Service。
2. **统一生成入口**：节点、批量执行和聊天媒体生成应复用同一媒体实现，避免行为分叉。
3. **配置驱动模型**：模型能力、参数和 provider 映射应由配置与适配器描述。
4. **工作流与模型 API 分层**：ComfyUI 工作流协议不与普通厂商模型请求强行混用。
5. **资产可恢复**：远端生成成功后尽量落盘，节点保存本地引用和原始来源。
6. **命令执行可审计**：聊天画布操作保留确认、revision、操作日志和撤销边界。
7. **复杂交互模块化**：画布几何、节点编辑器和多选操作继续从大组件中拆出纯函数或专用模块。
8. **双环境边界明确**：浏览器模式只做安全可行的降级，原生系统能力统一经过 Tauri command 或插件。
9. **可选运行时固定且受限**：轻量网页导演台不得跟随分支或 GitHub `latest`，也不得在主项目启动源码服务；升级时必须更新固定清单、校验协议兼容并重新构建主应用。Blender 接入只能执行应用内固定脚本和已授权项目目录，模型、插件和场景数据不得传入任意 Python、命令行参数或文件路径。
10. **启动依赖保持轻量**：Store、全局 Hook 和首屏组件不得静态引入低频重型运行时。同步取消和清理能力拆到轻量模块，不能用异步导入改变操作时序。
11. **外部协议不扩权**：MCP 等外部控制入口只复用已注册工具和既有 Policy，不新增通用 Shell、任意路径读写或任意 HTTP，也不能自行批准高影响操作。
12. **凭据只在 Rust 侧**：API Key 不进入 Store 持久化、IndexedDB、导出归档、消息或日志；新增原生路径命令必须先过 `path_policy`。
13. **画布语义单一**：新的画布对象（如笔记）复用节点、选择、历史和持久化语义，不另建平行图层或平行状态树。
