# AI Canvas 架构说明

> 本文档描述 AI Canvas 当前的系统边界、模块职责、核心数据流和扩展约束。
> 当前版本：`0.9.0`；最后更新：2026-08-30。

## 1. 项目定位

AI Canvas 是一个基于 **Tauri 2 + React 19 + React Flow 12** 的桌面端 AI 多模态画布。你可以在无限画布中组织文本、图像、视频、音频、动画、全景图、Markdown、分镜、3D 导演台和手绘笔记节点，通过连线、引用、批量执行及对话 Agent 完成内容生成与画布操作。

项目同时支持：

- Tauri 桌面环境与有限的浏览器降级运行；
- 多项目、工作流、模型预设、技能、风格、角色库和短剧资产管理；
- 多厂商文本、图像、视频、音频生成，以及声明式自定义模型执行协议；
- ComfyUI 工作流、Dreamina 登录态调用和本地 ONNX 推理；
- 主画布、独立聊天窗口、独立资产搜索窗口和 3D 导演台窗口；
- 默认关闭、可显式配置自动开启的 MCP 控制桥，同时支持本机 stdio 与高风险 Streamable HTTP，让外部客户端复用同一套工具、Policy 和审计链。

## 2. 总体架构

```text
┌──────────────────────────────────────────────────────────────┐
│ Tauri 2 桌面层                                               │
│ Rust commands / plugins / window / fs / updater / ONNX       │
│ path_policy / secret_store / plugin_registry / plugin_runtime │
│ mcp_bridge / project_archive / director + Blender runtimes    │
└──────────────────────────────┬───────────────────────────────┘
                               │ IPC
┌──────────────────────────────▼───────────────────────────────┐
│ React 19 表现层                                               │
│ App / Canvas / Notes / Nodes / Panels / Agent / Windows      │
└──────────────────────────────┬───────────────────────────────┘
                               │ actions + selectors
┌──────────────────────────────▼───────────────────────────────┐
│ Zustand 5 全局状态                                            │
│ 21 slices：画布、项目、聊天、Agent、记忆、资产、配置和 UI 等     │
└──────────────────────────────┬───────────────────────────────┘
                               │ service calls
┌──────────────────────────────▼───────────────────────────────┐
│ 领域服务与运行时                                               │
│ AI generation / chat pipeline / polling / batch DAG / files  │
│ sub-agents / MCP control / character library / transfer      │
└───────────────┬──────────────────────────────┬───────────────┘
                │                              │
┌───────────────▼──────────────┐ ┌────────────▼────────────────┐
│ IndexedDB / 项目数据目录      │ │ 外部模型 API / ComfyUI       │
│ appLocalDataDir 固定运行资源  │ │ Dreamina / 本地 ONNX         │
│ secrets / plugin-private 等   │ │ MCP 客户端（stdio / HTTP）   │
└──────────────────────────────┘ └─────────────────────────────┘
```

核心边界如下：

- 组件负责展示和收集交互，不直接实现厂商协议或持久化细节；
- `useAppStore` 是前端共享业务状态的唯一入口；
- `services/` 负责 AI 请求、轮询、文件、数据库、聊天管线和外部控制映射；
- Rust 层负责浏览器无法安全或稳定完成的系统能力，并承担路径、凭据和网络出口的安全闸；
- 生成结果优先保存到项目数据目录，Store 中保存可恢复的资源引用；
- API Key 与 MCP 固定令牌不进入普通配置或 IndexedDB，只按条目名向 Rust 凭据存储索取；
- 插件 IndexedDB 记录用于管理和迁移，Rust 私有注册表及不可变源码快照才是运行阶段的执行权威；
- 外部可选运行时必须锁定版本和校验值，并安装到应用本地数据目录；
- 外部控制协议（MCP）不新增能力，只复用已注册工具和既有 Policy。

## 3. 运行入口与窗口

`src/main.tsx` 复用同一套前端入口，通过 URL 参数选择 AI Canvas 根视图：

| 入口 | 根组件 | 用途 |
|---|---|---|
| 无 | `App` | 主画布窗口 |
| `?view=chat` | `ChatWindow` | 独立聊天助手窗口 |
| `?view=assets` | `AssetSearchWindow` | 独立资产搜索窗口 |
| `director-desk://localhost/index.html` | 预构建 3D 导演台 | 固定标签 `director-desk` 的独立窗口 |

`App.tsx` 负责装配主窗口级组件，包括 `Canvas`、`Header`、`Sidebar`、`Titlebar`、节点菜单、设置、工作流、资产、角色库、短剧资产、项目库、输出历史、聊天面板、Toast、开屏动画、首次启动引导、吉祥物和更新提示。应用启动时从 IndexedDB 恢复数据，并在 Tauri 窗口关闭前静默保存当前项目和清理撤销暂存目录。

MCP 控制桥没有独立窗口。本机 stdio 客户端通过适配器进程连接 Rust 的 `127.0.0.1` bridge；Streamable HTTP 客户端直接访问绑定 `0.0.0.0` 的 `/mcp`。两种传输都由 Rust 完成鉴权与请求关联，再以不含令牌的 Tauri Event 转发给主窗口 `mcpControlService.ts`，因此外部调用与用户操作共用同一个 Store 写入源。

轻量网页导演台不经过 `src/main.tsx`，也不嵌入 iframe。`directorRuntimeRegistry.ts` 先解析节点选择的运行时；`lightweight-web` 交给 `directorDeskWindowService.ts` 创建或复用单一 `WebviewWindow`，`blender` 则由 `directorBlenderRuntimeService.ts` 调用用途单一的原生 Job commands。两种运行时都使用 `instanceId` 绑定当前导演节点，主窗口仍是节点数据和结果投影的唯一写入源。

## 4. 前端表现层

`src/components/Canvas.tsx` 是 React Flow 的集成边界，负责节点/边渲染和画布事件编排。复杂交互拆分到 `components/canvas/` 与 `hooks/`：

| `CanvasNoteStylePanel` | 选中笔记的线条、填充、粗糙度、字体和层级设置 |
| `CanvasContextMenu` / `NodeContextMenu` | 画布与节点右键操作 |
| `ConnectionMenu` | 连线释放后的节点选择 |
| `MultiSelectToolbar` | 多选节点对齐、分布和批量操作 |
| `DistributionGapHandles` | 平均分布后的间距拖拽调整 |
| `HistoryTimelinePanel` | 画布右上角操作记录浮层 |
| `SelectedNodeFlowEdge` | 选中节点的连线高亮边 |
| `useNodeCreation` | 节点创建和文件拖入 |
| `useCanvasDrawing` | 笔记绘制的指针交互、几何生成和样式套用 |
| `useNodeSnap` | 单选与多选包围盒吸附、对齐参考线 |

| `useAutoSave` | 项目自动保存 |

项目层的浮层组件与画布并列挂在 `App.tsx`：`SeriesRail` 是贴窗口右缘的剧集栏（原著、剧本、分集列表与本集大纲），`ProjectAssetsOverlay` 按集展示整部剧已生成的图片与视频，`ProjectSwitchOverlay` 在切换画布期间盖住画布区显示 Logo 加载动画。

说明性弹层同样挂在 `App.tsx` 与 `Sidebar` 两处：`OnboardingDialog` 由 `App.tsx` 在开屏动画结束后按 `localStorage` 标记 `ai-canvas-onboarding-seen` 弹一次，集中说明悬停提示和隐藏操作；`HelpCenterDialog` 挂在 `Sidebar` 的头像菜单下，按场景分类展示完整说明。两者的开关状态统一收在 `store.ui.ts` 的 `helpOpen`，引导弹窗因此可以直接把用户交给帮助中心。帮助中心里的操作演示（`HelpDemo` 与 `HelpMentionDemo`）复用真实组件和真实 chip 构造器：`HelpMentionDemo` 直接渲染 `MentionPicker` 并调用 `buildWorkflowChipEl` 生成工作流 IO 芯片，演示的样式即用户在提示词框里看到的样式。

画布笔记（`canvas-note`）不是独立图层，而是普通 React Flow 节点：它复用同一套选择、吸附、分组、复制和历史语义，几何计算集中在 `utils/canvasNoteGeometry.ts`，渲染拆分在 `components/noteNodes/`。

### 4.2 节点体系

节点类型统一定义在 `src/types/index.ts`。当前渲染组件包括：

| 组件 | 主要职责 |
|---|---|
| `TextNode` | 文本提示词、引用、流式文本生成与编辑（同时用于 `source-text` 与 `comment`） |
| `ImageNode` | 文生图/图生图、批量结果、生成历史、裁剪、扩图、抠图、合成、机位工作台等 |
| `VideoNode` | 文生视频/图生视频/视频到视频与视频参数 |
| `AudioNode` | 音频生成、参考音色、上传和播放 |
| `PanoramaNode` | 全景图生成与预览 |
| `AnimationNode` | 逐帧动画参数、生成与播放预览 |
| `DirectorDeskNode` | 双运行时导演台、当前镜头同步、结构化结果清单和下游媒体引用 |
| `MarkdownNode` | Markdown 内容编辑与渲染 |
| `StoryboardNode` | 分镜宫格、单格覆盖与素材组织 |
| `GroupNode` | 节点分组容器 |
| `CanvasNoteNode` | 形状、箭头、自由绘制、文本笔记和图片笔记 |

`ai-director` 的 `directorRuntimeKind` 是持久化运行时选择，旧项目字段缺失时由 resolver 解释为 `lightweight-web`；未知非空值失败关闭，不自动回退。`directorInstanceId` 是节点唯一运行时实例身份，`directorStatus` 表示当前会话状态，通用 `status` 表示节点是否已有可用截图或视频。复制会保留已有媒体和运行时选择，但必须生成新的实例 ID，并清除 `loading`、`error` 等瞬时状态。

共享编辑器和选择器位于 `components/nodes/shared/`，其中包括模型选择、提示词 Composer、@引用、预设（含高级序列）、技能、风格、质量比例、音视频参数，以及裁剪、扩图、抠图、多图合成、机位工作台和宫格编辑等能力。图像标注与全景查看已收敛到 `@tenney95/xiaoluo-image-editor` 和 `xiaoluo-vr-panorama` 两个外部包。新增通用节点交互应优先复用这里的组件。

节点工具栏由 `components/nodes/shared/toolbar/` 的注册表描述：用户可以调整常用操作在栏内的位置，其余动作进入「更多」菜单，布局按节点类型持久化到 IndexedDB。

`components/director/` 管理导演台运行资源的状态检查、下载确认、进度和错误恢复。`components/settings/DirectorDeskStorageManager.tsx` 展示已安装版本与占用，并提供应用内删除入口。

### 4.3 聊天助手

`components/chat/` 提供嵌入式和独立窗口共用的聊天 UI。业务逻辑由以下模块协作：

- `agentTaskControl.ts`：启动期轻量任务控制、状态迁移、同步中止、审批等待和调度队列清理；
- `agentRuntime.ts` / `agentRoundExecutor.ts`：ChatPanel 按需加载的多轮“模型、工具、Observation、模型”循环、上下文预算和工具执行；
- `toolRegistry.ts`：工具注册、可用性过滤和本地 schema 校验；
- `policyEngine.ts`：Plan/B/C 模式与工具 effect 的固定权限矩阵；
- `agentTaskService.ts` / `store.agent.ts`：任务持久化、后台状态和重启修复；
- `agentBudgetService.ts` / `agentCheckpointService.ts` / `agentRewindService.ts`：预算核算、画布 checkpoint 与回退；
- `agentInterjection.ts` / `agentJournal.ts` / `agentLifecycle.ts`：运行中插话、执行日志和生命周期事件；
- `subAgentService.ts` / `subAgentProfileService.ts` / `subAgentMaterials.ts`：只读子智能体的运行、配置与材料装配；
- `expertTaskService.ts`：内置只读专家复核角色；
- `contextManager.ts` / `contextCompressionService.ts`：上下文预算、历史组装和压缩；
- `projectMemoryService.ts` / `memoryRetrieval.ts` / `store.memory.ts`：用户确认的项目记忆及召回；
- `fileGrantService.ts` / `webAccessGrantService.ts` / `providerDocsGrantService.ts`：绑定会话的临时本地文件、网页与厂商文档授权；
- `skillCatalog.ts` / `skillManifest.ts`：Skill 索引与按需加载的渐进披露；
- `rulesEngine.ts` / `promptLearningService.ts`：项目规则与提示词沉淀；
- `tools/seriesTools.ts`：`series_read` 读取原著与剧本正文，`series_split_episodes` 只追加地批量创建分集并写入大纲；
- `services/ai/assistantStream.ts`：Provider 流式文本和工具调用协议。

`store.chat.ts` 和 `store.projects.ts` 直接调用轻量控制层，因此删除会话或项目时可以同步中止后台任务。`agentRuntime.ts` 继续重导出控制 API，聊天侧既有调用保持兼容；两个入口使用同一份控制器与审批 resolver，不会创建重复运行时状态。

Plan 模式只放行只读工具，`user_choice` 和所有写入 effect 都会拒绝。B 模式按 effect 对画布写入、文件写入、永久删除、媒体生成、记忆写入、厂商配置写入和资产写入请求确认；C 自主模式自动放行这些写入 effect。MCP 控制会话固定按 C 自主模式执行，同样不逐次等待人工审批，也不能调用审批解决接口。`user_choice` 在 B/C/MCP 中仍必须等待 AI Canvas 用户作答。画布写入还必须校验 `projectId`、canvas revision，并提交撤销历史。

#### 4.3.1 只读子智能体

子智能体是配置数据而非代码：用户在助手内定义名称、派用场景、角色说明书（绑定 Skill 或内联提示词）、可读材料和轮次上限，配置持久化在 `subAgentProfiles`，内置典范不落库、运行时合并。

与主任务的差别在于隔离而非并行调度：子任务不加载会话历史，自建“角色说明书 + 材料 + 分派任务”消息序列，因此复用 `executeAgentRound` 而不是 `runAgentLoop`；它只读、不写画布、不产生会话消息，所以绕过会话调度队列，并行度直接由 round executor 既有的只读工具并发提供。单个父任务最多派出 6 个子任务，产出在回传和持久化前分别按上限截断。

### 4.4 MCP 控制层

`services/mcp/` 是外部控制协议在前端的唯一落点：

- `mcpBridgeService.ts`：监听 Rust 转发的 bridge 请求并回送响应；
- `mcpControlService.ts`：把请求映射到已注册 Agent 工具，执行 schema、可用性、Policy、执行前项目与授权复核，并写入专用审计任务；
- `mcpSessionConfig.ts`：默认关闭/自动开启、stdio/Streamable HTTP、固定/随机端口、固定令牌读取与轮换及客户端配置片段。

控制桥默认关闭，但用户可以显式启用 `mcpAutoStart`。端口既可固定，也可留空交给系统随机分配。`scripts/ai-canvas-mcp.mjs` 是基于官方 `@modelcontextprotocol/sdk` 的 stdio 适配器，只连接 Rust 的 `127.0.0.1` bridge；Streamable HTTP 在设置页完成高风险确认后监听 `0.0.0.0`，端点固定为 `/mcp`，允许局域网或隔离容器内的兼容客户端直接连接。stdio 的原始设计背景见 [ADR 0004](adr/0004-local-mcp-control-bridge.md)。

`mcpSessionConfig.ts` 生成 256-bit 随机令牌，固定值唯一持久化到 Rust `secret_store` 的 `mcp/token` 条目并支持轮换；凭据存储不可用时才退化为当前会话内存令牌。令牌不进入普通配置、IndexedDB、Tauri Event、消息或日志；stdio 通过适配器环境变量接收令牌，HTTP 使用 `Authorization: Bearer`。工具发现使用占位 taskId，因此 `isAvailable` 不能依赖任务查询，需要任务上下文的判断放在 `authorize` 中。

两种传输都固定映射到 C 自主模式：安全矩阵中的八类 effect 不逐次审批，远程传输切换时的高风险确认只是配置授权；`user_choice` 在 MCP 自主上下文中仍等待 AI Canvas 用户作答，MCP 客户端不能调用审批解决接口。

| `store.plugins.ts` | 插件安装、迁移、启停、卸载与原生信任注册编排 |
| `store.agentPackages.ts` | 全局 AgentPackage 目录、安装状态与任务绑定入口 |

状态使用规则：

1. 组件通过 selector 订阅所需的最小状态；
2. 共享业务状态必须通过 Store Action 修改；
3. 异步协议和持久化细节留在 Service，slice 只负责编排和状态收口；
4. 画布结构性变更应接入撤销历史和聊天 revision；
5. 异步派生结果回写前经 `canvasDerivationGuard` 复核项目、源节点和 revision，避免写入已切换的画布；
6. 大体积媒体数据不直接写入 Store，保存文件路径、asset URL 或远端源地址；
7. API Key 等凭据在持久化前由 `providerSecretService.ts` 摘出，配置里只保留条目引用；
8. 插件工具和自定义节点捕获的 `sourceDigest` 是整次调用的版本租约；每轮原生执行、宿主 effect 和最终写回前都要复核，摘要切换、停用和卸载先撤销旧租约并清理内存文件 grant；
9. Slice 会进入主窗口静态启动图，顶层只导入轻量服务；模型协议、Provider、编辑器和完整 Agent Runtime 由懒加载功能边界引入。

## 6. 服务层与 AI 运行时

### 6.1 AI 生成

`services/aiService.ts` 保留统一公开入口，具体实现拆分在 `services/ai/`：

### 6.2 批量执行

`src/utils/batchExecute.ts` 负责选中节点的批量生成：

1. 过滤缺少模型、提供商、提示词或正在执行的节点；
2. 对选中范围内有连线的节点使用 Kahn 算法拓扑排序并顺序执行；
3. 无依赖的孤立节点并发执行；
4. 两组任务并行推进；
5. 每个结果更新节点状态、保存媒体并写入输出历史。

### 6.4 3D 导演台运行时

`directorRuntimeRegistry.ts` 是固定、不可动态注册的运行时门面。`lightweight-web` 是长期正式、无需安装 Blender 但自身运行资源按需安装的适配器；`blender` 是 Windows x86_64 上需要用户显式选择 Blender 5.2.1 的原生预览适配器，当前编译内嵌运行包为 `ai-canvas-blender-runtime 1.3.2`。未知运行时仍失败关闭，Blender 缺失或失败也不会静默调用网页导演台代替。

轻量网页导演台来自独立仓库 `Tenney95/3d-director-desk`。它是面向不安装 Blender 用户的正式方案，不是待删除的兼容层。主项目不拉取源码、不执行 npm 安装，也不启动额外 HTTP 服务。开发与生产环境使用同一条运行链路：

1. `scripts/director-desk-release.json` 固定仓库、版本、产物 URL、协议、大小和 SHA-256；
2. 显式新建 `lightweight-web` 节点时，Store 请求 `DirectorDeskRuntimeManager` 检查运行资源；批量新建整批只请求一次，项目恢复、粘贴和 Ctrl 拖拽复制不自动提示或打开；
3. 用户确认后，前端调用 Rust command 下载、校验并安装资源；
4. 安装完成后重新确认节点仍存在、实例 ID 未变化且仍选择 `lightweight-web`，再由运行时门面打开窗口；
5. `directorDeskWindowService.ts` 通过 `director-desk://localhost/index.html` 打开独立窗口；
6. 主窗口与导演台使用限定消息类型的 Tauri Event 信封通信；
7. 截图和扩展操作结果回写当前 `instanceId` 对应的画布节点。

Blender 路径由另一条受限链路执行：

1. 设置页或节点只接收脱敏候选摘要；标准位置由 Rust 有界发现，Steam/便携版通过系统文件对话框手选，绝对路径只进入用途单一的登记 command 并保留在 Rust 进程内；
2. 主窗口为当前项目建立绑定 `projectId` 的内存 grant，Renderer 只获得 opaque `projectGrantId`；
3. `directorBlenderRuntimeService.ts` 只提交固定 operation、项目/节点/Scene 标量和可选帧号，不提交 executable、脚本、argv、cwd、env 或输出路径；
4. Rust 根据 `runtime-manifest.json` 安装并复核编译内嵌的 Application Template、`startup.blend`、人物资产和固定 Job 脚本；清单中的包版本、资源大小、SHA-256 与 `resources.rs` 必须完全一致；
5. `open-editor` 以交互模式启动 Blender；用户点击“保存并返回 AI Canvas”后，固定模板先保存 `.blend`，再用当前活动摄影机渲染当前帧 PNG，并生成绑定本次 Job/Scene/manifest revision 的结果文件；
6. Windows 子进程进入 Job Object，取消、超时和应用退出走同一原生回收边界；
7. Rust 对 `open-editor` 只接受恰好一个 `frame-image` 和一个 `blend-project`，并复核结果绑定、摘要、大小、文件头和输出目录；校验通过后把不可变 artifact 与新 Result Manifest 提交到项目目录；
8. 前端要求返回当前帧，经项目、节点、`instanceId`、Scene revision 和 canvas derivation guard 复核后，把最新 PNG 投影到节点的 `imageUrl` / `filePath` / `thumbnailUrl`，并保存 `directorResultManifest`；`.blend` 通过结果清单延续，不把单一绝对路径作为节点状态真值。

Phase 1-C 当前仍是预览阶段：核心真机流程已经通过，但真实超时、崩溃和应用退出的可重复故障注入证据仍待补齐。

轻量网页导演台资源安装在 `appLocalDataDir/director-desk/<version>`。下载过程使用临时文件和 staging 目录，失败或取消时清理临时内容；成功后保留当前版本和最多一个旧版本。Blender 固定资源独立安装在 `appLocalDataDir/blender-native-private/blender-runtime/1.3.2`，该私有树不对 Renderer 开放。

同项目复制保留截图、参考视频及其文件引用，但运行时实例彼此独立。跨项目导演节点的多媒体结构化搬运尚未在本阶段收敛，不能把单个 `filePath` 当成全部截图与视频的共同来源。

轻量网页导演台的应用内删除入口会关闭导演台窗口并移除其运行资源目录。Windows NSIS 卸载钩子也会删除该目录；macOS 和 Linux 依赖应用内入口或平台对应用数据目录的清理策略。项目、配置和对话数据不属于该清理范围。

### 6.5 用户插件执行与原生信任注册表

插件平台保留两条执行轨道：JavaScript 在独立 QuickJS Runtime 中运行，只能使用 Manifest 声明的宿主能力；Python 是用户明确授权的可信本机代码，可以访问当前用户拥有的文件、网络、环境变量、site-packages 和系统 API。Python 的原生确认、超时与进程树回收是风险提示和生命周期边界，不是操作系统沙箱。详细决策见 [`adr/0010-native-plugin-trust-registry.md`](adr/0010-native-plugin-trust-registry.md)。

`plugins/registry.rs` 将注册表和不可变入口源码快照保存在 `{appLocalData}/plugin-private/`。每个注册项只保留 `active`、`previous` 和 `staged` revision，revision 记录入口源码 SHA-256、版本、runtime、entry、宿主权限和工具 ID。该目录从 fs scope、asset protocol scope 和通用路径 command 同时拒绝，Renderer 不能取得真实快照路径或内容。

安装和更新采用以下事务边界：

1. 前端解析 Manifest 并显示来源、完整源码摘要、宿主权限和 Python 本机风险；
2. Rust 独立解析 revision，Python 在写入私有数据前必须通过绑定插件 ID、版本、摘要与权限的原生确认；
3. `stage_plugin_revision` 保存不可执行快照并返回 Rust 计算的 `sourceDigest`，前端与用户确认值复核后把安装记录和摘要写入 IndexedDB；
4. 更新时先撤销旧前端版本租约，摘要变化还会清除旧 revision 的内存文件 grant；
5. `activate_plugin_revision` 原子切换活动版本，失败时恢复旧 active 或移除首次注册，并恢复 IndexedDB 记录。

普通执行 IPC 只接收 `pluginId + sourceDigest + toolId + invocationId + input`。`plugins/runtime.rs` 从私有注册表取得 runtime 和源码；Rust 依次确认可信调用窗口、插件已启用、摘要等于 active、工具属于该 revision，并在执行前重新读取和计算源码 SHA-256。前端把捕获的 `sourceDigest` 作为整次调用租约，在每轮原生执行、宿主 effect 和最终 Store 写回前复核，因此旧 QuickJS 结果也不能越过版本切换写入新状态。

停用、卸载和摘要切换会先撤销前端租约并清理内存文件 grant；原生注册表提交状态后取消活动 Python invocation。Windows Python 子进程加入带 `KILL_ON_JOB_CLOSE` 的 Job Object，macOS/Linux 使用独立进程组。已有摘要的旧记录只调用 `ensure_plugin_registration`；私有注册缺失、摘要不匹配或快照损坏时自动停用，不回退到 IndexedDB/Renderer 源码执行。当前 P0 revision key 仍是入口源码 SHA-256，Manifest 安全字段变化但入口字节不变时会失败关闭，不能以放宽校验作为兼容方案。

- `drag`；
- `updater`、`process`。

Rust 入口与跨域安全脊柱保留在 `src-tauri/src/` 根层，其他源文件按 `agent/`、`mcp/`、`plugins/`、`files/`、`media/` 和 `director/` 领域归类。`lib.rs` 通过显式 `#[path]` 保持既有 crate 根模块名，因此 Tauri command、内部安全调用和测试过滤器不因物理目录调整而变化。Windows 下额外处理 WebView2 GPU 参数，并使用 ONNX Runtime DirectML 执行本地推理。

关键安全闸包括：

- `path_policy.rs`：自定义命令不经过 fs 插件 scope，因此由本模块补上调用方窗口校验和真实路径校验；除 `secrets` 外，`agent-private`、`plugin-private`、Blender 原生私有目录及其祖先也不能成为递归命令目标。
- `secret_store.rs`：API Key 与 MCP 固定令牌写入同一受限凭据文件；该文件在 fs 插件 scope、asset 协议 scope 和 `path_policy` 三条路径上都被显式拒绝，Renderer 只能按条目名逐条索取，无法枚举或整份导出；unix 下文件权限为 0600。
- `plugins/registry.rs` / `plugins/runtime.rs`：执行身份由活动 `sourceDigest`、工具归属和重新哈希后的私有源码共同决定；Python 原生确认在锁外完成，确认后重新比较 registration 快照，停用、卸载和版本切换会取消活动 Python 调用。
- `director/blender_runtime/`：Renderer 只持有安装 ID、项目 grant 和固定 Job 标量；可执行文件、固定脚本、输出目录及 artifact 提交由 Rust 构造和校验。
- `agent/web.rs` / `agent/provider_docs.rs`：Agent 出网只走固定搜索端点和通过 DNS/IP、重定向、体积校验的公开地址，通用 `proxy_fetch` 不对 Agent 开放。

`director/desk_runtime.rs` 只接受固定 GitHub Release URL，并限制压缩包为 100 MB、展开内容为 300 MB、归档条目为 10,000 个。协议处理器只允许标签为 `director-desk` 的窗口访问当前版本目录，并验证规范路径、MIME 类型和单段 Range 请求。

`mcp/bridge.rs` 按传输类型绑定网络边界：stdio 适配器连接 `127.0.0.1`，Streamable HTTP 监听 `0.0.0.0` 并固定挂载 `/mcp`；固定或系统随机端口都由同一会话状态管理。它验证 256-bit 令牌并承担会话生命周期、请求关联和无令牌 Tauri Event 转发，但不解释 Agent 工具，也不访问 IndexedDB。固定令牌只落 Rust `secret_store`，凭据存储不可用时才留在当前会话内存，可在设置页轮换。

HTTP 分支要求 Bearer Token，Host 只接受 IPv4、localhost 或受支持的容器宿主名；请求带 Origin 时必须与 Host 和端口同源。服务限制请求体为 1 MiB，并施加有界并发。当前端点是明文 HTTP，Bearer 只提供鉴权而不加密流量，因此远程模式必须经过高风险确认，且只能用于受信网络或隔离环境。

## 9. 核心数据流

### 9.1 节点生成

```text
节点交互
  → Store 将节点置为 loading
  → 解析 @节点引用 / 技能 / 风格 / 角色 / 模型参数
  → connectedReferenceMedia 收集连线与提示词中的参考图片、视频、音频
  → mediaProviderRegistry 分发到对应厂商适配器
  → aiService 媒体入口
  → provider、模型协议、ComfyUI、Dreamina 或 ONNX
  → 同步返回或 pollManager 轮询
  → canvasDerivationGuard 复核项目与 revision
  → fileService 保存结果
  → Store 回填 URL、路径、尺寸、状态
  → historyRecord 记录生成历史
```

### 9.2 聊天助手

```text
ChatInput
  → conversationExecutionController 创建消息和 AgentTask
  → agentScheduler 按会话启动或排队
  → agentTaskControl 注册 AbortController 并迁移任务状态
  → 按需 agentRuntime 组装上下文并调用 assistantStream
  → toolRegistry 校验 schema，policyEngine 决定执行或确认
  → 工具结果作为 Observation 进入下一轮模型请求
  → 画布工具校验 projectId / revision 并提交撤销历史
  → 消息、步骤、事件和任务状态写入 IndexedDB
```

### 9.3 MCP 工具调用

```text
外部 MCP 客户端
  ├─ stdio → scripts/ai-canvas-mcp.mjs → 127.0.0.1 固定/随机端口
  └─ Streamable HTTP → 高风险配置确认 → http://<AI_CANVAS_IP>:<port>/mcp
  → 256-bit 固定令牌鉴权（stdio 环境变量 / HTTP Bearer）
  → mcp_bridge 校验传输限制，去掉令牌并按请求 ID 转发 Tauri Event
  → 主窗口 mcpControlService 查 Tool Registry
  → 本地 schema、可用性、policyEngine 决策
  → 固定 C 自主模式：八类 effect 不逐次审批；仅 user_choice 等待用户作答
  → 执行前复核项目、会话与授权，必要时建立画布 checkpoint
  → 结果脱敏后回送，并写入「MCP 控制」会话的 AgentTask 时间线
```

### 9.4 项目恢复

```text
应用启动
  → initFromDb
  → 恢复配置、项目、工作流、预设、技能、风格、子智能体和全局角色
  → 从 Rust 凭据存储按条目名补齐 API Key
  → 目标是剧集时改为打开它的第一集
  → 加载当前项目节点/边（含画布笔记）
  → 迁移并加载输出历史
  → 加载项目短剧资产与项目记忆
  → 加载项目聊天会话并修复异常中断状态（未完成任务恢复为 paused）
```

### 9.5 3D 导演台运行时选择与首次使用

```text
显式新建节点，或用户点击打开已恢复/复制的节点
  → 固定 registry 解析 directorRuntimeKind
  → 未知运行时失败关闭，不自动回退
  ├─ lightweight-web
  │    → 检查固定 Release 是否安装；批量新建只为首个节点请求一次
  │    → 用户确认后由 Rust 下载、计算 SHA-256 并校验归档和协议元数据
  │    → staging 原子切换为版本目录
  │    → 复核节点、instanceId 和运行时选择
  │    → director-desk:// 加载本地资源并用 Tauri Event 交换截图/结果
  └─ blender
       → 有界发现或系统对话框选择兼容 Blender，Rust 只保存不透明 installationId
       → 主窗口为当前项目建立内存 projectGrantId
       → Rust 安装并复核固定内嵌运行包，启动 open-editor Job
       → 用户在 Blender 保存并返回
       → 固定模板生成当前活动摄影机 PNG + .blend
       → Rust 校验精确 artifact 集合、绑定、摘要、文件头并提交新 Result Manifest
       → 前端复核项目/节点/instanceId/Scene/canvas derivation 后写回当前镜头和清单引用
```

## 10. 样式与性能

- Tailwind CSS 3 用于组件级工具类，颜色复用 `canvas-*` token；
- 全局入口为 `src/index.css`，只做 `@import` 聚合，功能样式拆分到 `src/styles/*.css`；
- React Flow 覆盖集中在 `src/styles/reactflow.css`；
- 暗色是基线配色，浅色为低饱和马卡龙方案，由 `src/styles/base.css` 中的 `[data-theme='light']` 覆盖；
- 滚动条统一由 `OverlayScrollbarLayer` 接管，原生滚动条全局隐藏；
- 节点按媒体类型拆分样式，编辑器也按能力拆分；
- 节点组件使用 `React.memo`，Store 使用细粒度 selector；节点弹窗只订阅所需字段，避免无关全局状态触发重渲染；
- Three.js、GSAP 等大体积吉祥物依赖按需懒加载；
- 帮助中心、首次引导及其 GSAP 演示时间线按需加载，已看过引导的用户不会加载引导 chunk；
- 长聊天节点引用订阅稳定的 displayId 派生快照，画布位置和选中变化不会触发全部引用文本重渲染；
- 图片合成、抠图、扩图、机位工作台、自定义宫格编辑器和全景查看器按需加载；
- Agent 的同步控制层进入启动图，模型上下文、流式协议和工具轮次执行进入按需 chunk；
- `DirectorDeskNode` 和下载管理 UI 按需加载，导演台静态资源不进入主应用 `dist` 或安装包；
- 高频拖拽、缩放、绘制和对齐计算避免写入持久化层，交互结束后再提交历史；
- 保存与加载画布时，文件仍停在记录的 `relativePath` 上就直接沿用已有的 `assetId`，不再逐个节点 `stat` 加重写资产索引；
- 项目素材目录的全量扫描只在有节点解析不到文件时触发（外部改名或移动），常规切换不扫盘；
- 画布缩略图只在从项目库切换时重拍，标签栏与剧集栏之间切换不做截图。

生产构建应保持 `agentTaskControl.ts` 位于共享启动 chunk，`agentRuntime.ts` 位于 ChatPanel chunk，`agentRoundExecutor.ts` 与 `contextManager.ts` 位于独立的按需 chunk。chunk 体积和文件名会随内容变化，验证时以当次构建统计及 sourcemap 中的源码归属为准，不把历史数值写成长期基线。

## 12. 设计约束与演进方向

1. **Store 是状态入口，不是协议实现层**：厂商请求、文件和数据库逻辑继续留在 Service。
2. **统一生成入口**：节点、批量执行和聊天媒体生成应复用同一媒体实现，避免行为分叉。
3. **配置驱动模型**：模型能力、参数和 provider 映射应由配置与适配器描述。
4. **工作流与模型 API 分层**：ComfyUI 工作流协议不与普通厂商模型请求强行混用。
5. **资产可恢复**：远端生成成功后尽量落盘，节点保存本地引用和原始来源。
6. **命令执行可审计**：聊天画布操作保留 Policy 决策、适用时的确认、revision、操作日志和撤销边界。
7. **复杂交互模块化**：画布几何、节点编辑器和多选操作继续从大组件中拆出纯函数或专用模块。
8. **双环境边界明确**：浏览器模式只做安全可行的降级，原生系统能力统一经过 Tauri command 或插件。
9. **可选运行时固定且受限**：轻量网页导演台不得跟随分支或 GitHub `latest`，也不得在主项目启动源码服务；升级时必须更新固定清单、校验协议兼容并重新构建主应用。Blender 接入只能执行应用内固定脚本和已授权项目目录，模型、插件和场景数据不得传入任意 Python、命令行参数或文件路径；内嵌资源变化必须同步包版本、大小和摘要，`open-editor` 只有在 `.blend` 与当前活动摄影机 PNG 双产物均通过原生校验后才能提交。
10. **启动依赖保持轻量**：Store、全局 Hook 和首屏组件不得静态引入低频重型运行时。同步取消和清理能力拆到轻量模块，不能用异步导入改变操作时序。
11. **外部协议不扩权**：MCP 等外部控制入口只复用已注册工具和既有 Policy，不新增通用 Shell、任意路径读写或任意 HTTP；stdio 与 Streamable HTTP 都按既定矩阵自主执行但不能调用审批解决接口或修改本地 Policy。远程传输的高风险确认只授权监听方式，不能改变工具集合或 Policy。
12. **私有数据只走专用 Rust 边界**：API Key 与 MCP 固定令牌不进入 Store 持久化、普通配置、IndexedDB、导出归档、消息、Event 或日志，只能进入 `secret_store`；新增原生路径命令必须先过 `path_policy`，且不得暴露凭据、AgentPackage、插件或 Blender 私有目录及其祖先。
13. **画布语义单一**：新的画布对象（如笔记）复用节点、选择、历史和持久化语义，不另建平行图层或平行状态树。
14. **插件执行身份不可由 Renderer 替换**：安装和更新遵循 `stage → persist → activate`，运行 IPC 只传不透明身份与输入；`sourceDigest` 同时约束 Rust 活动快照和前端整次调用租约，注册异常必须失败关闭。
