# ADR-0012：分离项目、分集与画布身份并保留旧数据定位

- 日期：2026-11-07。
- 状态：**Accepted（架构原则）**。P0～P5 已有准备层、隔离迁移／业务和归档恢复实现；P6 隔离演练与 P7 旧依赖收敛正在推进，未完成正式路由或发布验收。正式迁移／激活保持关闭；各阶段实际验证结果和未完成项以主方案为准。
- 领域模型、迁移、兼容矩阵、阶段与验收唯一详述：[主方案](../plans/2026-11-07-project-episode-canvas-refactor.md)。

## 背景

CanvasProject 同时表示普通项目、剧集容器和单集画布。共享资产/会话/记忆归 owner，任务/历史/MCP 写入则通常绑定旧画布 projectId。项目摘要携带完整剧本和故事图；删除最后一集会删除共享容器。新增的工作台、原文、团队、故事图及归档合并进一步放大了职责和身份歧义。

## 备选方案

| 方案 | 收益 | 代价 |
|---|---|---|
| 原大记录只加 kind | 改动小，可作过渡 | 不能解决大摘要、共享生命周期与跨域保存 |
| 领域对象＋分域仓储＋版本化兼容迁移 | 可保留 ID，小步替换读写和协议 | 需迁移账本、恢复能力与外部合同覆盖 |
| 全量换 ID/目录/持久化 | 新模型形式统一 | 引用和数据恢复风险过高 |

采用第二项作为本阶段合同，后续激活仍受主方案的验证与恢复门禁约束。

## 决策一：作品所有者独立于画布

Project 持有共享归属与默认设置。普通项目直接拥有主 Canvas；剧集拥有零到多个 Episode，每集首期严格一张 Canvas。不为普通项目建立虚构分集，不扩展多级/多画布。

删末集保留整剧；普通项目转剧集只增加分集关系，根项目和原 Canvas ID不变。成本是需要项目就绪/画布就绪两个状态，空项目不能误当全局上下文。

旧 v1 孤立分集形成的顶层文稿进入 standaloneCreative，保持可编辑/可往返，不为了无 Episode 模型丢掉已知字段。旧多根目录保留受限 rootRef，业务归属统一不意味着物理目录强制统一。

## 决策二：列表、创作内容与画布分域保存

列表只读取轻量 Project/Episode 元数据，正文、共享内容和预览按需读取。画布、正文、故事图采用各自版本与条件写入，聚合操作由同一 IndexedDB 事务处理，不依赖组件补偿多次保存。

成本是增加必要对象表与读取 API；收益是避免画布保存重写无关资料。文件系统和 IDB 仍通过暂存、回执与可恢复步骤协调，不宣称跨系统 ACID。

## 决策三：旧身份不改号，旧合同按域解释

保留 owner、旧分集/Canvas、节点、资产、任务与逻辑协作身份，建立持久化 legacy binding。新内部合同明确 Project/Episode/Canvas target。旧 MCP expectedProjectId 仍表示原画布，不转换为 owner 后比较；旧幂等绑定和付费回执不重算。

成本是兼容期适配层；收益是避免跨集误写、历史定位丢失与重复付费。旧任务/operation/binding 原关联整体保留，读取视图派生新 target，不单改 projectId。写入采用可跨连接传递的明确 expectedContext 与原有鉴权，不引入与单请求 CLI冲突的连接绑定令牌；缺少代际证明不无条件可写，客户端也不自动刷新旧意图。只读回执查询继续兼容。运行时租约、grant和进程不迁移，旧 checkpoint 不跨新代际执行回退。

## 决策四：旧设置固定，新集显式继承

旧分集保存原独立 settings，缺失仍按原应用兜底；新集默认项目继承并可显式覆盖/清除。旧集改继承需展示差异并由用户选择，不能把结构升级变成画风/模型默认值更新。

## 决策五：冻结旧源、分批暂存、单一权威激活

升级前准备可读回备份和独占屏障；数据库升级仅加表/索引，转换通过可续接 ledger 分批完成，核对后事务切换 activeDataModel/generation。不采用长期双写或运行时缺项回读旧表。

旧源和异常材料保留，只读隔离不等于成功迁移；备份不足和恢复未验证阻止上线。pollManager 的 localStorage 媒体回执亦需冻结、备份和版本适配，不能只覆盖 IDB。新写入后回滚必须说明丢失范围。旧二进制不能直接打开更高 IDB 版本，保留旧表不代表可无损降级。

旧 IDB连接关闭不代表旧实例停止写 localStorage，必须有可验证的全 profile 停写证据。回滚仅回退所选作品内容，真实付费提交、幂等绑定、预算及不确定状态单调保留；恢复有独立 journal，局部恢复不能切换全局 generation。活动文件重定位不得原地改写冻结源/恢复点，素材恢复先核对真实字节和当前目录。

## 决策六：旧修订不可变，新规范显式升版

读取旧 v1/v2/v3 项目包，保留 canonical v1 修订及摘要；新原生格式推荐外层 v4、canonical v2、bundle v2。跨版本比较使用确定性派生视图，迁移修订保留原父链，不把新正文套进旧 hash。v3 仅对能无损投影的情况兼容导出。

代价是协议适配和新旧样本覆盖；收益是离线往返协作的来源、删除语义和恢复点保持可解释。来源不明、基线不完整时继续保守处理。

本机迁移保号、归档新建导入换本机号、独立复制换 lineage、已有目标更新保号分别定义。导出以同事务捕获和实际发布回执为准，所有旧导入/复制路径统一到新仓储。历史来源去重不依赖可变 owner；v4 明确已删目标的不可执行历史绑定，保证删集后仍可带历史往返。

## 评审与执行边界

普通业务仍使用正式 DB v27 与 v3 项目包，迁移／恢复应用和自动入口固定关闭。新语义只对已核对的 fixture business session 开放；接管标记继续阻止 P2 续接／撤销。Agent、MCP/CLI、多窗口及原生能力保留明确上下文和迟到写入保护；旧 ID、幂等键、预算和费用不重算。默认 DB27 执行仓储拒绝 generation>0 请求，不能把 fixture 身份写入正式旧库。

P5 已实现隔离归档及恢复准备，P6 正推进隔离故障与原生归档容器演练，P7 正盘点旧调用；这些不等于正式 Store/UI、Agent/MCP 仓储与 v4 收发已经接线或验收。旧 v1～v3 校验、备份和审计材料继续保留；阶段范围、实际验证、失败恢复和验收入口见主方案第 20～22 节。
