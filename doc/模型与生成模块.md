# 模型与生成

负责模型目录、厂商协议、图片/视频/音频生成及工作流适配。生成成功、取消、产物保存是需要分别处理的状态。

## 关键边界

- 节点提示词栏的模型胶囊通过 × 清除模型、厂商和工作流绑定；`BaseNodeData.model = ''` 表示主动清除，不回填历史偏好或项目默认模型，重新选择后恢复生成。清除走 Store Action，可撤销；桌面端的清除、重选和撤销行为待用户验收。
- AI 镜头预演复用文本/VLM 协议，处理显式分镜表与图片引用，模型产出为白名单 JSON 场景；节点成功后保存预演引用，不生成普通文本输出。项目文件、场景与截图/视频边界归[导演模块](./导演台与Blender模块.md)。
- 火山方舟图片/视频节点的桌面用量通过 [volcengineBillingService.ts](../src/services/billing/volcengineBillingService.ts) 与 [volcenginePricing.ts](../src/services/billing/volcenginePricing.ts) 保存调用与价格快照，由原生 SQLite 管理；查询和 Excel 导出位于方舟连接专属设置。估算、核算、Usage 与未知金额分别标记，不声称等于官方账单。Web 模式和对话直接生成不纳入当前账本，价格目录、迁移及待验收项见[账本计划](./plans/2026-09-26-火山方舟节点计费系统设计.md)。

- 对话生成走统一入口；节点生成沿用节点/生成服务，不能声称所有入口已统一迁移。
- 打包桌面端连接本机 ComfyUI 时通过原生 HTTP 查询队列，显示不确定进度，避免 `tauri.localhost` 的 WebSocket Origin 被 ComfyUI 拒绝；浏览器开发模式和其他地址仍使用 WebSocket 显示实时采样百分比。生成提交及结果判定继续使用原有 HTTP 流程。
- 工作流与厂商模型 API 使用各自适配协议；鉴权、上传、轮询和解析不散落在节点组件中。
- 自定义连接的图片模型在各自的调用协议设置中选择 GPT-Image 中转站 JSON、OpenAI 官方 Images、Google 原生图片或 xAI 原生文生图；不兼容时编辑高级自定义 JSON。图片与文本模型不展示复杂协议表单。短暂提供的连接级图片默认值只在编辑旧连接时复制到已选图片模型，不继续作为运行时隐式默认值。范围、验证和回滚见[图片调用协议选择计划](./plans/2026-09-23-image-protocol-selection.md)。
- 自定义连接的文本模型可单独选择 OpenAI Chat、Anthropic Messages 或 Gemini 原生对话；后两者复用 `chatApiProtocol.ts` 的非流式与流式适配器，未单独选择时继承连接级对话协议。高级自定义 JSON 仍可处理其他接口。
- 自定义协议的表单与 JSON 共用示例变量、脱敏请求预览、响应路径校验和 AI 配置说明复制入口；草稿或子表单无效时禁止试跑，执行前重新解析当前草稿。异步接口可用 `poll.response.result.download` 在轮询成功后按提交任务 ID 发起同源 GET 下载；与响应结果映射互斥，鉴权仅运行时注入，恢复描述只保存绑定任务的请求。下载失败或取消不重提生成。配置与验证见[自定义模型协议计划](./plans/2026-07-19-custom-model-execution-protocol.md#2026-10-07试跑一致性json-预览与任务结果下载)。
- 参考图按已声明协议传输：标准 `edits-multipart` 直接读取原图，不先上传第三方图床；高级自定义协议优先保留自身路径、字段和响应/轮询映射，multipart 的 `$file` 图片引用转换为受限 data URL 后编码为文件。`$file` 可接收数组并按原字段名提交多个文件；请求预览逐文件脱敏。APIMart 继续使用自身上传服务，未确认支持 multipart 的厂商不自动切换或失败后重提生成。
- 内置图片合同由 `resolveBuiltInImageRequestContract` 统一选择：CCC 目录中声明 `edits-multipart` 的图片模型使用 OpenAI Images；GRSAI 文档列出的 Nano Banana / GPT Image 使用原生 JSON。已确认合同执行时优先于旧 Provider、旧通用模型保存的参考图模式或 `executionProfile`；不迁移持久化配置。其他厂商、自定义连接、未收录模型与工作流保持原协议优先级，未知厂商不按模型名称猜协议。multipart 和 data URL 请求中的提示词参考图优先使用本地素材，不复用生成结果的远程 sourceUrl。自定义协议缺少参考图映射时仍在本地拦截。
- 参考图压缩复用 `prepareReferenceImageUpload`：标准 multipart、GRSAI/自定义 Base64、自定义文件表单、APIMart/通用图床、RunningHub 图片及工作流内联图片均接入。直接交给服务商读取的公网 URL 不额外下载转存；有效上传缓存继续复用，视频/音频保持原处理方式。
- 连线及 `@` 引用有本地副本的媒体时优先使用本地素材，不让生成结果的旧 `sourceUrl` 绕过上传缓存；需要公网 URL 的接口复用现有 2.5 小时上传缓存，到期重新上传，multipart 和内联接口沿用各自传输方式。只有公网地址的素材仍直传。验证入口：`generateVideo.test.ts`、`referenceImageTransport.test.ts`。
- 共享预处理先读取图片头：JPEG、静态 PNG、静态 WebP 的最长边达到 3840 px 时等比缩到 2048 px，再按透明像素输出 PNG 或 JPEG；不放大小图，超过 2400 万像素的超大源图仍保留原字节。未达到 4K 的图片继续沿用原规则：只有超过 4 MiB 的 8 位 RGB/RGBA 静态 PNG 才尝试 JPEG（质量参数 0.95），保留像素尺寸且体积减少超过 20% 才采用。RGBA / tRNS 按像素检测，存在任何真实透明像素就保留原图；动画、索引色、其他格式或解码失败也保留原字节。只改变临时上传副本，JPEG 转换属于有损压缩，不能将质量参数解释为保真百分比。
- 图片数组最多同时准备 2 项、全局一次解码压缩 1 张；按原下标回填，任何读取失败均中止该组，不过滤失败项造成参考编号错位。取消排队立即返回，仍在运行的浏览器编码结束并释放位图/画布后才释放解码槽。Base64 原图读取受既有 32 MiB 内存预算约束，压缩后仍执行单图 8 MiB、最多 6 张、合计 24 MiB 限制；媒体工作流保留自身预算。
- 自定义 multipart 图片的文件 MIME 和扩展名跟随实际 data URL 类型，覆盖模板遗留的 PNG 标记；预览与实际请求保持一致，路径、字段名和响应协议不变。标准图片网络提交失败或 HTTP 504 显示实际模型、参考图数量、提交体积及等待时间；原生错误只保留类别与系统错误码，不泄露 URL 参数。结果不确定时不自动重提生成。
- 自定义接口文档导入支持带引号的 cURL `-F` / `--form` 图片文件参数及 `--form-string` 文本参数，保存识别出的参考图模式；单个 `image` 映射第一张，`image[]`、复数字段或同名重复文件字段映射全部参考图。示例文件路径不读取、不保留；未知文件字段或无法解析的表单语法明确拒绝并提示手动配置。验证入口：`modelProtocolImport.test.ts`、`modelProtocol.test.ts`、`modelRequestTransport.test.ts`。
- Seedance 2.0/2.5 的分辨率、比例、时长、参考素材与操作级约束集中在 `seedanceModelCapabilities.ts`；火山直连和中转站只在共享语义上叠加各自已确认的字段、路径和响应映射，不能因为模型同名就共用请求体。普通连线图片、普通 `@` 图片及无角色的旧图片数组始终作为参考图，只有用户明确指定 `first_frame` / `last_frame` 时才填入首尾帧字段或进入首尾帧模式。火山 2.5 的首尾帧及视频编辑按官方约束收敛为自适应比例，视频编辑只允许自动时长；APIMart 2.5 按当前文档开放 480p/720p/1080p 和 `-1` 自动时长，保留 5 秒默认值和自身任务协议，其视频参考与编辑由素材及提示词判定，不把全部视频参考强制变为自动时长。
- 自定义视频模型可在“视频参数能力”中显式应用“Seedance 版本 + 火山原生/APIMart/Lec”快速模板，一次写入能力与提交/轮询协议。手动新增视频模型后自动定位调用协议；未配置协议时默认进入“高级自定义 JSON”的 JSON 页，已有协议保持原配置，工作流编辑方式不变。JSON 标题旁的 SD2.0、SD2.5、H3 按钮明确使用 APIMart 兼容模板，替换当前草稿并应用对应视频能力，保留当前模型 ID；参考图/首尾帧、参考视频和音频按各自模板映射，不自动提交生成。模型目录、手动添加、对话助手和 MCP 共用同一自动匹配器：精确模型 ID 覆盖优先于已验证网关协议，已有手工能力、协议和非视频分类不覆盖；未知网关只补官方家族能力，不猜请求协议。助手与 MCP 通过 `provider_config_preview` 的可选 `templateId` 生成任务级草稿，再由既有 `provider_config_apply`、Policy 和审计链写入。火山模板使用 `content` 类型数组，APIMart 模板使用 `prompt`、`size`、`image_with_roles` 等中转字段，Lec 使用 `/v1/videos` 任务协议并按已核验线路限制参考素材。预设按钮及默认页签回归见 `modelProtocolEditor.test.tsx`、`modelProtocolEditorInteractions.test.tsx`。
- MiniMax H3/H3-Max 的公共能力与 MiniMax 官方、APIMart、AI Ping 三种传输模板集中在 `h3ModelCapabilities.ts`。设置页、手动添加、目录同步、助手与 MCP 共用同一识别逻辑：普通 H3/H3-Max 在已验证网关补齐能力和协议，未知中转只补能力，已有手工字段不覆盖。RunningHub 继续使用 operation 级标准模型适配器，AutoDL/ComfyUI 继续使用工作流模板，不与云 API 请求体混用。Context-IR 返回文本，Regeneration 依赖源任务，APIMart 新目录和默认视频选择器不再将二者展示为普通视频生成模型；旧配置的底层执行兼容保留。AI派、MetaSo 所需的轮询成功后二次二进制下载尚未进入声明式协议，本阶段不提供不完整模板。实施与回滚见 [H3 快速适配计划](./plans/2026-09-22-h3-quick-adaptation.md)。
- 首尾帧角色的界面与请求保持一致：已指定角色的连线图片按 URL 去重，不重复计为普通参考图；RunningHub 字段角色由字段名优先识别，表单与执行器共用判断。即梦普通图片（包括单图）走全模态参考并保留比例，单独首帧或一组首尾帧走对应命令；仅尾帧及首尾帧混用其他素材在提交前拒绝，避免丢失角色。回归入口：`videoParamSelectorProtocol.test.ts`、`runninghubMedia.test.ts`、`dreaminaService.test.ts`。
- 取消需要贯穿提交、轮询和回填。模型已生成但保存失败时，应报告保存状态，不能把再次生成当作保存重试。
- API Key 由凭据服务管理，运行记录不携带密钥。工具审批归[Agent Policy](./对话助手-Agent能力实施方案.md)，不由 Provider 改写。
- 火山方舟虚拟人像库配置位于「编辑火山方舟连接」弹窗中，连接信息下方、启用模型上方，是独立的可选配置，不复用模型 API Key；项目名称默认 `default`。AK、SK 只经 Rust `secret_store` 保存，项目名称与区域等非敏感字段保存在厂商配置中。资产管理入口仍位于资产侧栏的「方舟素材库」页。请求集中在 [volcengineAssetLibrary.ts](../src/services/ai/providers/volcengineAssetLibrary.ts)。由于方舟文档页面的 schema 需要登录后动态加载，当前适配器的签名、路径、字段和 multipart 上传合同在真实接入前必须以官方 OpenAPI/SDK 再校准；不得根据当前 UI 结构推断生产接口字段。
- 火山方舟虚拟人像采用“角色绑定、节点无感使用”方案：角色编辑弹窗可选绑定一个通过真人面部审核的方舟视觉 Asset ID，项目名默认 `default`；视频节点仍只选择普通角色，生成前仅当 Provider 为火山方舟、模型为 Seedance 2.0/2.5、视觉资产为 `Active` 且项目一致时自动改用 `asset://<Asset ID>`，否则回退现有普通参考图流程。角色声音继续使用现有角色声音片段、普通音频或模型音频能力，不绑定方舟 Audio Asset ID。绑定数据只保存视觉 Asset ID、名称、状态和项目名，不保存 AK/SK。用户不直接选择虚拟人像素材，也不需要手写 Asset ID。旧版节点中的直接方舟素材引用保留读取兼容，但新入口不再提供。

## 帧动画节点

- [AnimationNode.tsx](../src/components/nodes/AnimationNode.tsx) 统一显示为「帧动画」，单击选中、双击打开懒加载编辑弹窗；生成通过按钮或空格键进入。编辑页复用 UI Kit 与深浅主题，采用大预览、右侧参数和底部帧序列；支持原图导入、宫格校正、帧排序/停用、像素偏移、帧率和循环控制。编辑器内快捷键不操作背后的画布。原图格数/动作保存为独立快照，不随下一次生成参数变化；应用编辑和导入可撤销。
- [animationPrompt.ts](../src/services/ai/animationPrompt.ts) 为单节点和批量生成共享提示词：明确身份图/动作图职责，固定朝向、比例、非对称细节、隐形中心轴与安全区。提示词不能保证每帧像素一致。
- [sprite_processing.rs](../src-tauri/src/media/sprite_processing.rs) 使用 Rust 完成绿/品红底色清理、软边去色、透明沟槽分帧、脚部/全体 Alpha 质心对齐和共同缩放；缩放后重新计算锚点，统一脚底线。跳跃默认保留纵向轨迹，可逐帧修正武器等造成的质心偏差。
- 原图只读；处理参数与编排持久化，预览只使用短期 Blob。导入/生成结果经过项目和画布派生守卫；关闭编辑器丢弃待返回的导入结果。原生命令复用调用方和路径授权，限制输入体积、像素及帧数。
- [sprite_export.rs](../src-tauri/src/media/sprite_export.rs) 与预览使用相同处理和帧编排，导出 GIF、PNG 序列帧或 PNG 图集 + JSON；JSON 包含绝对帧矩形、fps、loop、durations_ms。逐一授权派生文件，拒绝覆盖已有文件，失败清理本轮新文件。
- 不依赖 Python，不新增依赖或数据库版本。仅移植上述图像流程；视频转循环、RIFE、场景合成未接入。参考、验证与回滚见[专项计划](./plans/2026-10-07-animation-node-rust.md)。

## 配置与运行状态

API Key 列表中所有 CCC 连接只显示一张「CCC API」卡片，汇总已配置分组与启用模型数量；打开后在同一页管理各组，复制已保存配置与删除连接放在各组内部。节点及对话媒体目录也共用一个 CCC API 分组，同名模型仍标注所属组并保留独立引用。删除成功后清除该组编辑草稿，常驻组恢复空白输入，后续「保存全部分组」不会恢复已删连接；其他组的未保存编辑保留。

CCC 在同一设置页同时展示全部分组，每组独立填写 Key、勾选和拉取模型；不需要切换分组，也不会因编辑其他组丢失 Key 或选择。保存全部分组时通过既有 Store Action 同步各连接的模型身份，再一次提交配置与凭据。已存在分组复用连接 ID，旧连接、重复分组及未知分组保留原身份。各组仍通过独立 `providerConfigId` 使用 Rust `secret_store` 中的 Key，节点与对话选择模型后自动路由，无需在调用时切换设置；同名模型保留组标签。新分组保存 CCC 默认地址，读取旧配置时补齐缺失地址；文本、反推与对话解析缺省地址时沿用内置厂商定义，自定义地址优先，Key 始终只取当前连接。分组表与候选筛选位于 [cccProviderGroups.ts](../src/services/ai/cccProviderGroups.ts)，预置目录不表示 Key 权限已验证；拉取后只保留当前 Key 返回且匹配分组的条目。单组改 Key 或拉取失败不影响其他组，过期请求丢弃，保存失败保留全部编辑内容供重试。空白分组始终可见，仅填写 Key 或选择模型后才保存对应连接；待补 Key 的连接仍可重新编辑，分享不携带凭据。范围、验证与回滚见[模型目录计划](./plans/2026-07-19-provider-model-catalog.md#2026-10-07ccc-分组连接)。

项目设置的图片、视频、音频默认模型支持按类型选择已导入的 ComfyUI 工作流，保存为 `comfyui/<工作流 ID>`；新节点继承时转换为执行模型及 `workflowId`，无模型节点的快捷生成也传递该绑定。设置页允许离线配置，已删除的选择沿用不可选的「已隐藏」提示；文本与视觉理解不提供工作流选项。沿用节点已有模型优先的生成规则，回归入口：`projectSettingsService.test.ts`、`generationProjectDefaults.test.ts`。

本次默认工作流验证：项目设置、节点生成、视频比例、风格参考和分镜生成的 5 个测试文件共 40 项通过，前端/测试类型与定向 ESLint 通过；未执行桌面视觉验收或真实 ComfyUI 调用。

用户配置见[说明书：自定义接口](../site/manual.html#connection)和[本地与云端工作流](../site/manual.html#comfy)。厂商模型、RunningHub 工作流和通用工作流 API 的 Key、参数与恢复状态分别处理，不能互相套用。

模型选择器的工作流分组默认收起，无可用条目时整体隐藏。ComfyUI 工作流按实际绑定地址探测 `/system_stats`，仅展示在线服务对应的条目；未绑定或服务器已删除时沿用默认地址回落。打开菜单立即检测，打开期间每 10 秒刷新，关闭后取消检测；RunningHub 与工作流 API 不受 ComfyUI 在线状态影响，已有节点选择不因暂时离线被清空。验证入口：`modelSelectorWorkflows.test.tsx`、`comfyServerBinding.test.ts`。

ComfyUI 提交前只绕过能够确认的空可选媒体分支；必填或未知结构交由原工作流校验。视频节点未设置秒数或旧帧数时使用 5 秒默认值，旧帧数兼容换算。实时百分比属于当前执行节点，任务完成仍需查询输出并保存成功；具体注入和回退规则见[ComfyUI 集成](./ComfyUI工作流集成说明.md)。

ComfyUI 结果交付要求 history 终态；视频只接受真实视频扩展名，不把预览 PNG 当成成片。默认保留服务缓存；设置页提供显存状态和服务级手动释放，自动卸载或完全释放需显式选择、只对本机回环地址生效，并在队列非空时跳过。释放 history 不等于释放显存，项目不把二者混用。
