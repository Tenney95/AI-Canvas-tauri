## 媒体提交失败与状态未知

CCC、声明式协议（ToAPIs／LibAPI／万象／自定义接口）、APIMart、GRSAI 与 RunningHub 模型入口共用有限的 HTTP 失败分类。提交返回明确请求拒绝或已确认任务 `failed` 时，清理该次完整回执，显示普通生成失败及已脱敏原因；批次仍有可恢复子任务时保留它们。HTTP 200 的已知结构化拒绝也可识别，但不全局猜测任意数字业务码，不用结果旁的附加错误字段覆盖有效结果或任务身份。APIMart 语音返回的 JSON 错误不能作为音频文件交付。

HTTP 408／504、断网、响应丢失或无充分失败证据的服务端异常仍为状态未知；已有任务 ID 后，查询接口的 401／429／5xx 不等同于任务失败，原任务继续保留。未知／暂停界面补充固定 HTTP、超时或网络原因，持久化只保留有限分类与整数状态码，不保存原始异常、响应或 Key。继续查询／保存从不重新提交生成，旧未知任务也不会仅凭平台截图自动改为失败。

失败清理绑定项目、节点、任务与尝试身份。等待期间切项目时，仅保留有限终态标记；切回后投影为普通失败，再清理记录，不将仍为 loading 的原节点误判为提交未知。原对话的失败先按会话和消息身份持久化；存储失败保留终态记录，不发起查询或生成。同组子节点若已有独立新任务或活动操作，不接收旧批次的失败投影。

## 单图模型的画布批量生成

`supportsBatch/maxBatchCount` 描述单次接口数量，不能据此禁用画布创建多个图片节点。普通通用图片模型明确单次只支持一张时，长按发送仍可选择 1/2/4/8 张；共享生成服务先创建目标节点，再按节点 ID 串行执行，每次传单张数量并独立保存产物、历史和任务回执。万象 `Image-2.5-Flare` 保持原有同步协议和固定 `n:1`，不把用户总张数传给其单次接口；原生多图模型继续使用既有数量上限，ComfyUI、RunningHub 和其他云工作流仍由自己的参数和任务流程决定数量。

批次 owner 与取消信号仅存内存，并绑定原项目和各目标节点；源节点首张完成后，节点弹窗与共享生成服务仍识别整批运行状态，防止重复提交。用户停止、项目切换、目标删除、输入变更或任一张失败／状态不确定时，不再提交下一张；已提交任务保留原节点身份供继续查询或保存，不自动重投。图片提示词、项目风格、相机设置与素材引用沿用同一单节点执行路径。本次未调整 `batchExecute.ts` 独立的全局批量执行入口，其普通图片路径仍沿用原调度。

## 生成结果的鉴权下载与续存

生成结果若指向厂商同源受保护的媒体地址，不能按公开链接下载。声明式媒体协议及已明确采用 Bearer 的标准接口在结果中传递无密钥的 `mediaDownloadAccess`，绑定真实连接 ID、原始 origin 和协议鉴权方式；保存时才读取原连接当前 Key。同源另一分组不共享凭据，连接删除或 origin 变化时停止交付。外部 CDN／签名 URL 不附厂商 Key；原生流式下载跨源跳转后永久剥离显式请求头及查询鉴权，拒绝 userinfo 与 HTTPS 降级，不通过 GitHub 镜像转发凭据。

万象视频已有的 `/v1/videos/{id}/content` 结果按原查询协议与连接恢复，不重提生成。Image 2.0／2.5 补充官方文档声明的 Base64 结果路径，仅完整命中旧内置合同才使用兼容更新，用户修改的协议不覆盖。尚无失败图片实际响应，不能把所有 2.5 下载问题都归因于鉴权。

同步接口已返回 HTTP(S) 结果后也保存交付记录，使用本地 `result-` 身份区分远端任务；恢复只下载该结果，不发生成或任务查询请求。记录不保存 Key、运行时请求头或 Base64 正文。异步任务继续查询原任务，允许平台刷新过期结果链接。历史未保留的同步结果、过期且无法刷新的链接、内联二进制的跨重启恢复不能凭空取回。

## 中转接口的执行与交付边界

声明式协议在同步／异步提交、任务查询、业务失败和同源结果下载时，先移除错误文案中当前连接 Key 的原文、URI 编码及实际查询参数使用的表单编码，再创建异常；HTTP 200 响应验证器抛出的业务错误同样处理，HTTP 状态、重试间隔和任务失败类型保持可识别，不携带原始 cause／堆栈。标准兼容图片接口的 JSON、multipart 和 CCC 出口复用同一处理，节点、历史和对话不接收这些已覆盖路径中的凭据回显。

桌面原生 HTTP 的流式、非流式和图片下载共用重定向策略：只有无显式请求头、无查询参数、无 URL 凭据、无请求体的 GET／HEAD 允许受控跨源跳转；其他请求仅允许同 origin，禁止 HTTPS 降级、跳转目标携带 URL 凭据和超过 10 次跳转，不自动发送 Referer。带 `Accept`、`Range` 等显式头或签名查询的跨源跳转也会被拒绝，需要配置最终资源地址；这些字段同样可能被自定义协议用作鉴权，不能仅按字段名推测为公共下载。

LibAPI 完整匹配内置合同的首尾帧在编译提示词前统一排序，图片数组、`@` 编号及角色说明使用同一顺序；用户修改的 LibAPI 协议和普通自定义协议保留原顺序。媒体续取的新查询接入调用方停止信号；等待他人已发起的共享恢复时，仅停止自己的等待。取消保留原任务身份，不重新提交生成；已开始且不可取消的文件保存可能完成，但迟到结果不得更新消息／画布或确认交付。

真实声明式生成及原任务续取，在交付前复用试跑的结果类别校验。视频／图片接口返回 HTTP 200 的 JSON 错误体或错误类别的内联 MIME 时，不能落盘后标记成功；已有异步任务保留原 ID 和执行身份，不为错误结果重新提交生成。

## 高级快捷指令生成流程

## 图片生成质量与背景

图片参数弹层把分辨率 `imageSize` 与生成质量 `imageQuality` 分开。质量选项来自当前连接和精确型号的 `qualities/defaultQuality`，不按 GPT 同名模型跨渠道继承；未声明质量或默认值时省略请求字段，不把第一个候选值当作默认。单张、批量、快捷生成及重新生成透传同一质量，生成历史记录该参数。RunningHub 继续使用自己的参数 schema，不增加重复控件。

CCC／APIMart 已确认的 GPT Image 2.5 Flare、Sunburst 为六档；GRSAI Flare 为三档、Sunburst 为五档；ToAPIs 普通 2.5 固定 high，VIP／official 为六档。其他型号逐项声明。CCC 的旧 `gpt-image-2.5` 别名、APIMart 无后缀旧型号及未公布 quality 的型号不推测支持。自定义接口可声明质量和默认值，多档必须在协议中映射 `{{imageQuality}}`；原来的 `quality → imageSize` 自动识别已改为独立质量变量。用户的固定值协议保持固定，ToAPIs 仅完整匹配已知旧内置模板时在执行中使用更新合同，不改写保存数据。

图片背景使用独立的 `imageBackground` 与逐渠道、精确型号的 `backgrounds/defaultBackground` 声明。未声明时不显示控件、不发送背景字段；内置型号默认省略，由用户选择「透明」后发送 `background: "transparent"`。CCC／APIMart 的 2.5 Flare、Sunburst 可选 auto／opaque／transparent；GRSAI 的这两个型号及 ToAPIs 2.5 普通／VIP／official 仅启用文档明确的 transparent，另提供「接口默认」。不为旧别名、APIMart Ext 或 GRSAI 基础 2.5 推测能力。透明输出时 CCC／APIMart 标准合同请求 PNG；GRSAI／ToAPIs 不增加未公布的格式字段。

背景参数贯通节点、单张、批量、快捷生成、重新生成、历史和最近参数；切模型只更新背景适用值，继续保留用户比例及节点尺寸。自定义协议使用 `{{imageBackground}}`，声明可选背景时须有相应动态映射，固定同值合同可保留；显式 JPEG 与透明能力冲突时拒绝。节点的「接口默认」以空字符串表示明确省略，覆盖用户自定义的背景默认值，生成历史只记录实际有效值。ToAPIs 兼容更新只接受完整匹配的旧内置协议，不修改保存数据。结果沿用原始字节下载／落盘，不铺底或转换 JPEG；RunningHub 保留原参数表，不增加重复控件。分辨率、质量与背景三组共用 UI Kit 的 `ui-segmented--brand` 品牌色选中态，预览在「选择控件」。

## 异步媒体查询与交付恢复

图片、视频、音频的异步生成沿用 `pollManager` 保存真实任务身份。取得结果 URL 后进入待交付阶段，本地保存及 Store 回填都成功才按项目、任务 ID 和执行回执清理；断网、查询超时、结果下载或保存失败保留原任务，节点与提示词窗口可继续查询／保存。再次生成前保留未交付旧任务到独立恢复节点；没有拿到 ID 的提交中断显示状态未知，不自动重投。批量仅交付原任务产物，明确失败与暂未查询成功分别处理，不按缺图数量重发生成。

任务查询的单次期限覆盖响应正文读取，并传递取消信号；普通文本流与同步生成不套用该期限。结果保存及恢复回填保留画布派生守卫，旧回执不能结束新任务。主窗口对话绑定原消息及项目，MCP 通过 `media_pending_tasks` 查看脱敏任务身份、`media_resume_task` 续取原任务；独立对话窗口仍回主窗口处理。凭据仅在执行时从对应连接读取。

RunningHub、工作流 API 与 ComfyUI 的专用提交和取消流程保持原边界；本批补齐已有 ComfyUI 任务的对话交付恢复，不改其首轮提交服务。RunningHub／工作流 API 的纯消息任务仍依赖重开原项目和会话后的专用恢复，尚未接入通用手动恢复按钮，通用 MCP 不将它们标为可直接续查。没有留下任务记录的 ComfyUI 中断、以及不返回远端 ID 的同步接口，不能据此声称可续查。

实现入口：`pollTask.ts`、`pollManager.ts`、`MediaTaskStatus.tsx`、`generationRuntime.ts` 及厂商生成适配器。2026-10-23 复核的 21 个相关测试文件、680 项用例、本批定向 ESLint 与应用类型检查通过；测试类型检查仍受另一并发任务的两处 props 断言错误阻断。未运行构建、桌面验收或付费调用，待用户验收。范围、复核修复、回滚和桌面步骤见[异步媒体交付恢复计划](./plans/2026-10-23-async-media-delivery-recovery.md)，早期视频方案见[视频轮询恢复计划](./plans/2026-10-13-video-polling-recovery.md)。

- 原生命令只接受受信主窗口的内存字节，不接受文件路径；PNG／JPEG 共用单并发槽，限制输入 32 MiB、2400 万像素与最大边 16384。PNG 另限制 4096 个块、检查解压规模并使用协作式优化时间预算；JPEG 限制扫描次数与内部缓冲，但不承诺硬超时或进程 RSS 上限。取消等待后原生工作仍持有槽，直到实际结束。APIMart 对上传副本先尝试适用的无损优化，优化后仍超过 20,000,000 字节则在上传前报错，不静默改成有损图或缩小尺寸。JPEG 通过 bundled 源码静态链接，编译期需要 CMake，应用运行时不依赖系统 JPEG 库或 CMake。
- 图片数组最多同时准备 2 项，按原下标回填，任何读取失败均中止该组，不过滤失败项造成参考编号错位。Base64 原图读取受既有 32 MiB 字节预算约束，准备后仍执行单图 8 MiB、最多 6 张、合计 24 MiB 限制；媒体工作流保留自身预算。回归入口：`referenceImageUpload.test.ts`、`referenceImageTransport.test.ts`、`runninghubClient.test.ts`；Rust 在 `src-tauri/` 执行 `cargo test reference_image_upload --lib` 和 `cargo check --lib`。桌面需分别检查 4K PNG／JPEG、透明 PNG、EXIF 方向／ICC、动画、无压缩收益、仍超 20 MB 和取消，预期保持格式与尺寸，超限不发送上传或生成请求。
