## 关键边界

- 三种运行时共用导演节点的选择、历史、持久化与下游媒体语义；各自维护场景，不能互相冒充。旧节点仍默认轻量网页。轻量导演台与 Blender 始终隐藏节点浮动对话框，切换到这两种运行时时立即关闭；只有 AI 镜头预演显示该输入框。
- `ai-threejs` 为主窗口的「AI 镜头预演」弹窗，复用已配置文本模型。模型只能生成有界 JSON，不能提供 JS、网页、URL、脚本或原生命令。Y-up 米制简模与 position/target/焦距/横滚关键帧支持 1–60 秒预演、人物走位、分段缓动和三种画幅；不声明物理模拟或自动避障。
- 预演阴影按物体全程运动与地面投影范围固定拟合，不随摄影机移动；旋转物体用包围球覆盖中间姿态。贴图最多 2048 并按显卡上限回退，采用有界法线偏移减少自阴影条纹；静态场景复用阴影贴图，辅助标记不投影。预览、截图和视频共用此设置。
- AI 预演可由节点浮动输入框直接生成，也可在弹窗内通过同一 MentionEditor 输入 `@` 或点击连线素材引用；仅连线不发送。整表逐行包含镜号、景别、运镜、内容、台词、时长、音效/音乐、转场、备注与绑定画面。图片走既有受限 Base64 文本/VLM 协议，需支持视觉输入的模型，最多 6 张、单张 8 MiB、合计 24 MiB。节点生成使用所选或项目默认文本模型，成功保存为预演引用，不生成普通文本输出。
- 两个生成入口共享节点加载状态、重复请求保护与取消；修改已有场景时先校验并载入当前场景。项目、实例、运行时、场景引用、提示词、模型或显式引用的节点/画面变化后不发布结果；失败保留上一场景。浮动输入框关闭后允许后台生成，弹窗发起的操作在弹窗关闭时取消；控制器只在内存。
- 预演使用独立合同和 `directorPrevisScene`，不覆盖 Blender Scene/Manifest。场景保存在 `director/previs/<SHA-256>.json`，节点只保存项目相对引用、摘要与大小；读取验证摘要、字节数与合同。文件保留到项目删除，支持撤销、重开、复制及整体导入导出。
- 预演生成/保存/媒体回写绑定项目、节点实例、运行时、场景引用与画布派生守卫。弹窗关闭会取消其发起的操作，上下文变化使在途结果失效；失败保留上一场景。截图与 24fps MP4 只渲染摄影机视角，空间辅助轨迹不进入输出；编码失败显式报错。MP4 使用高画质码率模式兼容 WebKit，导出成功后回填导演节点并在右侧创建视频素材节点，共享项目文件、继承分组坐标且只记录一次撤销；失败或结果过期不新增节点。普通运行时帧/视频 RPC 不自动回退，预演输出由面板宿主执行。
- 桌面端的 AI 预演节点已有场景但没有截图时自动补截；场景引用更新后刷新摄影机起始帧，包括 MCP 写入和节点生成。面板打开时暂缓自动截图，手动同步的当前帧保持不变。多个节点排队渲染并立即释放 WebGL，复用输出保存与派生守卫；失败保留旧图并提示手动重试，不自动调用模型或导出视频。
- MCP 可用 `director_get_previs_schema` 读取合同和完整示例，由外部大模型生成白名单场景 JSON；通过已有 `canvas_create_nodes` 创建 `ai-director`（或查询已有节点），`director_set_runtime` 选择 `ai-threejs`，再以 `director_set_previs_scene` 写入完整 `sceneJson` 字符串。`director_get_previs_scene` 返回已保存场景，未保存时为 `null`；修改前可读回场景。场景响应走 MCP 瞬时完整内容，避开模型结果截断，不把原始 JSON 放进消息或任务摘要。用户双击节点即可播放、调整和输出。
- 这三项预演工具只在当前项目的 MCP 控制会话开放；两项读取为 `read`，写入为 `canvas_write`，复用 Registry/Policy 与预演写回守卫。MCP 自主执行，无需逐次审批；不额外调用应用内模型，不执行外部 JS，不自动重试写入。场景写入后的截图由节点自动同步，不额外发起付费媒体生成。
- 网页模式可查看、播放和调整示例，场景与输出的项目文件保存需要 Tauri 桌面端；真实模型/原生存储/编码验收与前端浏览器验证分开记录。
- Blender 固定包 1.5.0 声明 Windows x86_64、macOS x86_64/aarch64 目标，版本策略接受 4.5.x、5.0.x、5.1.x、5.2.x 稳定系列，不锁补丁号；预发行版和未纳入的系列不自动放行。安装还须与应用架构匹配；版本策略不代表 Blender 官方为每个架构提供所有版本。跨平台/版本的真实桌面验收状态见专项计划。
- 唯一安装自动使用；多个安装或未发现时由系统选择器手选。Windows 选择 `blender.exe`，macOS 选择 `.app`，原生仅解析其固定 `Contents/MacOS/Blender`。手选结果只保存在本机原生私有目录；旧安装失效不阻断其他安装发现。macOS 有界扫描系统/用户 Applications、固定 Steam 路径和 PATH，不扫描整盘。
- Windows 使用 Job Object，macOS 使用专属进程组管理正常关闭、取消和超时；均复用固定参数、成果收集与结果校验。macOS 原生窗口、权限与打包验收尚未在真机执行，不能以 Windows 上的应用包/Mach-O 模拟测试替代。
- EEVEE 标识、材质/世界节点初始化和图像/视频设置按 API 差异适配；保存工程保留时间线和 Cycles 选择。前端只映射已绑定 Job 的固定失败码，区分版本、渲染能力、启动、崩溃、超时和成果错误，不展示原生诊断正文。
- Renderer 只提交固定 operation 和已验证场景引用，不提交任意可执行文件、脚本、argv、环境变量或输出路径。
- Blender 进程退出不等于结果成功；先验证文件集合、摘要和 Result Manifest，再检查项目、节点实例、Scene revision 与派生结果守卫后回填。
- 真实 Blender 预览、保存返回、故障注入和界面验收分别记录；历史“预览已接通”不能替代阶段完成标准。

## 白模工作流与提示策略

2026-11-07 根据用户提供的第 7 集白模视频教程的画面与字幕整理：约 02:50–04:35 的人物模型三档选择与精度取舍、05:40–06:10 的路线与局部修改、08:30–09:10 的动作链与分层修正、10:10–10:30 的适用场景与素材分工。采用其中的工作方法，不把示例效果或模型时长当作通用保证。

2026-11-08 已逐段核对完整 10 分 37 秒视频的画面与字幕，补充约 02:00–02:40 的场景搭建、05:30–07:20 的路线/交付/提示结构、07:20–09:50 的画面方位、道具与表演、跨片段连续性。教程中的第三方插件、生成时长与他软件操作不作为本应用功能声明。

- 应用内入口为「使用帮助 → 3D 导演台」，提供运行时选择、白模制作、局部修改与下游成片提示示例。轻量导演台用于手动摆放；AI 预演用于文字生成空间与整体走位；需要关节动作、接触细节或真实多镜头工程时在 Blender 内制作并先保存返回。
- 内置生成与 MCP `director_get_previs_schema` 共用 `buildPrevisGenerationPrompt`。提示词按“空间和主体路线 → 时间段 → 摄影机 → 起中终构图”组织；为人物和关键道具保留稳定身份，修改时锁定未涉及的布局、路线、时长与画幅。
- 白模保留影响轮廓、尺度、接触与遮挡的必要细节，复杂路径、多人站位和连续揭示优先预演；普通近景表演不强制先做白模。不能将“不要过度建模”误写成“越粗糙越好”。

人物模型按需要控制的信息分三档，依据是动作精度与姿态关系，不只是动作幅度；静止但姿态特殊的人物也需要清楚的人形。

| 需要锁定的内容 | 白模选择 | 当前实现边界 |
|---|---|---|
| 站位、队形、粗略路线、入画时机、遮挡 | 圆柱、方块或雪人式极简占位，普通步态可留给视频模型 | 提示词优先选择已有 `cylinder/box`；保持主体身份、尺寸和脚底路线，几何体中心与 `character` 脚底坐标不能直接互抄 |
| 跪地、抬臂、后仰等特定姿态及支撑/受力关系 | 四肢清楚的人形粗模，先摆准膝落点、手腕和躯干关系 | 内置 `character` 四肢固定；静态姿态可由现有独立几何体组成，复杂姿态可在 Blender 实际摆出，不能只改名字冒充姿态已完成 |
| 精准抛接、接触、高难打斗的连续过程 | 骨骼与连续动画，按关键姿态和接触时机调整 | 在 Blender 制作或适配动作素材；Three.js 合同没有骨骼、自动绑定与物理模拟，不能把根位移视为关节动作 |

动作戏若只锁定路线与摄影机，也可继续用极简占位，把具体招式交给下游文字和模型发挥；省去动作制作会牺牲招式与接触控制。细节多、动作僵硬的参考可能把问题带进成片；简化能留出发挥空间，但不能删掉必须确定的姿态。组合人形的部件均使用世界坐标，命名前缀不是运行时父子绑定；整体平移可同步相同位移，转向时独立部件的直线插值不会自动保持关节连接，需增加中间关键帧并逐段预览，不能将端点姿态正确当成连续动作已正确。

- AI 预演仅有一条连续摄影机轨迹。提示词要求整表引用仍读取完整上下文，但优先预演指定镜号；未指定时选首个有效镜头，在场景标题标明镜号，不把多个镜号伪装成瞬移切镜；复杂手部/骨骼动画、物理和自动避障不在当前合同内。
- 固定环境先确定场景图再搭可修改的粗略空间；无固定图可用文字说明门、楼梯、通道及门后空间。单图未展示的部分按路线需要补足，不宣称准确恢复完整建筑；影响通行/遮挡的门框、楼梯和柱廊独立表达，装饰纹理交给成片参考。俯视草图可给主体编号并标路线，引用图片须显式选择且使用视觉文本模型。
- 人物图指定长相服装，场景图指定环境外观，白模视频指定空间与运动。成片提示分为“连续镜头概要 → 实际素材与主体/道具对应 → 分时可见变化”；不带入白模测试场地或额外演示人物。保留明确要求的路线与关键时机，给自然承重、动作反应和相机惯性留出表演空间，不要求机械换皮或逐帧复刻。
- 每段按当前摄影机画面写左右、人物朝向、视线与接触对象，并区分画外声音和入画人物；主体和道具身份固定，场景参考布局须与白模一致。共享生成提示把画面关系换算为世界位置，不因反打换人或重摆空间。
- 道具交接按同一物体身份和素材对应，明确“谁持有 → 离手/飞行 → 接触 → 接住”的时间与新状态；不能因持有者变化复制道具。Three.js 只用已有物体关键帧表示粗略轨迹，不新增持有者/骨骼/绑定字段，也不把轨迹当手指接触和物理精度。
- 白模已经拍清的路径可简写，把成片文字留给动作、受力与可观察表演。例如“嘴角松动 → 下巴轻颤；视线先移开 → 头随后转开并低下；泪沿原湿痕滑落”，比只写“很悲伤”更具体；这属于下游视频提示，不是 AI 简模已有面部表情能力。
- 导演节点的下游参考收集目前只读取截图。传递完整运镜应使用导出后新建的视频素材节点，并选择支持视频参考的模型与模式，核对实际素材引用、画幅、时长和模型限制。截图只表达静态构图；写进提示词不代表不支持的模型会获得视频输入。
- 先检查开场/中间/结束构图，再完整播放连续运动；保留可编辑工程，视频模型使用可播放的渲染视频而不是 `.blend` 工程。场景图、视频参考和输出的画幅/时长需核对，不要求安装教程中的第三方自动导入插件。
- 跨段连续时先在同一 Blender 工程、同一时间线安排场景、人物、道具与摄影机，再按所选模型当前实际限制分段导出、分别生成；核对段末与下一段开头的站位、道具状态、机位和朝向。教程的“30 秒”不写死为通用限制，应用不因此宣称具备自动分段、自动续接或连续性保证。AI 预演仍是单场景合同，不承接 Blender 的工程时间线。
- 按最早出现问题的层修正：空间错误回白模/场景修，动作僵硬检查实际动画并补动作与受力描述，主体混淆检查素材对应与交接时间。先用“两个人、一个空间、一段简单运镜”走通，并选择最易出错的短段做成片试验，再逐步加特殊姿态和复杂动作；AI 视频能否遵循参考仍需实际生成验收。

本轮只调整共享提示词与帮助内容，场景合同、渲染器和原生执行边界沿用现有实现。本次未运行测试，待用户验收。

桌面验收步骤：

1. 在已打开的项目进入「使用帮助 → 3D 导演台」，确认三档模型选择、白模、局部修改和成片示例可读；切换深浅主题及英/日/韩语言，确认说明完整且可滚动。
2. 创建导演节点，选择「AI 镜头预演」与可用文本模型，按帮助示例生成 8 秒走廊镜头；检查起点、转折、终点、人物与相机同步、连续环绕及墙体遮挡。若输入独立多镜分镜表，应只生成指定镜头或标题标明的首个有效镜头。
3. 要求只修改指定时间段的摄影机，检查其他物体身份、路线、片长和画幅是否保留；复杂手部动作不应被描述为已实现的骨骼动画。使用 Blender 时先保存返回，再检查实际导出成果。
4. 导出参考视频，使用旁边的视频素材节点和人物/场景图作为下游实际参考；选择支持视频参考的模型/模式并对齐画幅时长，先确认引用预览再生成。不支持视频参考的模式与只引用导演截图的情况，不应被当作完整运镜已输入；成片效果单独验收。
5. 分别用“仅用圆柱确定人物站位与路线，不做步态”“保持静止，但需明确跪地、抬腕、后仰关系”“精确抛接与手指接触”三种描述核对：第一种应优先几何占位且贴地；第二种要检查实际四肢几何关系，不能仅靠静止圆柱或直立人形代替；第三种不得声称当前 AI 预演已有骨骼或接触精度，应在 Blender 动画中验收。切换人物表示后脚底路线和摄影机注视点应保持。
6. 输入含俯视编号、门后空间和道具交接的场景，完整播放后核对：换视角不串人、同一道具不复制、离手与接手时间连续、未展示区域不被说明成准确复原。下游先试最易出错的短段，检查表演与交接；跨段方案按同一 Blender 工程手动安排、分段导出，核对段末段初状态，不能以帮助文案代替原生保存与实际生成验收。
