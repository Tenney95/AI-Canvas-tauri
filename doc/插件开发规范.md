# AI Canvas 插件开发规范

> 适用宿主版本：AI Canvas `0.9.2`；Plugin API v1<br>
> 最后更新：2026-09-03；插件入口：设置 → 插件 → 导入插件文件夹 / 插件市场

本文档说明如何为 AI Canvas 编写用户插件。当前只有一套 Plugin API v1：节点工具、自定义节点、宿主管理的模型调用、节点/连线/包资源句柄、主窗口隔离弹窗，以及由用户明确授权的可信 Python 运行时都属于同一份首版契约，不存在旧版本兼容分支。

## 1. 当前能力范围

Plugin API v1 支持：

- 在节点右键菜单中注册一个或多个工具；
- 在文本、图片、视频、音频和全景节点的上方工具栏中注册按钮；
- 由宿主根据 Manifest 渲染统一操作弹窗，或在同一主窗口 Modal 内挂载隔离的插件 UI；
- 指定每个工具适用的节点类型；
- 读取 Manifest 中声明的节点顶层字段；
- 返回 JSON 数据更新当前节点；
- 返回 JSON 数据创建派生节点；
- 在独立 QuickJS 沙箱中执行同步 JavaScript。
- 通过本机 Python 3 和当前环境已安装的包执行可信 `main.py` 插件；
- 通过 `contributes.nodes` 注册带字段和输入输出端口的自定义节点；
- 向自定义节点与节点工具提供当前可调用模型的安全目录，并由宿主代为调用模型；
- 在操作弹窗中提供模型下拉，并通过 `model.generate` 把参考图与提示词一起交给多模态模型；
- 通过调用级不透明 `resourceId` 读取当前节点文件、直接输入连线文件和 Manifest 声明的包资源；
- 通过宿主在项目目录创建新的文本输出，不向插件暴露真实路径；
- 从符合发布规范的 GitHub Release 安装插件，并检查稳定版更新。

JavaScript 沙箱当前暂不支持：

- 自定义设置面板或任意挂入宿主 DOM 的 HTML/React；
- 任意网络请求、任意路径文件访问、目录遍历、删除、系统命令或 Tauri API；
- `import`、`require`、第三方 npm 包或多个 JavaScript 文件；
- Promise、`async` 工具或后台任务；
- 获取真实本地路径、跨项目文件、非直接连线文件或修改受保护的资产字段；
- 构造新的远程媒体 URL 交给宿主加载；远程媒体只能从真实媒体输入或本轮宿主媒体模型结果中原样传递。

## 2. 插件目录结构

每个插件是一个独立文件夹。JavaScript 与 Python 插件分别使用以下结构：

```text
my-plugin/
├── manifest.json
├── main.js
├── ui.js                    # 仅声明 manifest.ui 时需要
└── resources/               # 仅放 manifest.resources 声明的包资源
    └── template.txt

my-python-plugin/
├── manifest.json
└── main.py
```

- 文件名区分大小写；
- `manifest.json` 和入口文件必须位于同一级目录；
- 文件夹中必须且只能有一个 `manifest.json`；
- JavaScript 入口固定为 `main.js`；可信 Python 插件固定为 `main.py`；
- `ui.entry` 和 `resources[].path` 必须是插件目录内的安全相对路径并通过字节数与 SHA-256 校验；
- 未在 Manifest 中声明的其他文件不会被插件运行时加载。

## 3. 最小可运行示例

下面的插件会为文本节点增加“输出转大写”右键工具和工具栏按钮。由于工具声明了 `dialog`，两个入口都会在主窗口中打开同一个操作弹窗。

### manifest.json

```json
{
  "apiVersion": 1,
  "id": "com.example.uppercase",
  "name": "文本大写工具",
  "version": "1.0.0",
  "author": "Your Name",
  "description": "把文本节点的输出内容转换为大写",
  "category": "content",
  "keywords": ["文本", "格式化"],
  "entry": "main.js",
  "permissions": ["node.read", "node.write"],
  "contributes": {
    "nodeTools": [
      {
        "id": "uppercase-output",
        "title": "输出转大写",
        "description": "把当前节点的 output 转换为大写",
        "placements": ["node-context-menu", "node-toolbar"],
        "icon": "lucide:case-upper",
        "dialog": {
          "title": "输出转大写",
          "description": "可选填写前缀；确认后插件会处理当前节点输出。",
          "submitLabel": "转换",
          "fields": [
            {
              "id": "prefix",
              "label": "结果前缀",
              "type": "text",
              "placeholder": "例如：标题："
            }
          ]
        },
        "nodeTypes": ["ai-text", "source-text"],
        "inputFields": ["output"],
        "output": {
          "mode": "update-current",
          "fields": ["output"]
        }
      }
    ]
  }
}
```

### main.js

```javascript
definePlugin({
  tools: {
    "uppercase-output": (input) => ({
      data: {
        output: String(input.parameters.prefix || "")
          + String(input.node.data.output || "").toUpperCase()
      },
      message: "已将节点输出转换为大写"
    })
  }
});
```

安装后，在画布中选择 `ai-text` 或 `source-text` 节点，节点上方工具栏会显示插件图标；右键菜单中也会出现“输出转大写”。

## 4. Manifest 顶层字段

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `apiVersion` | number | 是 | 固定为 `1` |
| `runtime` | string | 否 | `javascript`（默认）或 `python` |
| `id` | string | 是 | 插件唯一 ID，建议使用反向域名；仅允许小写字母、数字、点、下划线和短横线，最长 128 字符 |
| `name` | string | 是 | 用户可见名称，最长 80 字符 |
| `version` | string | 是 | 插件版本，最长 32 字符；建议使用语义化版本，如 `1.2.0` |
| `author` | string | 否 | 作者名称，最长 80 字符 |
| `description` | string | 否 | 插件用途说明，最长 240 字符 |
| `repository` | string | GitHub 发布必填 | GitHub HTTPS 仓库地址，格式为 `https://github.com/作者/仓库` |
| `homepage` | string | 否 | 插件主页，必须使用 HTTPS |
| `license` | string | 否 | 开源许可证标识，如 `MIT`、`Apache-2.0` |
| `category` | string | 是 | 插件分类，见下表 |
| `keywords` | string[] | 否 | 1–12 个关键词，每项最长 128 字符 |
| `entry` | string | 是 | JavaScript 固定为 `main.js`；Python 固定为 `main.py` |
| `permissions` | string[] | 是 | 插件权限，见权限章节 |
| `contributes.nodeTools` | object[] | 条件必填 | 插件贡献的节点工具，最多 64 个 |
| `resources` | object[] | 否 | 当前 revision 随包安装的不可变资源，最多 64 项、合计 64 MiB |
| `ui` | object | 否 | 自定义 UI bundle、SHA-256 与导出映射；使用时必须声明 `ui.custom` |
| `contributes.nodes` | object[] | 条件必填 | 自定义节点，最多 32 个；两类贡献至少填写一种 |

### category 可选值

| 值 | 含义 |
|---|---|
| `content` | 文本、提示词、结构化内容处理 |
| `media` | 图片、视频、音频相关的元数据处理 |
| `workflow` | 工作流内容或参数处理 |
| `utility` | 不属于以上分类的通用工具 |

分类用于向用户说明插件用途，不会自动授予额外权限。

## 5. 节点工具声明

`contributes.nodeTools` 中的每一项表示一个节点工具。同一个工具可以同时出现在右键菜单和节点工具栏。

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `id` | string | 是 | 工具在当前插件内的唯一 ID，最长 64 字符；仅允许小写字母、数字、点、下划线和短横线 |
| `title` | string | 是 | 菜单、工具提示和弹窗中的工具名称，最长 80 字符 |
| `description` | string | 否 | 工具用途说明，最长 240 字符 |
| `placements` | string[] | 是 | 可填写 `node-context-menu`、`node-toolbar`，也可同时填写两者 |
| `icon` | string | 工具栏入口必填 | Iconify 图标名，例如 `lucide:wand-sparkles`；不接受 URL、SVG 或 HTML |
| `dialog` | object | 工具栏入口必填 | 点击后由宿主渲染声明式表单，或在主窗口 Modal 中挂载隔离自定义 UI |
| `nodeTypes` | string[] | 是 | 工具适用的节点类型 |
| `inputFields` | string[] | 是 | 允许传给插件的节点数据顶层字段，数量为 1–64 个 |
| `output` | object | 是 | 工具的写入方式和允许输出的字段 |

Manifest 中的工具 ID 必须与 `main.js` 的 `tools` 键完全一致。

### placements 与交互方式

| 值 | 出现位置 | 点击行为 |
|---|---|---|
| `node-context-menu` | 节点右键菜单 | 声明 `dialog` 时打开同一个主窗口弹窗；未声明时立即执行，`input.parameters` 为空对象 |
| `node-toolbar` | 匹配节点的上方工具栏 | 打开 Manifest 声明的宿主弹窗，用户确认后执行 |

同一工具从工具栏或右键菜单触发时复用同一个弹窗。只要声明了 `dialog`，即使没有必填字段也会打开它；完全不需要 UI 的一键工具可以省略 `dialog`，插件需自行处理空的 `input.parameters`。

工具栏按钮会自动追加到现有节点工具栏，不进入用户的内置工具栏排序配置。按钮提示格式为“工具标题 · 插件名称”。目前实际提供上方工具栏的节点族包括文本、图片、视频、音频和全景；对应的源节点复用同一工具栏，但仍按 `nodeTypes` 精确匹配。

### icon 规则

工具栏入口必须提供 `icon`。它必须是 Iconify 的 `集合:图标名` 格式，只能使用小写字母、数字和短横线，例如：

```json
"icon": "lucide:wand-sparkles"
```

插件不能传入远程图标 URL、SVG 字符串、HTML 或本地文件路径。

### dialog 规则

`node-toolbar` 工具必须声明 `dialog`：

```json
"dialog": {
  "title": "整理文本",
  "description": "选择处理方式并填写附加说明。",
  "submitLabel": "开始处理",
  "fields": [
    {
      "id": "instruction",
      "label": "附加说明",
      "type": "textarea",
      "placeholder": "请输入要求",
      "required": true
    },
    {
      "id": "tone",
      "label": "语气",
      "type": "select",
      "defaultValue": "brief",
      "options": [
        { "label": "简洁", "value": "brief" },
        { "label": "详细", "value": "detailed" }
      ]
    }
  ]
}
```

`dialog` 支持以下字段：

| 字段 | 类型 | 必填 | 规则 |
|---|---|---:|---|
| `title` | string | 否 | 弹窗标题，缺省使用工具 `title` |
| `description` | string | 否 | 弹窗说明，缺省使用工具 `description` |
| `submitLabel` | string | 否 | 确认按钮文字，缺省为“执行” |
| `fields` | object[] | 是 | 0–16 个表单字段；空数组表示仅确认后执行 |

表单字段支持 `text`、`textarea`、`number`、`select` 和 `boolean`。每项可声明 `id`、`label`、`type`、`description`、`placeholder`、`required` 与 `defaultValue`；`select` 还必须声明 1–32 个 `{ "label", "value" }` 选项。字段 `id` 在当前弹窗中必须唯一，只能使用字母开头的字母、数字和下划线组合。

API v1 还支持 `model` 类型，用于让用户在弹窗里选择模型：

| 类型 | 说明 | 额外字段 |
|---|---|---|
| `model` | 渲染当前已配置且可调用的模型下拉。插件只拿到用户选择的模型 ID，拿不到 API Key、接口地址或任何厂商凭据 | 可选 `modelCategories`：`text`、`image`、`video`、`audio` 的数组，缺省表示不限分类 |

```json
{
  "id": "model",
  "label": "分析模型",
  "type": "model",
  "modelCategories": ["text"],
  "required": true
}
```

`model` 字段要求插件声明 `models.read`；`modelCategories` 只能用在 `model` 字段上。模型下拉只列出已配置凭据的模型，未配置的厂商不会出现。

### 支持的 nodeTypes

| 节点类型 | 用途 |
|---|---|
| `ai-text` | AI 文本节点 |
| `ai-image` | AI 图片节点 |
| `ai-video` | AI 视频节点 |
| `ai-audio` | AI 音频节点 |
| `ai-animation` | AI 动画节点 |
| `ai-panorama` | AI 全景节点 |
| `ai-markdown` | Markdown 节点 |
| `ai-storyboard` | 宫格分镜节点 |
| `ai-shotlist` | 分镜表节点 |
| `ai-director` | 导演台节点 |
| `source-image` | 图片源节点 |
| `source-video` | 视频源节点 |
| `source-audio` | 音频源节点 |
| `source-text` | 文本源节点 |
| `canvas-note` | 画布笔记 |
| `comment` | 评论节点 |

一个工具可以同时声明多个节点类型：

```json
"nodeTypes": ["ai-text", "source-text", "ai-markdown"]
```

## 6. 输入数据

工具函数接收一个 `input` 对象：

```typescript
interface PluginInput {
  projectId: string;
  iteration: number;
  parameters: Record<string, JsonValue>;
  node: {
    id: string;
    type: string;
    data: Record<string, JsonValue>;
  };
  models: PluginModelSummary[];
  effectResult?: PluginNodeHostEffectResult;
}
```

`input.parameters` 来自宿主弹窗。工具栏按钮总会先打开弹窗；右键菜单是直接执行入口，通常该值为 `{}`，但工具声明了必填字段时宿主会先打开弹窗（见第 5 节）。插件应为可选参数提供缺省处理：

```javascript
const prefix = String(input.parameters.prefix || "");
const confirmed = input.parameters.confirmed === true;
```

另外三个字段与宿主 effect 相关，详见「宿主 effect」：

| 字段 | 含义 |
|---|---|
| `iteration` | 当前是第几轮调用，首次为 `0`；每完成一次宿主 effect 加一 |
| `models` | 当前可调用模型目录，每项包含 `id`、`name`、`provider`、`category` 与 `inputModalities`，不含任何凭据；未声明 `models.read` 时为空数组 |
| `effectResult` | 上一轮宿主 effect 的结果，`{ type, ok, value?, error? }`；首次调用时不存在 |

```javascript
const models = input.models.filter((model) => model.category === "text");
if (input.effectResult && !input.effectResult.ok) {
  return { data: { output: `调用失败：${input.effectResult.error}` } };
}
```

其中 `input.node.data` 只包含当前工具在 `inputFields` 中声明、并且可以安全转换为 JSON 的字段。例如：

```json
"inputFields": ["label", "prompt", "output"]
```

对应的插件代码：

```javascript
const label = input.node.data.label;
const prompt = input.node.data.prompt;
const output = input.node.data.output;
```

常用节点字段包括：

| 字段 | 常见类型 | 含义 |
|---|---|---|
| `label` | string | 节点名称 |
| `prompt` | string | 提示词 |
| `output` | string | 文本结果或媒体 URL |
| `status` | string | `idle`、`loading`、`success` 或 `error` |
| `model` | string | 当前模型 ID |
| `provider` | string | 当前供应商 ID |
| `workflowId` | string | 当前工作流 ID |
| `workflowInputs` | object | 工作流输入映射 |
| `imageUrl` | string | 图片展示 URL |
| `videoUrl` | string | 视频展示 URL |
| `audioUrl` | string | 音频展示 URL |
| `thumbnailUrl` | string | 缩略图 URL |
| `style` | string | 画风 ID |
| `aspectRatio` | string | 宽高比 |
| `imageWidth` / `imageHeight` | number | 图片尺寸 |
| `videoWidth` / `videoHeight` | number | 视频尺寸 |
| `note` | object | 画布笔记数据 |

不同节点不一定拥有所有字段。插件必须处理字段不存在或值为空的情况。

以下本地敏感字段禁止出现在 `inputFields` 中：

- `filePath`
- `relativePath`
- `directorCaptureFilePaths`
- `__proto__`
- `constructor`
- `prototype`

## 7. main.js 注册规则

入口文件必须且只能调用一次全局函数 `definePlugin`：

```javascript
definePlugin({
  tools: {
    "tool-id": (input) => {
      return {
        data: {
          output: "插件处理结果"
        },
        message: "可选的完成提示"
      };
    }
  }
});
```

规则如下：

- `tools` 的键是 Manifest 中声明的工具 ID；
- 每个工具值必须是同步函数；
- 工具必须返回可 JSON 序列化的普通对象；
- 返回对象必须包含非空的 `data` 对象，或包含一个 `effect` 请求宿主代执行模型/资源能力；
- `message` 可选，用于执行完成后的短提示，最长保留 240 字符；
- 不要修改 `input`，应根据输入创建并返回新数据；
- 不要返回函数、Symbol、循环引用、`undefined`、Promise 或其他不可 JSON 序列化的值。

返回 `effect` 的多阶段写法见第 9 节「宿主 effect」；节点工具与自定义节点都可以使用，两者只是取模型 ID 的位置不同。

Plugin API 的 JSON 值范围为：

```typescript
type JsonValue =
  | null
  | boolean
  | number
  | string
  | JsonValue[]
  | { [key: string]: JsonValue };
```

### 7.1 main.py 注册规则

可信 Python 插件同样使用 API v1，并显式声明运行时：

```json
{
  "apiVersion": 1,
  "runtime": "python",
  "entry": "main.py"
}
```

`main.py` 必须调用一次 `define_plugin`，工具函数接收与 JavaScript 相同的 JSON 输入并返回可 JSON 序列化的字典：

```python
def uppercase(input_value):
    output = str(input_value["node"]["data"].get("output", ""))
    return {
        "data": {"output": output.upper()},
        "message": "已转换输出",
    }

define_plugin({"tools": {"uppercase-output": uppercase}})
```

宿主按顺序探测 macOS/Linux 的 `python3`、`python`，以及 Windows 的 `python`、`py -3`、`python3`。解释器必须是 Python 3。插件直接使用该环境的标准库和 site-packages；AI Canvas 不下载 Python、不创建虚拟环境，也不读取或自动执行 `requirements.txt`。

Python 工具同样必须同步返回 JSON 数据；不接受 coroutine。每次调用使用一个独立子进程，默认最长运行 30 秒。源码通过标准输入传递，不拼接到 Shell 命令中。

> **安全警告：** Python 插件不是沙箱。它以当前用户身份运行，可以绕过 Manifest 权限自行访问本机文件、网络和环境变量，也可以启动其他程序。Manifest 权限只约束 AI Canvas 代办的模型、资源和画布能力。只安装并启用你信任且已审查源码的 Python 插件。

## 8. 输出规则

### 更新当前节点

使用 `update-current` 将结果合并到当前节点：

```json
"output": {
  "mode": "update-current",
  "fields": ["label", "output"]
}
```

```javascript
definePlugin({
  tools: {
    "format-output": (input) => ({
      data: {
        label: `${input.node.data.label}（已处理）`,
        output: String(input.node.data.output || "").trim()
      }
    })
  }
});
```

### 创建派生节点

使用 `create-node` 在源节点右侧创建新节点：

```json
"output": {
  "mode": "create-node",
  "nodeType": "source-text",
  "fields": ["label", "output"]
}
```

```javascript
definePlugin({
  tools: {
    "create-summary": (input) => ({
      data: {
        label: "内容摘要",
        output: String(input.node.data.output || "").slice(0, 120)
      },
      message: "已创建摘要节点"
    })
  }
});
```

`nodeType` 仅对 `create-node` 有效；省略时沿用源节点类型。未返回 `label` 时，宿主会根据源节点和工具名称生成新节点名称。

插件只能返回 `output.fields` 中预先声明的字段。如果返回未声明字段，整次执行会失败，不会进行部分写入。

JavaScript 节点工具返回 `imageUrl`、`thumbnailUrl`、`videoUrl`、`audioUrl`、`sourceUrl` 或其他宿主媒体载体时，远程地址必须与本次输入中的真实媒体引用完全一致。插件不能拼接、改写查询参数或从普通文本、JSON、文件正文、弹窗参数中构造新的 `http/https` 媒体地址。插件同样不能猜测或自行返回 `asset:`、`file:`、`blob:` 等本地引用；只有宿主在本轮模型结果中发出的精确本地引用可以原样回传。普通文本节点的 `output` 仍可包含网页链接；只有会被宿主作为媒体加载的字段受此限制。

`ai-markdown` 的 `output` 需要额外遵守同一规则：普通 Markdown 链接可以正常输出，但 `![说明](URL)` 图片会被宿主加载，因此其中的远程 URL 必须来自该 Markdown 节点原有的图片引用或其他受信媒体来源。

以下字段属于宿主身份、本地资产或内部关联信息，禁止写入：

- `type`
- `displayId`
- `filePath`
- `relativePath`
- `assetId`
- `artifactId`
- `role`
- `dramaAssetId`
- `dramaAssetKind`
- `characterLibraryLinks`
- `hiddenByCharacterLibrary`
- `directorInstanceId`
- `directorCaptureFilePaths`
- `__proto__`
- `constructor`
- `prototype`

## 9. 自定义节点与资源端口

自定义节点由宿主统一渲染。Manifest 决定节点字段和端口，`main.js` / `main.py` 中与节点 `id` 同名的 `tools` 函数负责编排数据及宿主能力。

```json
{
  "apiVersion": 1,
  "permissions": [
    "node.read",
    "node.write",
    "models.read",
    "models.invoke",
    "files.connected.read",
    "files.output.create",
    "plugin.resources.read"
  ],
  "resources": [{
    "id": "system-prompt",
    "path": "resources/system-prompt.txt",
    "integrity": "sha256-<64位十六进制摘要>",
    "mediaType": "text/plain",
    "bytes": 128
  }],
  "contributes": {
    "nodeTools": [],
    "nodes": [{
      "id": "writer",
      "title": "写作节点",
      "description": "读取直接连入的资料并调用文本模型",
      "icon": "lucide:sparkles",
      "inputs": [{
        "id": "source",
        "label": "资料",
        "type": "resource",
        "multiple": true,
        "accept": ["text/*", "application/json"],
        "maxBytes": 1048576
      }],
      "outputs": [{ "id": "result", "label": "结果", "type": "text" }],
      "fields": [
        { "id": "prompt", "label": "提示词", "type": "textarea", "required": true },
        { "id": "model", "label": "模型", "type": "model", "modelCategories": ["text"] }
      ],
      "resourceAccess": { "self": true, "incoming": true, "portIds": ["source"] }
    }]
  }
}
```

### 节点字段

`fields` 最多 16 项，支持 `text`、`textarea`、`number`、`select`、`boolean` 和 `model`。`modelCategories` 可包含 `text`、`image`、`video`、`audio`；模型下拉只显示当前已配置且可调用的模型。文件不再作为表单字段保存，统一通过 `resourceAccess` 和 `input.resources` 获得短期句柄。

### 输入输出端口

`inputs`、`outputs` 各最多 16 项，端口类型支持 `text`、`image`、`video`、`audio`、`json` 和 `resource`。输入端口可声明 `required` 和 `multiple`；媒体与 `resource` 端口还可声明 MIME `accept` 与单文件 `maxBytes`。插件最终只能返回 Manifest 已声明的字段和输出端口。

插件节点之间的连线按来源 `plugin-out-<outputId>` 和目标 `plugin-in-<inputId>` 精确路由。目标 Handle 缺失或未知时不会回退到第一个输入端口。显式插件端口要求来源插件、节点和端口仍属于当前活动 revision，且来源与目标端口类型完全一致；例如 `image` 不能直接连接到 `text`。来源插件被卸载、节点被移除、端口被改名或连线被替换时会立即失效，不会回退到其它输出端口。

### 文件资源授权

`resourceAccess` 默认不授予任何文件：

- `self: true`：当前目标节点自身引用的项目文件；
- `incoming: true`：当前节点的一跳直接输入连线所引用的项目文件；
- `portIds`：仅自定义节点可用，把入边授权进一步限制到指定输入端口，且必须与 `incoming: true` 同时声明；
- `resources[]`：插件包内不可变资源，按 ID、相对路径、字节数和 SHA-256 随完整 revision 登记。

项目文件要求位于当前项目目录中，路径及父目录均不得是符号链接。宿主只把以下结构放进 `input.resources`，不提供绝对路径或项目相对路径：

```json
{
  "self": [],
  "incoming": [{
    "resourceId": "plugin-resource-<opaque>",
    "origin": "connection",
    "displayName": "frame.png",
    "mediaType": "image/png",
    "size": 123456,
    "access": "read",
    "source": { "nodeId": "source-node", "edgeId": "edge-1", "portId": "source" }
  }],
  "inputs": { "source": [{
    "resourceId": "plugin-resource-<opaque>",
    "origin": "connection",
    "displayName": "frame.png",
    "mediaType": "image/png",
    "size": 123456,
    "access": "read",
    "source": { "nodeId": "source-node", "edgeId": "edge-1", "portId": "source" }
  }] },
  "package": []
}
```

`resourceId` 只在本次调用或 UI 会话内有效，并绑定插件 ID、入口源码摘要、完整 revision 摘要、项目、节点、画布 revision、连线和端口。读取前宿主会重新检查这些条件以及文件大小、修改时间和普通文件身份；任一变化都会撤销授权。

当前单个 `image`、`video` 或 `audio` 输出端口应返回一个媒体 URL 字符串。JavaScript 插件可以原样返回真实远程媒体输入、本轮宿主发出的模型结果，或受支持的安全内联媒体；自行构造的 `asset:`、`file:`、`blob:` 和不安全 `data:` 引用会被拒绝。需要把本地图片交给模型时，应使用 `model.generate.resourceIds`，由宿主解析句柄；插件不会看到本地 URL。

### 宿主 effect

插件 JavaScript 仍是同步函数。需要异步模型或资源能力时返回一个 `effect`；宿主完成后**再次调用同一个函数**，并在 `input.effectResult` 中给出结果。单次节点、工具或自定义 UI 会话最多执行 4 个 effect。

自定义节点与**节点工具**都可以使用 effect。区别只在于模型 ID 从哪里来：自定义节点读 `input.node.values`，节点工具读弹窗传来的 `input.parameters`。

```js
definePlugin({
  tools: {
    "analyze-frames": (input) => {
      // 第一轮：请求宿主调用模型
      if (!input.effectResult) {
        return {
          effect: {
            type: "model.generate",
            modelId: input.parameters.model,
            prompt: "请逐帧分析这些画面的景别、运镜与光线。",
            resourceIds: input.resources.incoming
              .filter((resource) => resource.mediaType.startsWith("image/"))
              .map((resource) => resource.resourceId)
          }
        };
      }
      // 第二轮：effectResult 已就绪
      if (!input.effectResult.ok) {
        return { data: { output: `模型调用失败：${input.effectResult.error}` } };
      }
      return {
        data: { output: input.effectResult.value.text },
        message: "分析完成"
      };
    }
  }
});
```

`input.iteration` 表示当前是第几轮（首次为 `0`），可用于区分更多阶段。不需要多阶段的工具直接返回 `data` 即可，宿主不会再发起第二次调用。

支持的 effect：

| `type` | 权限 | 输入 | 返回值 |
|---|---|---|---|
| `model.generate` | `models.invoke` | `modelId`、`prompt`、可选受信远程 `imageUrls`、本次会话的 `resourceIds` 与 `parameters` | 文本为 `{text}`；媒体为 `{url}` |
| `resource.readText` | `files.connected.read` 或 `plugin.resources.read` | 本次授权的 `resourceId`、可选 `maxBytes` | `{resource, content}`，最多读取 256 KiB UTF-8 文本 |
| `resource.readRange` | `files.connected.read` 或 `plugin.resources.read` | `resourceId`、`offset`、`length` | `{resource, offset, bytes, base64}`，单次最多 256 KiB |
| `resource.createText` | `files.output.create` | `content`、可选 `suggestedName` | 在当前项目目录创建新文本，返回 `{fileName, bytes}`；不显示路径且不覆盖上游文件 |

宿主操作失败时不会中断整个工具，而是以 `{ ok: false, error }` 的形式回到 `effectResult`，由插件决定降级还是报错；权限不足、模型不在目录、模型请求异常都走这条路径。

模型目录通过 `input.models` 提供，只包含 ID、名称、分类、用途和输入模态，不包含 API Key、接口地址或厂商凭据；未声明 `models.read` 时该数组为空。模型实际请求始终由宿主现有生成服务执行。

**随模型一起提交的参考图**：远程参考仍可从真实媒体输入原样传递；本地节点或直接连线文件使用本次 `input.resources` 中的 `resourceId`，放进 `model.generate.resourceIds`。宿主会确认资源属于当前调用且 MIME 为图片，再在插件不可见的边界内解析为模型输入。

`imageUrls` 的来源规则：

| 运行时 | 规则 |
|---|---|
| JavaScript | 每一项必须已经存在于本次 `inputFields` 声明的媒体引用中，或是本轮宿主模型产生的结果。自行拼接的远程地址会被拒绝，整次运行失败 |
| Python | 不做来源限制——可信 Python 本身已具备当前用户的联网能力，该校验没有沙箱意义 |

宿主只把成功的图片、视频或音频模型返回 URL 加入本次运行的受信媒体来源集合；文本模型结果和资源正文不会获得该资格。来源集合与资源句柄都不会跨节点、跨 invocation 或跨 UI 会话持久化。

### 主窗口自定义弹窗

节点工具可以用 `dialog.ui` 引用 `manifest.ui.exports` 的逻辑键，用插件自定义视图替换声明式表单。宿主仍使用自己的 `ModalOverlay`、标题栏、关闭行为和主题容器；插件 bundle 只运行在 Modal 内部的 `<iframe sandbox="allow-scripts">`，不会打开额外系统窗口，也拿不到主窗口 DOM、Store、Tauri IPC 或网络能力。

Plugin API v1 只允许节点工具使用自定义 UI。`contributes.nodes` 的节点主体始终由宿主根据 `fields`、`inputs` 与 `outputs` 渲染，不接受 `nodes[].ui`；这样可以保持画布拖拽、缩放、主题、焦点和错误边界一致。

```json
{
  "permissions": ["node.read", "node.write", "ui.custom"],
  "ui": {
    "entry": "ui.js",
    "integrity": "sha256-<ui.js 的 64 位十六进制摘要>",
    "exports": { "toolDialog": "ToolDialog" }
  },
  "contributes": {
    "nodeTools": [{
      "id": "compose",
      "title": "组合处理",
      "placements": ["node-toolbar", "node-context-menu"],
      "icon": "lucide:panels-top-left",
      "dialog": { "fields": [], "ui": "toolDialog" },
      "nodeTypes": ["ai-image"],
      "inputFields": ["output"],
      "output": { "mode": "update-current", "fields": ["output"] }
    }]
  }
}
```

`ui.js` 必须是自包含的 IIFE/UMD bundle。插件可以使用原生 DOM，也可以把 React、Vue 等框架打进自己的 bundle；宿主不会把主窗口的 React 实例交给插件。bundle 需要把挂载函数写入 `window.__AI_CANVAS_PLUGIN_HOST__.exports.ToolDialog`，签名固定为 `(root, props) => cleanup?`：

```js
(function () {
  window.__AI_CANVAS_PLUGIN_HOST__.exports.ToolDialog = function mount(root, props) {
    const button = document.createElement('button');
    button.textContent = '执行';
    button.onclick = () => void props.submit({ confirmed: true });
    root.appendChild(button);
    return () => button.remove();
  };
})();
```

挂载函数只能操作 iframe 内传入的 `root`。它收到的 `props` 只有：

- `surface`（v1 固定为 `tool-dialog`）、`theme`、裁剪后的 `node`、安全模型目录和 `parameters`；
- 本会话的不透明 `resources`；
- `runEffect()`、`setParameters()`、`submit()`、`close()`、`toast()` 与 `busy`。

iframe 与宿主只通过 `window.postMessage` 交换带随机 `sessionId` 的有界 JSON。宿主同时绑定消息的 `event.source`、插件双摘要、项目、节点和画布 revision；伪造来源、更新插件、切换项目、修改画布或断开连线都会使会话失败关闭。UI 点击提交时沿用同一 invocation 的资源句柄和受信媒体集合，不会在提交瞬间换发一组不兼容的 ID。主窗口深浅主题会实时同步到 `theme` getter 与 iframe 的 `data-theme`，同时派发 `ai-canvas-theme-change` 事件；插件负责为两种主题提供可读配色。iframe 内按 `Esc` 也会请求宿主关闭当前 Modal。

宿主启动自定义 UI 前还会确认该 iframe 没有获得 `window.__TAURI__`、`window.__TAURI_INTERNALS__` 或其它 Tauri 初始化标记；检测到即停止加载插件 bundle。这个 iframe 是能力隔离边界，不承诺独立进程或 CPU/内存隔离：死循环或过重渲染仍可能影响主窗口响应，因此常规设置优先使用宿主声明式 `dialog.fields`，自定义 UI 应限制依赖、动画和大对象处理。

## 10. 权限声明

支持以下权限：

| 权限 | 含义 |
|---|---|
| `node.read` | 读取 `inputFields` 声明的节点字段 |
| `node.write` | 更新当前节点或创建派生节点 |
| `models.read` | 读取不含凭据的可调用模型目录 |
| `models.invoke` | 请求宿主调用目录中的模型 |
| `files.connected.read` | 读取 `resourceAccess` 明确允许的当前节点或直接入边项目文件 |
| `files.output.create` | 通过宿主在项目目录创建派生输出，当前开放文本输出 |
| `plugin.resources.read` | 读取 `manifest.resources` 随当前 revision 登记的包资源 |
| `ui.custom` | 在主窗口隔离 Modal 中加载经摘要校验的自定义 UI bundle；代码可能影响主窗口响应 |

节点工具必须声明 `node.write`。只要工具声明了输入字段，也必须声明 `node.read`。模型、资源和 UI 权限不会隐式授予。节点工具的常规配置如下：

```json
"permissions": ["node.read", "node.write"]
```

需要模型能力的节点工具再加上模型权限：

```json
"permissions": ["node.read", "node.write", "models.read", "models.invoke"]
```

| 权限 | 对节点工具的作用 |
|---|---|
| `models.read` | 填充 `input.models`，并允许弹窗使用 `model` 字段 |
| `models.invoke` | 允许发出 `model.generate` |

只声明 `models.read` 而没有 `models.invoke` 时，`model.generate` 会被拒绝，并以 `{ ok: false, error }` 回到 `effectResult`，不会中断工具。读取节点/连线文件、包资源和创建输出分别需要对应权限；拥有权限但未声明精确 `resourceAccess` 或资源清单时仍得不到句柄。

声明权限不代表插件能绕过字段白名单；运行时仍会分别校验输入和输出字段。

## 11. 安全与资源限制

JavaScript 插件每次调用都会创建独立 QuickJS Runtime。宿主只传入裁剪后的 JSON 快照和不透明资源句柄，不向 JavaScript 暴露 DOM、网络、文件系统或 Tauri 宿主函数。自定义 UI 运行在主窗口 sandboxed iframe 中，CSP 禁止网络连接且没有 Tauri capability。Python 插件每次调用创建独立本机子进程，但它是可信代码，不受 QuickJS 或 iframe 沙箱保护。

QuickJS 运行时还会在写回画布前检查媒体引用来源。检查覆盖直接媒体 URL、媒体节点的 `output` 回退、Markdown 图片、分镜/导演台/视频参考等嵌套媒体数据。`http/https` 地址（包括本机和局域网地址）不会因目标位置而豁免。画布笔记的 `strokeColor` 和 `backgroundColor` 只接受宿主当前色板值或 `#RGB`、`#RGBA`、`#RRGGBB`、`#RRGGBBAA`，不接受任意 CSS 函数或转义。此规则用于维持“JavaScript 无任意网络能力”的边界；可信 Python 插件本身已经能以当前用户权限联网，因此不受该来源集合约束。

同一套来源集合也用于校验 `model.generate` 的 `imageUrls`：JavaScript 插件只能把本次输入已有的媒体引用交给模型，Python 不受限制。模型请求由宿主发起，因此这条能力不会给 JavaScript 沙箱带来新的网络出口。

节点工具使用 effect 时，宿主会在每一轮结束后重新核对插件版本与画布状态；期间发生项目切换、节点变化、插件更新、停用或卸载，过期结果都不会继续请求宿主操作，也不会写入画布。

### 原生信任注册与代码摘要

安装或更新时，应用会计算入口源码 `sourceDigest`，Rust 还会把规范化 Manifest、入口源码、UI bundle 和按 ID 排序的包资源字节共同计算为 `revisionDigest`。可信 Python 或自定义 UI 的确认会显示来源、完整摘要、宿主权限及对应风险；Renderer 传入的布尔值不能替代 Rust 原生授权。声明的字节数、资源/UI 摘要或两端身份不一致时拒绝安装。

入口源码、UI 和包资源随后以不可变快照登记到应用私有的 `plugin-private` 目录。运行命令只提交插件 ID、`sourceDigest`、`revisionDigest`、工具 ID、调用 ID 和结构化输入，不再把 `main.js` / `main.py` 或 runtime 交给执行命令。Rust 会确认插件已启用、双摘要属于活动 revision、工具由该 revision 声明，并在每次执行和资源读取前重新核对私有快照。

`plugin-private` 不能通过普通文件 API、asset URL 或通用路径命令读取。不要手动编辑其中的 `registry.json` 或源码快照；注册缺失、摘要不一致或快照损坏会让插件失败关闭，而不会退回到直接执行 IndexedDB 源码。

`sourceDigest` 只绑定 `main.js` / `main.py` 的精确字节；`revisionDigest` 绑定本次实际启用的 Manifest、入口、UI 和包资源。两者都不是作者签名或仓库签名，不能证明来源可信；作者和用户仍须核对来源并审查可信 Python 代码与 UI bundle。

| 项目 | 限制 |
|---|---:|
| `manifest.json` | 最大 64 KiB |
| `main.js` / `main.py` | 最大 512 KiB |
| `ui.js` | 最大 2 MiB |
| 单个包资源 | 最大 16 MiB；单插件最多 64 项、合计 64 MiB |
| 单次资源分段读取 | 最大 256 KiB |
| 单次输入 JSON | 最大 1 MiB |
| 单次输出 JSON | 最大 1 MiB |
| 沙箱内存 | 最大 64 MiB |
| JavaScript 栈 | 最大 512 KiB |
| JavaScript 单次执行时间 | 最长 2 秒 |
| Python 单次执行时间 | 解释器探测与正文执行合计最长 30 秒；Windows 使用 Job Object，macOS/Linux 使用独立进程组；管道回收另有 2 秒关闭上限 |
| 单插件节点工具 | 最多 64 个 |
| 单插件自定义节点 | 最多 32 个 |
| 单节点输入/输出端口 | 各最多 16 个 |
| 单节点/单工具宿主 effect | 最多 4 次 |
| 单工具输入字段 | 最多 64 个 |
| 单工具输出字段 | 最多 64 个 |

传入和返回的数据还会进行边界化处理：

- 字符串最长保留 256,000 个字符；
- 数组最多保留 256 项；
- 单个对象最多保留 128 个键；
- JSON 嵌套深度最多 8 层；
- 非有限数字、函数、Symbol 和危险对象键会被拒绝或移除。

画布在插件执行期间发生项目切换、节点变化、插件 revision 更新、插件停用或卸载时，过期结果不会继续请求宿主 effect，也不会写入画布。更新、停用和卸载会在原生 mutation 前先撤销前端版本租约和资源句柄；旧 revision 的资源不会自动交给新代码。

## 12. 安装、更新、启停与卸载

### 安装

1. 打开“设置”；
2. 选择“插件”；
3. 将插件文件夹拖到上传区，或点击上传区打开目录选择器；
4. 选择包含同级 `manifest.json` 与 `main.js` 或 `main.py` 的插件目录；
5. 可信 Python 或自定义 UI 插件会先显示来源、入口源码摘要、完整 revision 摘要、宿主权限和对应风险；
6. 随后的 Rust 原生 Warning 会再次绑定插件 ID、版本与当前 revision。只有原生确认通过后才会暂存代码、UI 和声明资源；
7. 安装成功后，在匹配类型的节点上打开右键菜单，或选择节点查看上方工具栏按钮。

也可以在“插件市场”中点击安装，或粘贴 GitHub 仓库地址。GitHub 安装仍会经过与本地导入完全相同的 Manifest、权限、源码大小和沙箱校验。

Python 或自定义 UI 插件在安装、更新和从停用状态重新启用时，都会先经过前端来源、摘要、宿主权限和风险复核，再经过 Rust 原生 Warning。确认表示用户信任该 revision，并不表示 AI Canvas 已对其完成安全审计。

原生注册表会保留上一批准 revision，供更新失败补偿或内部回滚使用；它不是插件页中的手动降级功能。任何真实切换到上一 Python revision 的原生流程都必须重新显示高风险授权，不能沿用当前版本的批准状态。

### GitHub 发布规范

需要被插件市场追踪的仓库必须满足：

1. 公开 GitHub 仓库根目录包含 `manifest.json` 和 Manifest 声明的 `main.js` 或 `main.py`；
2. Manifest 填写规范化的 `repository`，且必须与当前仓库一致；
3. `version` 使用稳定三段版本号，如 `1.2.0`；
4. 创建正式 GitHub Release，标签使用 `vX.Y.Z`，如 `v1.2.0`；
5. Release 标签中的版本必须与 Manifest `version` 完全一致；
6. 不使用 Draft 或 Pre-release 作为市场稳定版。

示例发布字段：

```json
{
  "version": "1.2.0",
  "repository": "https://github.com/example/my-ai-canvas-plugin",
  "homepage": "https://example.com/my-ai-canvas-plugin",
  "license": "MIT"
}
```

应用读取 GitHub 的最新正式 Release，再从该 Release 标签对应的仓库快照读取根目录文件。仓库地址、Release 标签和 Manifest 版本任一不匹配时都会拒绝安装。

### 提交到插件市场

插件市场索引位于项目的 `public/plugin-marketplace.json`。作者通过 Pull Request 添加仓库地址：

```json
{
  "schemaVersion": 1,
  "plugins": [
    {
      "repository": "https://github.com/example/my-ai-canvas-plugin",
      "featured": false
    }
  ]
}
```

市场收录只登记仓库，不复制插件源码。收录后，作者发布新的稳定版 Release，应用会在刷新插件页时自动识别新版本。未收录的公开仓库仍可通过仓库地址直接安装；直接安装后也会继续检查更新。

### 更新

修改 Manifest、入口、UI 或包资源后重新导入相同 `id` 的插件，会先暂存新的不可执行快照。安装记录保存成功后，宿主先撤销旧版本租约和资源句柄，再原子激活新 `revisionDigest`，并保留原来的启用或停用状态；原生层同时保留上一批准 revision 供本次失败补偿，不代表用户可以手动降级。摘要比较、数据库保存或激活任一步失败，都会回切旧 active 或移除首次注册，并丢弃未提交的 staged 快照。

完整 revision 身份包含 Manifest、入口源码、UI 和包资源；只修改其中任一部分都会形成新的 `revisionDigest`，不需要为了改变 Manifest 而人为改动入口源码。

GitHub 插件有新稳定版时会显示“可更新”。更新必须由用户点击确认，不会静默替换本地插件。检查结果会短期缓存，以避免频繁消耗 GitHub API 限额。

### 启用、停用与卸载

- 从停用状态重新启用时，宿主重新激活已登记的 active 摘要；可信 Python 必须重新通过前端复核和 Rust 原生 Warning，JavaScript 不获得 Python 授权语义；
- 停用后，插件工具不会显示在节点右键菜单或工具栏中；
- 停用、卸载或切换 revision 时，前端会先撤销版本租约并清除资源句柄，原生层随后阻止新调用并取消活动 Python 调用；
- 卸载成功后会移除应用内的原生注册、IndexedDB 安装记录和私有源码快照，但不会删除用户最初选择的插件开发目录，也不会修改 GitHub 仓库；
- 已经写入节点的数据不会随插件卸载而自动撤销，可通过画布历史记录撤销最近操作。

## 13. 常见错误

### 插件工具没有出现在右键菜单或工具栏

检查：

- 插件是否处于“已启用”状态；
- 当前节点类型是否包含在 `nodeTypes` 中；
- `placements` 是否包含目标入口：`node-context-menu` 或 `node-toolbar`；
- 工具栏入口是否配置了合法的 `icon` 和 `dialog`；
- Manifest 工具 ID 是否与 `main.js` 中的 `tools` 键一致。

### 安装时报“请求了不允许暴露给插件的本地字段”

`inputFields` 中包含了本地路径或受保护字段。请改为读取安全的展示字段，例如 `output`、`imageUrl` 或 `fileName`。

### 执行时报“返回了未声明字段”

插件返回的 `data` 包含了 `output.fields` 未声明的字段。将需要写入的安全字段加入 Manifest，或者从返回值中删除该字段。

### 执行时报“未经宿主授权的远程媒体引用”或“未经宿主授权的本地媒体引用”

JavaScript 插件返回了一个并非来自真实媒体输入或本轮宿主媒体模型结果的媒体 URL。请改为原样透传输入，或通过 `model.generate` 让宿主创建媒体；不要自行拼接 CDN、跟踪像素、查询参数、局域网地址，也不要猜测 `asset:`、`file:` 或 `blob:` 本地引用。

### 执行时报“端口类型不兼容”

插件输出端口与目标输入端口的声明类型不同。请连接相同的 `text`、`image`、`video`、`audio` 或 `json` 类型；需要格式转换时，应使用一个显式转换节点。

### 模型调用后 `input.models` 是空数组，或模型下拉为空

插件没有声明 `models.read`，或当前没有已配置凭据的模型。下拉只列出已配置且可调用的模型，未配置的厂商不会出现；声明 `models.read` 后仍为空时，请检查设置中的厂商连接。

### 宿主操作返回 `ok: false`，提示未声明 models.invoke

工具发出了 `model.generate`，但 Manifest 只声明了 `models.read`。宿主不会抛出错误，而是把 `{ ok: false, error: "插件未声明 models.invoke 权限" }` 放进 `effectResult` 交回插件。在 `permissions` 中加入 `models.invoke`，或在插件里对该结果做降级处理。

### 执行时报“模型调用的 imageUrls 必须是字符串数组”或“未经宿主授权的远程媒体引用”

`imageUrls` 必须是字符串数组，且 JavaScript 插件只能提交本次 `inputFields` 中已有的媒体引用或本轮宿主模型结果。不要从文本、JSON、文件正文或弹窗参数里拼接新的 `http/https` 地址；确实需要新图时改用 Python 运行时，或让宿主先生成媒体再引用。

### 执行时报“来源插件未安装或已卸载”

当前连线指向一个无法从安装记录解析的显式插件输出端口。请重新安装提供该节点的兼容插件，或删除这条失效连线后重新连接；宿主不会把遗留的通用输出静默代替目标端口。

### 执行时报“不允许的画布笔记颜色”

JavaScript 插件为画布笔记返回了任意 CSS 表达式。请使用宿主色板中的现有值，或使用 3、4、6、8 位十六进制颜色；不要使用 `url()`、转义函数或其他 CSS 代码。

### 执行时报“源码摘要”或“插件未注册”

安装记录与原生私有注册表不一致，或者源码快照已损坏。请停用插件并从原始本地目录或可信仓库重新安装。应用不会为了兼容而直接执行 IndexedDB 中的源码。

### 执行时报“首版插件工具不支持异步返回值”

工具返回了 Promise，或使用了 `async`。v1 工具必须同步完成并直接返回普通对象。

### 执行超过 2 秒

减少输入规模和循环次数，避免无限循环。超过时间限制的执行会被沙箱中断，结果不会写入画布。

### 未找到可用的 Python 3

在插件设置页点击“重新检测”。确认终端中能直接运行 `python3`、`python`，或 Windows 的 `py -3`。AI Canvas 不会自动下载解释器或安装依赖。

### Python 插件输出不是有效 JSON

工具必须返回可由 `json.dumps` 序列化的字典。不要向原始 stdout 写入额外协议内容；普通 `print` 会被 runner 捕获，但直接写文件描述符或子进程继承 stdout 仍可能破坏 JSON 输出。

## 14. 发布前检查清单

- [ ] 文件夹根目录包含 `manifest.json` 和对应的 `main.js` 或 `main.py`；
- [ ] `apiVersion` 固定为 `1`；JavaScript 使用 `main.js`，Python 使用 `runtime: python` 与 `main.py`；
- [ ] 插件 ID 稳定且不会随版本变化；
- [ ] GitHub 发布填写了正确的 `repository`、`license` 和三段式 `version`；
- [ ] GitHub Release 标签为与 Manifest 版本一致的 `vX.Y.Z`；
- [ ] 每个 Manifest 工具 ID 都在 `definePlugin().tools` 或 `define_plugin()["tools"]` 中注册；
- [ ] 工具栏工具配置了合法的 Iconify `icon` 和声明式 `dialog`；
- [ ] `nodeTypes` 只包含实际支持的节点类型；
- [ ] `inputFields` 只申请工具确实需要的数据；
- [ ] `output.fields` 与工具实际返回的 `data` 字段完全一致；
- [ ] 对缺失、空字符串、空数组等输入进行了处理；
- [ ] 工具同步执行；JavaScript 正常数据规模下远低于 2 秒，Python 远低于 30 秒；
- [ ] JavaScript 未使用任意网络、任意路径、DOM、Tauri、npm 包或异步 API；模型和资源操作只返回受支持 effect；
- [ ] JavaScript 的远程媒体输出只原样透传真实媒体输入或本轮宿主媒体模型结果，没有自行拼接 URL；
- [ ] Markdown 图片和画布笔记颜色没有形成新的远程资源加载入口；
- [ ] 自定义节点的来源/目标端口类型一致，并已验证多个输出端口分别连线时的结果；
- [ ] Python 插件的本机访问、依赖和供应链风险已经由作者与用户审查；
- [ ] 已测试“更新当前节点”和“创建派生节点”是否符合预期；
- [ ] `name`、`description` 和工具标题能让用户理解插件用途与出现位置；
- [ ] 使用模型能力时声明了 `models.read`（目录与模型下拉）与 `models.invoke`（`model.generate`）；
- [ ] `resourceAccess` 只包含确实需要的 `self`、直接 `incoming` 和端口；没有依赖真实路径；
- [ ] `resources[]` 的路径、字节数、MIME 与 SHA-256 和发布包实际文件一致；
- [ ] 自定义 UI 在主窗口 Modal 的深浅主题下均可读，且只通过 props / `runEffect` 使用宿主能力；
- [ ] 弹窗 `model` 字段的 `modelCategories` 与实际调用的模型分类一致；
- [ ] 用 `input.effectResult` 或 `input.iteration` 区分了 effect 前后两种阶段，并处理了 `ok: false`；
- [ ] JavaScript 插件提交的 `imageUrls` 都来自本次输入已有的媒体引用或本轮宿主模型结果。

## 15. 版本约定

- 当前只接受 `apiVersion: 1`，它直接包含本文档列出的节点工具、自定义节点、资源、effect、可信 Python 与主窗口隔离 UI；
- 不存在更早插件格式的加载、迁移或运行兜底；缺少有效 `sourceDigest` / `revisionDigest` 或原生私有快照的记录会失败关闭，必须重新安装；
- 插件自身的 `version` 用于展示、更新和发布管理，不决定 API 兼容性；同一插件升级时保持 `id` 不变；
- 已发布工具和节点应尽量保持各自 `id` 稳定；改变端口 ID 会让现有连线按安全规则失效；
- 插件不得依赖未在本文档中声明的宿主内部对象。后续能力优先通过 v1 的可选声明扩展；只有出现无法安全表达的破坏性变化时才重新评估 API 版本。
